# Shop site (Pages CMS + Cloudflare Pages)

A fictional sample of a shop site. The customer edits `content/` and `media/` in Pages CMS, and every commit builds the
page into `dist/`. This repository was generated by Second Root (`experiments/pages-cms/export-delivery.ts`). It does
not depend on Second Root, holds no secrets and uses no model.

| Path | What it is | Who changes it |
|---|---|---|
| `content/`, `media/` | the shop's content and photos | the customer, in Pages CMS |
| `.pages.yml` | the Pages CMS configuration (customer-editable fields only) | nobody: generated; the build refuses a changed one |
| `site/` | the page code and the content checks (a copy of Second Root's) | nobody: generated |
| `build.mjs`, `photo-prep.mjs` | the build | nobody |
| `migrate-ids.mjs` | one-off: gives entries delivered with a readable id (`job-1`) a UUID id, so Pages CMS can save them (dry run unless `--write`) | Second Root, once |
| `site.config.json` | which site the page code builds | nobody |
| `content/generated-materials.json`, `content/photo-provenance.json` (when present) | records written at delivery | nobody (not in `.pages.yml`) |

## Cloudflare Pages settings

Taken from the Cloudflare Pages build-image documentation
(https://developers.cloudflare.com/pages/configuration/build-image/, read 2026-11-27). Not yet tried on a real Pages
project; that needs the owner's approval.

| Setting | Value |
|---|---|
| Framework preset | None |
| Build command | `npm ci && npm run build` |
| Build output directory | `dist` |
| Root directory | (empty: the repository root) |
| Environment variable | `SKIP_DEPENDENCY_INSTALL` = `1` (the build command installs the exact lockfile versions itself) |
| Node.js | from `.node-version` (`22.23.4`, the v3 build image's default) |

No other variables or secrets are needed. The build image runs Linux x86_64, where the pinned `sharp` installs its
prebuilt binary from the npm registry.

## Build locally

```
npm ci
npm run build     # writes dist/; a stopped build leaves dist/ as it was
npm test          # node --test: sample build, Pages CMS save shapes, last good output, phone photos
```

## Photos

- JPEG, PNG and WebP. A phone's full-size photo is fitted by the build (upright, inside 2560 px, no metadata such as
  the GPS position). The repository keeps the original.
- Delivered generated materials and shop-provided photos keep their exact bytes.
- HEIC (an iPhone's default format) is not accepted. On the iPhone, go to 「設定」→「カメラ」→「フォーマット」→
  「互換性優先」, or upload from Safari, which sends a JPEG. A stopped build names the photo and what to do.
