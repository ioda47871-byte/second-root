# DEV-043: tight + medium hero compaction for every layout

## Cause (from DEV-042, cause 3)

- DEV-036 / DEV-038 made a `tight` + `medium` hero a band, not a screen, but only for `centered_cover`.
- `stacked_oversized` and `split_crop` kept the generic medium floor: 40svh on phones, 56svh on desktop.
- On a sparse page, a reviewer asking for a lower hero could only reach it with `centered_cover`, which pushed every run toward that layout.

## Change (`components/demo/profile/profile.module.css` only)

The DEV-038 `centered_cover` rules stay byte-identical. Two rule pairs are added next to them, with the same values, for every layout without a photo:

- Phones (< 720 px): `.canvas[data-spacing="tight"] > .hero[data-height="medium"]:not([data-photo])` → `min-height: 22svh; padding-top: 14px; padding-bottom: 14px`, and its `.title` → `padding: 14px 0`.
- Desktop (≥ 720 px): the same selector → `min-height: 38svh; padding-top: 18px; padding-bottom: 24px`, and its `.title` → `padding: 24px 0`.

Unchanged:
- `centered_cover` (all values and all cases, including its framed photo hero, which already had the band since DEV-038);
- DEV-036's every-spacing phone floor for a medium centered cover (28svh, title 20 px), which stays `centered_cover` only;
- the desktop name cap of a medium centered cover (9 rem), which is the layout's own type size, not compaction;
- other spacings and heights;
- photo heroes of the other layouts: split heroes are not direct children of `.canvas`, and framed heroes carry `data-photo`.

Specificity: (0,5,0) for the hero and (0,6,0) for its title, equal to the `centered_cover` rules they sit beside. They beat the generic medium floor (0,2,0), DEV-036's centered-cover rules (0,3,0) / (0,4,0), the desktop `.hero` padding and the base `.title` padding.

## Recorded, not changed: split_crop with Japanese / unspaced names (DEV-042, cause 5)

- `setsInPieces` (`components/demo/profile/text.ts:314`) sends every name without spaces, or with any Japanese character, down the pieces path (`ProfileRenderer.tsx:108`). `nameLines`, which gives split_crop its one-word-per-line split, is used only for spaced Latin names.
- On desktop, such a name is set on one line sized to fit (`profile.module.css`, the `[data-fit="phone"]` rule at ≥ 720 px). split_crop then differs from the other layouts only in its larger type.
- On phones, split_crop only right-aligns every other phone line (`profile.module.css:187`).
- So for most shops in this market, split_crop's signature is weak. Fixing it is a typographic design change, outside DEV-043. Revisit after the next controlled rerun if structure still converges.

- `dot_grid`: the dots run past the hero's bottom edge and are clipped by up to about 31 px (split_crop, 360 px; stacked_oversized 28 px; centered_cover 24 px). They are decorative and sit behind the area line.

The lines do not cross (the bracket has only bottom and left borders) and the area text starts clear of it. centered_cover never shows this because it hides that rule. This is new crowding of decorations only.
