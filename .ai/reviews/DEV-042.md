# DEV-042: structural convergence (investigation only, 2026-10-17)

Question: why do the sparse Staging runs end on `centered_cover / medium / editorial_12 / ruled_list / hairline / tight`, with only direction, palette and type varying?

Sources: repo code at develop `a2f431c` and the run records in `.ai/reviews/DEV-034…039.md` and `.ai/progress.md` (codes, scores and stored enum values only). No screenshots, Instagram content, cookies, HTML, sessions or URLs were opened.

## Ranked causes

1. **The starting structure is fixed by the category defaults, and low-confidence briefs fall back to them.**
   - `lib/design-agent/defaults.ts:10-18`: the shared `base` is `centered_cover / tall`, `editorial_12 / ruled_list / hairline`, `generous`. bakery keeps all of it; baked_goods changes only info style and divider; only cafe changes the hero.
   - `lib/design-agent/pipeline.ts:126-132`: a brief under `LOW_CONFIDENCE` (0.5, `defaults.ts:8`) is replaced whole by the default, its structure included. 3 of the 7 recorded runs started this way (sparse Instagram material tends to give low confidence; `prompts.ts:41` asks for < 0.5 in that case).
2. **The review loop only refines; it does not re-choose the structure.**
   - `prompts.ts:120` (history block): "Keep what scored well and fix the problems; do not repeat a change that made a later round score lower." With `MAX_REVISIONS = 2` (`pipeline.ts:19`), each revision is a small step from candidate-0. Structural moves carry risk under that rule, so height and spacing move (`tall → medium`, `generous → tight`) while the layout stays.
   - `generic_template_feel` is scored per job (`prompts.ts:146`). The reviewer cannot see that other demos share the structure, so cross-demo sameness is never penalised. This is by design, not a defect.
3. **The renderer's sparse-page compaction exists only for `centered_cover` + `medium` (since DEV-036 / DEV-038). This is a reinforcer, not the origin** (the PoC runs converged before it existed).
   - `components/demo/profile/profile.module.css:380-386, 694-695`: under `tight`, a medium centered cover's floor is 22svh on phones (≈ 186 CSS px at 390 × 844) and 38svh on desktop (≈ 342 px at 1440 × 900).
   - Every other layout keeps the generic medium floor: 40svh on phones (≈ 338 px, `:87`) and 56svh on desktop (≈ 504 px, `:683`).
   - Reviews of sparse pages repeatedly asked for less hero height and whitespace (DEV-036 / DEV-038 causes). Within the vocabulary, only `centered_cover / medium / tight` reaches that, so it is the best-scoring structure for the reviewer.
4. **Some structural values make no difference on the phone, so nothing moves them off the default.**
   - `grid` is applied only at ≥ 720 px (`profile.module.css:714-717`); on the 390 px shot all three grids look the same.
   - `ruled_list`'s label column is desktop-only too (`:722`); `hairline` is the quietest divider.
   - The reviewer weighs mobile heavily (problem areas and `mobile_quality`), so these stay at the `base` values.
5. **`split_crop` loses its character for Japanese / unspaced names** (minor).
   - `ProfileRenderer.tsx:108`: unspaced names use the phone pieces, not `nameLines`; on desktop they are set on one line (DEV-034.md:62), and on phones split_crop only right-aligns every other line (`profile.module.css:187`). For this market's mostly Japanese names, one of the three hero layouts is weak.

Not causes: the score formula (`review.ts:46-48`), the profile validator (`profile.ts:156-164`, which checks only schema, contrast and repeats), and the DEV-039 prompt calibration (the run before it converged too).

## Conclusion

- No single small, generic fix is justified. The causes are independent (1 is about the defaults and fallback, 3–5 about the renderer), each changes design outcomes, and each needs its own controlled rerun to judge. Whether structural variety matters more than the current scores is also a product call.
- DEV-042 is closed as investigation only. No code, CSS, prompt, threshold, schema or data change.
- Follow-ups (backlog, start decision by a person):
  - **DEV-043**: renderer parity for sparse pages. Give `stacked_oversized` and `split_crop` the same tight / medium compaction `centered_cover` has (causes 3, and 5 as a related note), with geometry tests. CSS only.
  - **DEV-044**: starting structure. Per-category structural variety in the defaults, and/or keep the low-confidence brief's structure while using the default's other values (causes 1–2). Changes defaults and pipeline behaviour, so a human design decision comes first. The 0.5 threshold itself stays.
- Cause 4 (mobile-invisible grid) is recorded only; it needs no task unless DEV-043 / DEV-044 show it matters.
