# DEV-022 / DEV-023 review — fresh-context reviewer (security + correctness)

One branch and one PR for both tasks: the admin inbox UI (DEV-022) and human-approved sending through the official Send API (DEV-023).

## Round 1: PASS (Critical 0 / High 0 / Medium 4 / Low 6)

Verified OK:
- All 6 admin RPCs are SECURITY DEFINER, set `search_path=''`, and call `sales_assert_admin()` first. Execute is granted only to authenticated and service_role; the ingest role (service_role) fails the admin check.
- `sales_ig_sends` is readable only by admins (RLS).
- Concurrent taps are serialized by the draft's row lock, so there is never a second send.
- `unknown` is never resent automatically, and editing is blocked while a send is sending or unknown.
- Unmatched, DNC and 24h-window refusals are enforced in the DB.
- The token is server-only and appears only in the Authorization header; it is never logged.
- No `dangerouslySetInnerHTML`, and nothing sets or clears DNC.

| Sev | Finding | Resolution |
|---|---|---|
| Medium | An older `failed` draft stayed sendable after a newer message arrived | Fixed. `begin_send` refuses (`stale_draft`) and supersedes any draft that doesn't answer the latest inbound message; the same order is used as in DEV-021. Ignoring a thread also supersedes `failed` drafts. The inbox marks such drafts stale and disables their buttons. Test [R1-M1]. |
| Medium | `finish_send` had no state guard, so a late or duplicate result could overwrite `unknown`/`failed` or a newer send's draft state | Fixed. It accepts a result only for a `sending` send, or a definite `sent`/`failed` for an `unknown` one; anything else is a replay. The draft follows only its newest open send. Tests [R1-M2]. |
| Medium | A draft left in `sending` had no way out in the UI | Fixed. The button becomes 「送信状況を確認」. It calls `begin_send`, which reports in-flight or, after 2 minutes, `unknown`; it never resends. A 送信中 badge is shown. |
| Medium | Ambiguous 4xx errors (code 1/2, `is_transient`) were counted as `failed` and could be retried into a double send | Fixed: these now count as `unknown`. Tests added. |
| Low | An admin browser session could call `finish_send`/`update_draft` directly, bypassing the text checks | `sendIgReply` now re-runs `checkDraft` right before `begin_send`. Direct `finish_send` by an admin is accepted as trust-equivalent: the admin can send from the Instagram app anyway, and the send record exists only for them. |
| Low | `snoozed_until` was never read | Fixed: a snooze lasts 24h, then the conversation returns to the open list. |
| Low | Buttons were enabled in states the DB refuses; DNC not used in `canSend` | Fixed: edit and snooze are gated by status and staleness; DNC disables sending and shows a badge. |
| Low | `resolve_thread` could re-link a matched thread, or ignore one with an open send | Fixed: only unmatched threads can be linked (`already_resolved`), and ignoring is refused while a send is open (`send_open`). Test [R1-L8]. |
| Low | Send POST lacked `redirect: "error"` | Fixed |
| Low | DNC check relied on the matched CHECK constraint | Fixed: now requires that a non-DNC prospect exists. |

Also added: token expiry (Meta code 190) gets its own message 「アクセストークンの期限切れ」.

## Round 2: FAIL (Critical 0 / High 1 / Medium 3 / Low 4)

The round-1 fixes were verified, and the four invariants hold: no double send, no "sent" on failure, no automatic resend of unknown, human-only sending. The High was a regression introduced by the round-1 `follow` rule.

| Sev | Finding | Resolution |
|---|---|---|
| High | `finish_send` picked the "newest send" by `created_at`, so retrying an earlier text (A → B → A) left the draft stuck in `sending` | Fixed: the draft follows the send unless another send of the same draft is still open. The inbox now prefers the open send, then the latest `updated_at`. Test [R2-H1]. |
| Medium | A retried send reuses its send id, so a late answer for attempt 1 could be taken as attempt 2's result | Fixed: `begin_send` returns `attempt`; `finish_send(p_send_id, p_attempt, …)` ignores a mismatched attempt as a replay. Test [R2-M1]. |
| Medium | 「送信状況を確認」 was blocked by the window, DNC and match state, and by the text re-check | Fixed: for a `sending` draft the button is always available, and the action skips the re-check. `begin_send` only replays it, and after 2 minutes reports `unknown`. |
| Medium | A newer draft hid an unresolved `unknown` send | Fixed: a draft with an open send (`unknown`/`sending`) is shown first until the human settles it. |
| Low | `begin_send` did not lock the thread (race with 「営業と関係ない」) | Fixed: `for update` on the thread |
| Low | ISO strings compared with `localeCompare` | Fixed: compared as instants (`Date.parse`), then the id |
| Low | Stale draft stays disabled if a new draft never comes | Accepted. The inbox job retries with back-off; the human can still answer in the Instagram app. |
| Low | A late `sent` after the human recorded "not sent" was ignored | Fixed: a definite `sent` for the same attempt is accepted over `confirmed_not_sent` |
