## Findings and responses

1. **Medium — an email-only exclusion did not match a candidate whose email is not first-party.**
   - Problem: the checkpoint's `public_email` is set only for a first-party email. An existing customer registered by email could therefore still get an Instagram DM when Op Claude found the shop through Instagram and the email came from a link-in-bio page.
   - **Fixed:**
     - `prepareCandidate` now adds `email_digest`: the SHA-256 (hex) of the normalised submitted email, whatever its source. The raw email is still kept only when it is first-party.
     - The persist exclusion check also compares `sha256(exclusion.public_email)` with `c->>'email_digest'`.
     - Tests added:
       - integration: a non-first-party email is excluded, and a different email still gets `outreach_ready`;
       - unit: digest parity between TS and the stored value, and the raw non-first-party email does not appear in the candidate.
   - The form hint now asks for every known key, especially Instagram.
2. **Low — docs said Op Claude cannot see the list.**
   - The persist result does return reason `excluded`.
   - **Fixed:** MVP_SPEC §3.5.1 now says Op Claude cannot see the list or its contents, only the reason `excluded`.
3. **Low — the Instagram input was stricter than its label.**
   - `instagram.com/x`, `http://…` and `m.instagram.com/…` were refused.
   - **Fixed:** these forms are now accepted and normalised to `https://www.instagram.com/<handle>/`. Unit cases added.
4. **Low — an over-long field was silently dropped.**
   - The server action used `.catch("")`.
   - **Fixed:** a zod object schema now refuses over-long or non-string fields with an error, so an entry is never saved without a key the admin typed.
5. **Low — there was no ingest ↔ exclusion parity test.**
   - **Fixed:** new unit tests run `prepareCandidate` and `parseExclusion` on the same raw values and compare the handle, name + address, domain, email and email digest.
   - Not changed: the page's count is capped by the 500-row read. An exclusion list longer than 500 is not expected.
