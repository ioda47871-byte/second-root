## Fresh Review round 2 (C0 / H4 / M1 / L2) と対応

round 1 の後の確認のレビュー。指摘は Critical 0、High 4、Medium 1、Low 2。どれも「ページの側の検査 `decorationReferenceProblems` が `[]` を返すのに、Chromium は外や別のファイルを読む」形だった。悪い入力を一つずつ足すのをやめ、**許可一覧とブラウザでの確かめ**に作り直した。有効にするものは何も無い (comp-impl・`.github/workflows`・worker の道・依存は不変)。

- **H-1 外来の内容。** `<math><title><img src="//evil.example/x"></title></math>` (`style`・`textarea`・`xmp`・`noembed` も同じ) を、検査器は生の文字として飛ばしたが、ブラウザは `math` の中の `<img>` を HTML に戻して読む。→ 要素の許可一覧にした。`math`・`svg` は表に無いので名前で拒む (`PAGE_ELEMENT_NOT_ALLOWED`)。5通りすべてにテスト。Chromium が実際に `evil.example` を求めることもテストで示した。
- **H-2 `noscript`。** 検査器は JS 無効の読み方 (マークアップ) をしたが、来訪者は JS 有効 (生の文字) で読む。`<noscript><title></noscript><img src="//evil.example/x"></title>` とコメントの形。→ `noscript` を表から外した。コメントも全部拒む (`PAGE_COMMENT`)。2通りにテスト。JS 有効の Chromium が `evil.example` を求めることもテストで示した。
- **H-3 プロトコル相対の URL を値の先頭でしか見ていなかった。** `srcset="a.png 0.1x, //evil.example/x 1x"` (`img` と `<picture><source>`)、`\\evil.example/x`。→ `srcset`・`sizes` は `img` の属性の表に無い。`picture`・`source` は要素の表に無い。`img` の `src` は記録したパスと文字列として等しいときだけ通る (`SVG_NOT_RECORDED`)。3通りにテスト。`srcset` で Chromium が `evil.example` を求めることもテストで示した。
- **H-4 `<base>`。** `<base href="/x/">` で、記録した名前が検めていない別のファイルを読む。→ `base` は表に無い。絶対と相対の2通りにテスト。Chromium での確かめもテストにした。
- **M-1 `<link rel="stylesheet" href="other.css">` が通った。** → `link` は表に無い (このページは記録した資産のほかに何も読まない)。テストと、Chromium が `other.css` を求めることのテスト。
- **L-1 文書が字句解析器を言い過ぎていた。math・noscript・base・複数の候補の srcset のテストが無かった。** → 文書の 2.9 を許可一覧の記述に書き直し、「HTML の仕様の全部ではない。その代わりに字句の状態を変える要素・コメント・宣言・属性の値の `&` を拒むので、通るページでは残りに頼らない」と正確に書いた。2.10 にブラウザでの確かめを書いた。テストは上のとおり。
- **L-2 `srcset` や `picture` が置き換えても、記録した資産を「使った」と数えていた。** → 使ったと数えるのは、拒む属性も他の誤りも無い `img` の `src` だけ (`checkDecorationPage` の `used`)。`srcset` 付きの `img` だけのページは `SVG_RECORDED_NOT_USED` になるテストを足した。

### 作り直したもの

1. **静的な許可一覧 (第一の門)。** `checkDecorationPage(html, css, assets)` → `{ problems, used }`。`decorationReferenceProblems` はその `problems`。
   - 要素: `html`・`head`・`meta`・`title`・`body`・`header`・`main`・`footer`・`nav`・`section`・`article`・`aside`・`div`・`p`・`span`・`h1`〜`h6`・`ul`・`ol`・`li`・`dl`・`dt`・`dd`・`figure`・`figcaption`・`img`・`a`・`br`・`hr`・`strong`・`em`・`small`・`b`・`i`・`time`・`address`・`blockquote`。本番の `PAGE_ELEMENTS` から `link` を外し、読み込みも字句の切り替えもしない要素を少し足した。
   - 属性: `meta` は `charset="utf-8"` だけ。`a` は `href="#id"` だけ。`img` は `src` (記録したパス)・`alt=""`・`referrerpolicy="no-referrer"`・`width`・`height`・`loading`・`decoding` (`srcset`・`sizes` は無い)。共通は `class`・`id`・`lang`・`aria-label`・`aria-hidden`・本番の `data-comp-*` と `data-comp-role`。値ごとに文法がある。属性の値の `&` は拒む。
   - `title` は `head` の中だけ、中身に `<` を持てない。コメントと、先頭の `<!doctype html>` 以外の宣言は拒む。制御文字は拒む。
2. **ブラウザでの確かめ (第二の線)。** `lib/design-agent/research/decoration-page-browser.ts` の `verifyDecorationPageInBrowser(browser, dir, html, css, assets)` と `launchDecorationBrowser()` (`PLAYWRIGHT_CHROMIUM_EXECUTABLE` を使う)。ページを `http://decoration-page.invalid/page/index.html` として JS 有効・無効の2回描き、ページと記録した資産のほかの要求をすべて中断して `PAGE_UNEXPECTED_REQUEST` にする。DOM の要素の表 (`PAGE_DOM_ELEMENT_NOT_ALLOWED`)、装飾の `img` の `currentSrc` (`PAGE_UNEXPECTED_IMG`)、それと静的な `used` の一致 (`PAGE_DECORATION_MISMATCH`)、`performance` の resource の項目も照らす。静的な検査を新しい依存無しに保つため、別のファイルにした (`playwright` は既存の依存)。`.ai/tasks.json` の DEV-162 の `allowed_scope` にこのファイルを足した。
3. isolation のテスト: 検査器の import は node の組み込み3つのまま。ブラウザでの確かめの import は `node:fs`・`node:path`・`playwright`・`./decoration-svg` だけ。どちらにも禁止の語が無い。`lib`・`app`・`components`・`scripts` の誰も2つを import しない。`lib/design-agent/research` はこの2つだけ。
