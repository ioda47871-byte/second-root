## 守った規則

- 成功例 30 件と SR-001「輪」は参照だけ (判断の基準・近さの比較・禁止の hash・Staging の架空の試験)。相手のデモに写さない (§7.6)。
- Identity Lock と事実パック (不明は省くか「未確認」)、B方式の JS / 通信 / 書体 / asset の制約、`PAGE_FONT_FAMILIES`、`APPROVED_CAPABILITIES` (空のまま) を緩めない (§7.3・§7.4)。
- リポジトリのファイルにモデル名・所有者名・同意の参照・private path を書いていない。secret は扱っていない。
- 外部への接続は GitHub の push と PR だけ。DB・Storage・Vercel・WSL には触れていない。

## 今のコードで確かめたこと (下書きとの差)

- 下書き (研究メモ) の基盤は develop 56a6a3b で、DEV-195 が無かった。6443d99 で DEV-195 の `sales_outreach_approvals` と `sales_demo_version()` を読み、**今の `demo_version` は版の差し替えを拾わない**ことを確かめ、拡張を足した (§9.3)。
- `/design-preview/[runId]` (ローカル専用、`SR_DESIGN_PREVIEW_ROOT` が無ければ 404) が `next.config.ts` の DENY の対象に入っていることを確かめた。新しい接頭辞 `/demo-frame/` はどの既存の規則にも当たらない。
- 共有の view token は、匿名の要求のたびに DB に書かないよう HMAC にした (下書きは DB の session)。新しい環境変数が要る (§12 DEV-196d)。
