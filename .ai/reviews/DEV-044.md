# DEV-044: hybrid fallback for low-confidence briefs

Decision (human, 2026-10-17): when the brief is schema-valid but its confidence is below 0.5 (`LOW_CONFIDENCE`, unchanged), do not replace the whole profile with the category default. Keep only the structural choices that are safe and meaningful from the brief; take brand-sensitive or weak-evidence styling from the category default.

## Field-by-field classification (before coding)

Basis: `lib/design-agent/profile.ts` (schema), `components/demo/profile/ProfileRenderer.tsx` and `profile.module.css` (what each value does), `lib/design-agent/defaults.ts`, and DEV-036 / DEV-038 / DEV-043, which make every structural combination render without overflow or clipping (DEV-036's 4,500-render probe and DEV-043's develop-vs-branch probe).

| Field | Class | Source after the change | Why |
|---|---|---|---|
| `version` | n/a | literal 1 | Schema constant. |
| `direction` | 2 brand-sensitive | default | The art-direction label is the shop's identity, which is exactly what a low-confidence brief says it could not read. |
| `palette` (6 colours) | 2 brand-sensitive | default | Brand colour from weak evidence is the main risk. The defaults pass the contrast check by construction. |
| `typography.display` / `body` / `displayCase` / `displayWeight` / `tracking` | 2 brand-sensitive | default | The type voice is brand character (a Mincho vs a condensed grotesk, uppercase Latin, weight, tracking). |
| `motifs` | 2 brand-sensitive | default | Monogram, stamp ring and pleated liner are identity marks; weak evidence should not add them. |
| `heroLayout.layout` | 1 structural, safe | brief | Page architecture only (`data-layout`). All three layouts render any name and palette, and DEV-043 gave them equal sparse-page compaction. This field is what DEV-042 found collapsed. |
| `heroLayout.height` | 1 structural, safe | brief | A floor only; content grows past it. |
| `heroLayout.alignment` | 1 structural, safe | brief | Structural by its meaning (left / centre of the lower sections). It is currently inert: `ProfileRenderer.tsx:224` sets `data-align`, but no CSS rule uses it (pre-existing; the prompt vocabulary promises an effect). Keeping it is therefore harmless. |
| `composition.grid` | 1 structural, safe | brief | Section columns (desktop only). |
| `composition.infoStyle` | 1 structural, safe | brief | How the facts are laid out (ruled list / colophon / ledger columns). |
| `spacing.scale` | 1 structural, safe | brief | Page density. DEV-036 / DEV-038 / DEV-043 made every scale render sparse pages well. |
| `composition.divider` | 3 ambiguous | default | A rule between sections in the primary colour. Its weight (hairline / double / thick / none) reads as ornament and goes with the direction (the baked_goods default pairs `double_rule` with `editorial_luxury`). There is no repo evidence that it is pure structure. |
| `motion.intro` / `motion.sectionFade` | 3 ambiguous | default | Not visible in the review screenshots (reduced motion), so there is no evidence either way. |
| `confidence` | metadata | default (1) | Unchanged from today: the pipeline reads `confidence` only on the brief, before this step, and `briefConfidence` already records the brief's own value. |
| `rationale` | metadata | fixed text | Never rendered, and removed before upload. The brief's own words are not kept. One fixed line says what was combined, so the reviewer is not told "category default" for a page with the brief's structure. |

Summary: 6 structural fields are kept from the brief (`heroLayout.layout`, `heroLayout.height`, `heroLayout.alignment`, `composition.grid`, `composition.infoStyle`, `spacing.scale`). Everything else comes from the category default.

## Behaviour to keep

- Brief schema- or contrast-invalid, or a Codex error: unchanged (`fallback_template` / environment failure). The hybrid applies only to a brief that passed `checkProfile`.
- Confidence ≥ 0.5: unchanged (the brief as is).
- Threshold 0.5, score, `MAX_REVISIONS`, schema / enums, review prompts: unchanged.
- If the combined profile ever failed `checkProfile` (it cannot today: palette and motifs come from a valid default), use the plain category default as before, with a note.

## Known interaction (from DEV-043, accepted there)

- The bakery default has `corner_marks`. Combined with a brief's `stacked_oversized` / `split_crop` + `medium` + `tight`, phones show DEV-043's accepted Low (corner bracket meeting the area line's rule). This is decorative only.

## Implementation

- `lib/design-agent/defaults.ts`: `briefStructureOnDefault(brief, category)`. It starts from the category default and takes the six structural leaves from the brief. `rationale` becomes the fixed `BRIEF_STRUCTURE_RATIONALE`. It returns `null` if the result fails `checkProfile`.
- `lib/design-agent/pipeline.ts`, low-confidence branch only:
  - the note `LOW_CONFIDENCE_CATEGORY_DEFAULT` is kept;
  - then `BRIEF_STRUCTURE_KEPT` + `profileSource: "category_default_brief_structure"`;
  - or, if the combination failed the check, `BRIEF_STRUCTURE_REJECTED` + the plain default (`profileSource: "category_default"`, as before).
  - `brief-low-confidence.json` is still written locally.
- `docs/operations/design-agent-wsl.md`: two rows in the note table.
- Unchanged: `LOW_CONFIDENCE` (0.5), schema / enums, prompts, review, score, `MAX_REVISIONS`, the renderer and CSS, and the invalid-brief and Codex-error paths.
