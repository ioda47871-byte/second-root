## Findings and responses (fixed in b913d7d..fcdfc37)

1. **Medium — `RATE_LIMITED` was not a STOP code.** A rate-limited public capture was delivered as blocked, and the demo closed for good.
   - **Fixed:** `RATE_LIMITED` is a STOP code (whole word).
   - **Also added:** `helper_no_answer_in`. When the signed-in helper gave no answer and the public fallback then ended `PUBLIC_SOURCE_UNAVAILABLE`, the cycle stops. The codes are BROWSER_BUSY, HELPER_BUSY, HELPER_ERROR, CAPTURE_FAILED, CAPTURE_HELPER_TIMEOUT, CAPTURE_HELPER_UNAVAILABLE and the CAPTURE_/REQUEST_INVALID codes. The stop is `CYCLE_STOP_WORKER_SIGNAL`. The result then reflects the helper, not the shop.
   - These changes only make the cycle stricter. Tests added.
2. **Low — the budget check used the bridge's normal timeout (240), not its worst case (260).**
   - **Fixed:** `CLAIM_MIN_LEFT` is now 4220, and the check requires at least `WORKER_MIN_LEFT + BRIDGE_MAX`. Tests and the runbook table are updated.
3. **Low — the root-owned lock fd was inherited by less-privileged children.**
   - **Fixed:** `9>&-` on every bridge and other child call.
4. **Low — a relative invocation failed.**
   - **Fixed:** the script path is resolved with `readlink -f` before `cd /`. Tested.
5. **Low — redaction gaps** (JSON-quoted keys, multi-pair cookies, `x-api-key`, long hex).
   - **Fixed:** all of these are now redacted; job ids and UUIDs stay readable. Tests added.
6. **Low (docs) — stopping the cycle does not stop the jailed worker.**
   - **Fixed:** runbook §5 adds `systemctl stop 'sr-jail-run-*'` and a check.
7. **Low (docs) — no recovery path when the worker exported no result.**
   - **Fixed:** runbook §6.2 adds it: wait for the bridge's local expiry, then `--deliver-only` (expired 1), then one manual worker run to withdraw the job, then check that everything is empty.
8. **Low (tests) — some production guards and codes were not exercised.**
   - **Fixed:** new tests cover these codes and phases:
     - `CHECK_WORKER_RUNNING` alone
     - `claim_unknown`
     - `CYCLE_STOP_TIME_BEFORE_DELIVER`
     - `CYCLE_STOP_INTERNAL`
   - A production-path guard test runs in a private user/mount namespace (`unshare -rm`). It checks:
     - the test hook is refused at `/root/sr-capture-admin` (absolute and relative path);
     - a non-root user is refused.
   - No test hook was added to production.

## Checked and fine (reviewer)

- **Environment, PATH, IFS, umask:** the script re-executes itself with `env -i`. The test hook cannot run in production.
- **Files of less-privileged users:** root never runs git, python or cat on files the bridge user controls. The token is never read. `runuser` works under NoNewPrivileges.
- **Unit hardening vs `admin.sh run`:** compatible.
- **STOP list:** whole-word match, so `JAIL_OK` does not stop the cycle.
- **Claim and deliver:** the cycle claims exactly one job and delivers exactly that job.
- **Time budget:** fixed at the start; arithmetic consistent with `admin.sh` RuntimeMaxSec=3500 and the bridge timeouts.
- **Exit codes, signal handling, `flock`:** checked.
- **Units:** not installed or enabled. Installing and enabling them are human steps.
- **Recovery SQL:** guarded by the job id and `processing`. It keeps attempts and touches only that row.
