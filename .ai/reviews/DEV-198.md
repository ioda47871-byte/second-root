# DEV-198: phase2f-live steps のテストで pre-render の終了コードを先に確かめる

2026-11-11。branch `feature/dev-198-prerender-status-asserts` (`origin/develop` f3a8dd3 から)。

## 発端

CI run 42961770373 (PR #249、`unit (1/2)`、attempt 1) で `tests/unit/design-agent/phase2f-live/steps.test.ts` の
「records must agree before anything is used › an image request changed after the pre-render is refused before the approval is used」が
`ENOENT …/runs/pre-12/image-request-A1.json` で落ち、attempt 2 で通った。test は `w.prerender(d.outDir)` の終了コードを見ずに `.dir` を `readRequest` に渡していた。

**本当の原因 (同じ job の log、04:55:09)**: `steps CLI --prerender: stopped RENDER_FAILED (Error: page.screenshot: Protocol error (Page.captureScreenshot): Unable to capture screenshot)`。
timeout ではなく、Chromium の screenshot の失敗 (DEV-137 で記録した断続的な RENDER_FAILED と同じ系統)。指示どおり timeout は上げず、ここに報告する。

## 変更 (test のみ)

- `world()` に `prerenderOk(designDir, route = "C")`: `prerender` を呼び、`expect(pre.status, \`${JSON.stringify(pre.out)}\n${pre.stderr}\`).toBe(0)` を確かめてから返す。
- pre-render の出力 (image-request-*.json・prerender.md・JSON の `ready`) を使う 20 箇所をすべて `prerenderOk` に。直接の `w.prerender(` は2箇所だけ: 最初の test (元から同じ確認あり) と、`RECORD_MISMATCH` の停止を期待する test (終了コード 2 が正しい)。
- skip・retry・削除・期待の緩和・timeout / 閾値の変更なし。`n` の採番・`pre-N` の名前・既定の route も変わらない。

## Fresh Review (別 context の subagent)

- 対象 commit 62a76df。判定 **PASS**。Critical 0 / High 0 / Medium 1 / Low 1。
- **Medium (対応済み)**: CLI はすべての停止 (RENDER_FAILED の detail を含む) を stdout の JSON に書き、stderr はほぼ空。`pre.stderr` だけの message では原因が出ない。→ message を `JSON.stringify(pre.out)` + stderr に (同じ file の `expect(c.status, JSON.stringify(c.out))` と同じ形)。手元で壊れた既定の browser で確かめ、失敗は `ENOENT` ではなく `AssertionError: {"status":"refused","code":"REFUSED"}` になった。
- **Low (対応済み)**: 受け入れ基準の `.ai/reviews/DEV-198.md` が未 commit → この file。
- 範囲外の follow-up (報告のみ): `scripts/design-artifact/phase2f-steps.ts` の最後の catch は想定外の例外 (例: `chromium.launch()` の失敗) を `{status: refused, code: REFUSED}` にし、例外の内容をどこにも出さない。CI でそれが起きると原因がわからない。本体の変更なので別 Task の候補。
