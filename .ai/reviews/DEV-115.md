1. **[fail-open（1段目）] 安全検査 `checkPrototype` を素通りして、描画中に外部への要求を出させる試作が作れる。**
   - **場所:**
     - `lib/design-agent/phase2f/prototype-safety.ts:42-52`（`cssProblems` のエスケープ展開 → コメント除去 → `url(` の正規表現）
     - `:37`（`URL_ATTRIBUTES` に SVG のプレゼンテーション属性が無い）
   - **再現（実機。すべて安全検査は OK、描画で `blocked = 2`）:**
     - 引用符付きで `)` を含む URL: `body{background:url("http://evil.example/a)")}`。正規表現 `[^'")]*` が一致しないので、URL として見られない。同じ形は `cursor`・`border-image`・`list-style-image`、style 属性（`&quot;`）、SVG の `<style>` でも通る。
     - エスケープで偽のコメントを作る: `a{x:/\2a} body{background:url(http://evil.example/b.png)} /* */`。展開後の `/*` が本物の url() を「コメント」として消す。実際の CSS では `/\2a` はコメントではない。
     - 文字列の中の `/*`: `a::before{content:"/*"} body{background:url(http://…)} b::after{content:"*/"}`
     - SVG 属性 `fill="url(http://…#g)"`・`mask="url(http://…#m)"`。これらは style 属性でも `URL_ATTRIBUTES` でもないので、検査されない。
   - **影響:**
     - 要求は route abort で外へ出ない。runner は `PROTOTYPE_NETWORK_ATTEMPT`（ownerCheck）で止まることを、runner 全体で確認した。
     - ただし、docs §3 の「CSS のエスケープは展開してから調べる…隠し方は見抜く」は事実より強い。
     - route C では、安全検査の後・描画の前に画像の呼び出しをするので、承認済みの画像呼び出しが1回消費されてから止まる（実機で `asset_calls = 1` を確認）。
   - **修正案:**
     - CSS を文字列とコメントを区別する tokenizer で読む。または、構文解析と同じ空ページで `new CSSStyleSheet().replaceSync(css)` を使い、CSSOM の各宣言値から `url()` を取り出す。
     - `url\(\s*("(?:[^"\\]|\\.)*"|'(?:[^'\\]|\\.)*'|[^)]*)\)` のように、引用符の中の `)` を扱う。
     - SVG 要素のすべての属性値に `url(` があれば `cssProblems` に通す。
     - 上の4形をテストに加える。
