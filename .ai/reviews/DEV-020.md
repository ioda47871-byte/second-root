# DEV-020 security review (PR #30) — fresh-context reviewer

VERDICT: PASS (Critical 0 / High 0 / Medium 3 / Low 5)

Verified: HMAC over exact raw bytes, strict header format, constant-time compare, nothing stored/logged before verification; handshake token compared in constant time, challenge restricted and returned as text/plain + nosniff; 503 fail-closed; 2MB cap on declared and streamed bodies; single-transaction RPC (retry-safe), concurrent same-mid handled by `on conflict`; RLS/grants (authenticated read-only, anon none, RPC service_role only); no raw body / attachment URL / token stored; direction rules; db-security-audit passes with the new objects.

| Sev | Finding | Resolution |
|---|---|---|
| Medium | Unsent message kept its text when message + delete came in one batch, or when the delete arrived first | Fixed: in-batch dedupe keyed on (mid, is_deleted); delete of an unknown mid writes a tombstone so a later original is skipped; attachments cleared on delete; tests for both orders |
| Medium | NUL / lone surrogate / odd mid made a delivery fail forever (poison batch) | Fixed: `safeText` (well-formed, no control chars except tab/newline), printable-ASCII mid, timestamp ≤ 1e14; regression tests |
| Medium | `INSTAGRAM_ACCOUNT_ID` optional → other accounts' events accepted | Fixed: required (digits) or 503; docs updated |
| Low | Timestamp overflow could block a batch | Fixed (`.max(1e14)`) |
| Low | Delete for unknown mid created an empty thread | Accepted: the thread now carries the tombstone that blocks the original |
| Low | Thread upsert touched updated_at / took locks on every event | Fixed: select first, insert only when missing |
| Low | Replay protection depends on retained hashes/mids | Documented for DEV-024 retention (reject timestamps older than the pruned window) |
| Low | Missing tests (orders, odd chars, 413, uppercase header, mismatched/other-account echo) | Added (integration + unit) |
