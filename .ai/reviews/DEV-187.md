# DEV-187 Review — 画像の承認を root の境界で1回限りにする（既定 OFF、real Codex 0回）

- **根拠:** オーナー指示（Issue コメント 6677710995）。無人 real Codex の ON の承認ではない。
- **土台:** `origin/develop` `1a9f649`（DEV-186、PR #228）。

## 守った権限境界

- **使用の確定は root:** `cycle.sh`（root、`sr-design-cycle.service`）が idle の worker 実行の直前に、root の state（`/var/lib/sr-design-cycle`、0700）へ `image-approval-used/<承認ID>` と `image-job-used/<job_id>` を atomic `mkdir`。どちらか既存なら grant を出さない。worker の利用者は消せない。DEV-185 の消費済み ID は常に拒否。
- **grant:** その後でだけ `/var/cache/sr-design-image-grant/grant.json`（root 0644、dir は unit の `CacheDirectory`・0755）。承認 ID・job_id・ジョブのバイト列の SHA256・発行・期限（worker 実行の上限 RuntimeMaxSec+停止猶予）。実行直後・cycle の全終了経路（`finish`）・次の cycle の開始時に消す。
- **root は worker のファイルを root として解釈しない:** inbox は `runuser -u sr-designgen python3 -I`（`as_bridge` と同じ形）で、link を辿らず 16KiB まで読み、厳密な書式の1行だけ返す。root は自分の設定だけを `python3 -I` で読む。
- **worker 側:** 既存の確認すべてに加え grant（root 所有・link でない・書込不可・dir が root の 0755・ID と SHA256 の一致・期限内・1実行分の長さ）。無ければ `REFUSED_NO_GRANT`、生成0回。

## 設計の判断

1. **どの worker 実行か:** step 3（idle run）。毎回の cycle で動き、step 5 が `CYCLE_IDLE` で終える前にある。step 6 は bridge の claim があった時だけ。grant を出した回は idle run の後 `CYCLE_IMAGE_RUN`（exit 0）で終える（重い仕事は1回に1つ。`SuccessExitStatus` は変えない）。
2. **置き場所:** 提案の `/run/sr-design-image-grant` は jail から見えない（`jail.properties` の `TemporaryFileSystem=/run:ro`）。jail を変えずに読める root の場所として `/var/cache`（`ProtectSystem=strict` で読み取り専用に見える）を選び、unit に `CacheDirectory=sr-design-image-grant`・`CacheDirectoryMode=0755` を足した。tmpfs ではないので、残りは cycle の開始時に消し、grant 自体にも短い期限がある。
3. 実行後のエントリ削除は不要（使用済みの印が再発行を止める）。全体の緊急停止 `enabled:false` は残す。
