## Findings

1. **High — surface の上の primary / secondary に contrast の保証が無い。店名・見出し・label・menu 番号が、受理される palette で読めなくなる。**（`profile.module.css`: kissaten_retro の `.title` / `.menuItem` / `.address`、boutique_minimal の `.section` / `.title`、pop_bakeshop の `.menuItem` / `.address`。`lib/design-agent/profile.ts` の `checkProfile`）
   - **現状:**
     - `checkProfile` が surface について保証するのは「text on surface ≥4.5」だけ。
     - DEV-066 までは、surface は写真の下地（写真が覆う）にしか使われていなかったので、問題にならなかった。
     - 本 PR で、surface の上に次のものが描かれるようになった:
       - 店名（primary）: kissaten・boutique の title パネル
       - 見出し（primary）、headingJa・rowLabel・menuNo（secondary）: boutique の各 section
       - rowEn（primary）: kissaten / pop の住所パネル、boutique
       - menuNo: kissaten（secondary）、pop（primary）
   - **再現（checkProfile を通る palette）:** `background #FBF7EF / surface #B07A4F / text #000000 / primary #8A4B22 / secondary #6E5A44 / accent #D4A017`
     - text on surface は 5.74 で、check を通る。
     - primary on surface は 1.85、secondary on surface は 1.79。
     - 「暖かいキャラメルのパネル」は、喫茶・焼菓子でモデルが選びそうな配色。
     - screenshot（kissaten_retro / boutique_minimal、390px）では、店名「EXAMPLE TEST」・ABOUT / MENU / VISIT・Hours などの label・01 / 02 が、地とほぼ同じ色になった。
     - 極端な例: `#767676` の primary と `#7A7A7A` の surface（白地・黒文字）でも check を通る。このとき primary on surface は 1.06。
   - **影響:**
     - 品質基準の「文字は ≥4.5 / 名前は ≥3」が、page の主役（店名）で破れる。
     - Codex が気づけば revise になり、round を使う。気づかなければ、読めない page が accept されうる。
     - 語彙も「text = ≥4.5 on background and surface」としか言っておらず、primary / secondary を surface に合わせる指示が無い。
   - **提案（どれか、または組み合わせ）:**
     - (a) `checkProfile` に「primary on surface ≥3」「secondary on surface ≥4.5」を足す。基準は厳しくなる方向なので、品質基準の緩和には当たらない。SURFACE_DIRECTIONS の時だけに限ってもよいが、写真の label などを考えると全体にかける方が単純。
     - (b) surface のパネルの中の primary / secondary を `--p-text` に置き換える。
     - 語彙と test（全 SURFACE_DIRECTIONS で、パネル内の文字の computed color と、その地の contrast を測る）も足す。

2. **Medium — desktop の editorial_12 / asymmetric_7_5 で、japanese_modern と french_classic の見出しが行の高さまで伸びる。** japanese_modern では、見出しが行の下端に落ちる。（`.heading` は section の grid の中で `align-self: stretch` になっている）
   - **japanese_modern:**
     - `flex-direction: column-reverse` で、justify-content が既定の値なので、中身は下端に寄る。
     - 1440px の screenshot では、Visit の行（約 250px）の下端に「店舗のご案内 / VISIT」が置かれた。隣の住所と表は行の上端から始まる。
     - 縦の bar（`border-left: 6px`）も行の高さ全体まで伸びる。
     - Menu の行も同じ。2 行の tile より上の空きに bar だけが立つ。
   - **french_classic:**
     - 見出しの下の二重罫（`border-bottom: 3px double`）が、行の下端（Visit で見出しの文字から約 230px 下）に引かれる。罫が見出しから離れる。
   - **範囲:** editorial_12 は fixture の既定で、よく選ばれる grid。新 test の base（AMERICAN_EDITORIAL = editorial_12）でも起きているが、assert が無いため通っている。
   - **提案:**
     - `.canvas[data-direction="japanese_modern"] .heading, .canvas[data-direction="french_classic"] .heading { align-self: start; }`（column-reverse 側は `justify-content: flex-end` でも可）。
     - test に「desktop の grid で、見出しの文字の上端が隣の列の上端に近い」「見出しの罫と文字の距離」を足す。

3. **Medium — title に枠や padding を付けると内容幅が 26〜62px 狭くなるが、名前の字の大きさの下限（`clamp(2.6rem, …)`、split_crop は 3rem）はそのまま。そのため、空白で区切られた Latin の店名が語の途中で折れる場合が増える。**（`.title` の preset。`overflow-wrap: anywhere` が働くので、overflow にはならず、語が割れる）
   - **probe の結果（390px、fallback 書体）:**
     - american_editorial（枠なし）と比べて、kissaten・boutique・craft・french・editorial_luxury では次の折れが新たに起きた:
       - split_crop: 「Patisserie Mademoiselle Coquelicot」の「Coquelicot」、「Konditorei Schwarzwaldhaus」の「Konditorei」
       - centered_cover / stacked_oversized: 「BOULANGERIE PATISSERIE LUMIERE」の「BOULANGERIE」
     - これらはどの書体でも起きる。
     - 360px ではすべての direction で同じ件数で、もともと折れていた。つまり既存の問題が、390px でも出るようになった。
     - 日本語や空白の無い名前（`data-fit="phone"`）は cqi で縮むので、問題は無い。
   - **影響:** 1 枚目の主役で「COQUELICO / T」のような割れが起き、review の mobile_quality で減点されうる。事実は残る。
   - **提案:**
     - 枠のある direction では、下限も内容幅に比例させる（例: `max(2rem, …)`）。
     - または phone では title の左右の padding を小さくする（枠は保ったまま、8〜10px 程度）。
     - test: 長い空白区切りの Latin 名で、各語が 1 行に収まることを、全 direction × 360 / 390 で確かめる。

4. **Low — gallery_mono では accent が描かれないのに、accent の motif があると visible に数えられる。**（`visible-profile.ts`）

5. **Low — 地の模様が、小さい文字の contrast を保証の外へ押し出す。**

   - 例: 白地で secondary `#757575`（4.61）、primary `#1A1A1A` のとき、縞の上では 4.01 になる。

   - **提案:** 縞と点は、文字の行（folio・dek・lead）を避けるか、mix の率を、保証に余裕のある値まで下げる。または「模様の上の地の色」で contrast を確かめる test を足す。

6. **Low — japanese_modern の folio の帯の端の処理。**

     - 帯の margin では、100% = hero の内容幅 1320 → 56px

   - (d) 帯の上の label の区切り（accent on primary）には、contrast の保証が無い（装飾）。
   - **提案:**
     - 帯は `margin-inline` ではなく、hero 側の `::before` などの full-bleed の帯で描くか、`--pad` を px に解決した値を使う。
     - tight の padding に合わせて margin-top を変数にする。

7. **Low — japanese_modern の About の見出しが小さな label だけになる。**
