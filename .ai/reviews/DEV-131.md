## Findings

### M1 ページ全体の比較が原因コードに一切使われず、セクションの並び替え・移動を検出できない
- 場所: `lib/design-agent/impl-lane/compare.ts` L85（`page` の ssim/colour_blocks/edges_iou を計算）、L104-118（コード化は `height_ratio` のみ）。セクションは id で個別に切り出して比べるため、位置（y）・順序は比較されない。
- 再現（実 Chromium、DSF 1）: design = hero / menu / info、impl = info / menu / hero（全反転）→ `differences: []`。page SSIM は PC 0.512 / SP 0.465 と大きく下がっているのに、ループには `match` が返る。
- 影響: 受け入れ基準「ページ全体（SSIM・色ブロック・エッジ・高さ）を比較し、差を原因コードに」に反し、構成が崩れた実装でも修正ループが「差なし」で owner_review に進む（承認ではないので C/H ではないが、比較の目的を外す）。閾値が仮という前提でも、どの閾値でも出ない構造上の欠落。
- 修正: (a) `PC_PAGE_LAYOUT` 等のページ全体コード（SSIM/edges_iou の仮閾値）を追加、(b) design の順序（box.y の並び）と impl の順序を比較して `*_SECTION_ORDER` を出す、またはセクションの y 位置のずれを `*_SECTION_POSITION_<ID>` に。並び替えケースのテストを追加。

### M2 `SECTION_CROP_EMPTY` が原因コードにならず、黙って差なし扱いになる
- 場所: `compare.ts` L91-93（CROP_EMPTY を返す）、L112 `if (s.code) continue;`（MISSING 以外のコードは捨てられる）。
- 再現: impl のセクション box が画像外（例: `info` の box を y=99999 に。実ページでは off-canvas に追い出したセクション、または screenshot の高さ上限で切れたセクション）→ section は `SECTION_CROP_EMPTY`、`differences: []`。design 側で box が null（その幅で非表示）でも同じく CROP_EMPTY でセクション由来のコードは出ない。
- 影響: 実質「セクションが見えていない」実装が `SECTION_MISSING` を回避して match になる。fail-closed でない。
- 修正: CROP_EMPTY も `${p}_SECTION_CROP_EMPTY_<ID>`（または MISSING に統合）として `differences` に積む。design 側 null は「design ではこの幅で非表示」として impl 側が表示していれば `*_SECTION_EXTRA_<ID>`。テスト追加。

### L1 「大きい順の固定順」がループの `sort()` で失われる（文書と実挙動の不一致）
- `compare.ts` 冒頭・L45・L110 は「missing → page height → section の順」と書くが、`lib/design-agent/loop/controller.ts` L176 が `[...new Set(list)].sort()` して先頭を直すため、実際は辞書順（PC が常に先、`SP_PAGE_HEIGHT` が `SP_SECTION_MISSING_INFO` より先）。実験テスト L146 はこの結果（症状の `SP_PAGE_HEIGHT` を直すと全部直る mock）を期待値として固定している。修正: compare の文書から順序の主張を外すか、順位をコード名に符号化／ループ側の扱いを別タスクで決める。

### L2 `codePart` の衝突と黙った重複除去
- `compare.ts` L53: Artifact の SectionId（`^[a-z][a-z0-9_]{1,40}$`）は末尾 `_` と 41 文字を許すので、`hero` と `hero_`、先頭30文字が同じ長い id が同一コードになり、L121 の `Set` で1つに潰れる。compare 自体は id を検証しない（重複 id は最初の impl box を使う）。修正: 衝突を検出したら index 付与または `*_SECTION_ID_COLLISION` を出す。

### L3 単位と幅の前提を検査していない
- `Box` は PNG px として使われ（CSS px→device px の scale 無し）、`WIDTH_MISMATCH` は design と impl の PNG 幅の一致しか見ない（1440/390 との一致や DSF 1 は未確認）。Artifact schema は `device_scale_factor: 1` なので現状は成立するが、型コメントで「CSS px = PNG px（DSF 1）」を明記し、幅が viewport と一致しなければ `WIDTH_MISMATCH` にするのが安全。

### L4 compare.ts 自体の単体テストが無い
- `DECODE_FAILED` / `WIDTH_MISMATCH` / `SECTION_CROP_EMPTY` / `codePart` の分岐は実験テストからも通っていない（M2 はこれで見逃された）。合成 PNG での単体テストを追加。
