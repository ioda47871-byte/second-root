- **根拠:** オーナー指示（Issue コメント 6676754174）。real Codex の無人実行 ON・本番能力 ON・公開・費用は別承認。**この容器では real Codex も画像生成もしていない。**
- **土台:** `origin/develop` `5c2e9d8`（DEV-185、PR #227）。

## したこと

1. **job（固定 schema）:** `scripts/sales-design-worker/image-autorun.ts` の `ImageAutorunJobSchema`（zod strict）。`shop_id=tsugute`・`page=d1-v10`・`slot_ids` = 6枠そのもの・`brief_sha256` = pin・`approval_id`（`[a-z0-9-]`）・`approval_scope`・`requested_at`。プロンプトは pin 済み brief からだけ作り、job の文字列は shell にもプロンプトにも渡らない。
2. **hook:** `worker.ts` の `run()`、checkout 確認（HEAD = origin/<ref>・clean）の直後。run.sh の `run.lock` の中で、専用 lock（`image-autorun.lock`）、1回の実行で最大1件。queue は `<queue>/image-autorun/{inbox,processing,done,failed,held}`（Codex から見えない既存の queue root の下）。queue dir が無ければ何もしない。
3. **OFF・fail closed:** スイッチは root 所有の `/etc/sr-design-worker/image-autorun.json`（repo に無い、env で差し替え不可、jail の中から書けない）。無い・不正・root 以外・group/other 書込可・link・`enabled!==true` なら `HELD_AUTORUN_DISABLED`、sandbox も生成も呼ばない。拒否: `REFUSED_JOB_INVALID`・`REFUSED_LIMIT_EXCEEDED`（max_images>6・枠数>max_images・max_jobs≠1・期間>7日）・`REFUSED_DUPLICATE`・`REFUSED_APPROVAL_EXPIRED`・`REFUSED_APPROVAL_REUSED`（共有台帳 `poc-approval-used/<id>`、DEV-185 の消費済み ID）・`REFUSED_AFTER_FAILURE`（`STOPPED`）・`REFUSED_NO_APPROVAL`・`REFUSED_CONCURRENT`・`DEFERRED_TIME_BUDGET`（25分未満、承認は未使用）。processing の残りは `FAILED_INTERRUPTED`。
4. **通った後:** atomic mkdir で予約（以後再試行しない）→ `generateImagesInOneRun` 1回（最大6枚、15分）→ `writeTsugutePhotos`（job の承認 ID）→ `importTsuguteAiPhotos`（`ai_generated_demo`、その承認 ID だけ受理）→ `swapPage` + PC1440/SP390 描画。出力は `~/.local/share/second-root-design/image-autorun/<job_id>/`。失敗は `STOPPED` を書く。全判定を `audit.jsonl`（コード・ID・hash・path のみ）。
5. **DEV-185 への追加は任意引数だけ:** `writeTsugutePhotos({approvalId?})`、`importTsuguteAiPhotos({approvalIds?})`。既定は従来どおり。
