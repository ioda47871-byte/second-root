## 指摘

### High-1 寸法のない画像が潰れ、同じ骨格が「別の骨格」になる（写しの見逃し）

- 場所: `lib/design-agent/structure/measure.ts:213-221`（全リクエスト abort。`setContent` なので相対 URL は about:blank 基準で、読み込まれない）、`:160`、`:230`
- 失敗のシナリオ:
  - Phase 2f の Codex プロンプト（`lib/design-agent/phase2f/prompt.ts:127`）は `<img src="assets/A1.png" alt="...">` だけを指示しており、寸法の付け方は指定していない。
  - CSS が `width:100%;height:auto` のような内在寸法頼みだと、画像を読み込まないので img の高さは約 0 になる。
  - その結果、`isMedia` が偽になり、split / full_bleed / imagery が全部消える。
  - 成功例と同じ骨格の案でも、画像の CSS の書き方が違うだけで類似度は 0.37 まで下がり、`TOO_CLOSE_TO_REFERENCE` / `SIBLINGS_SAME_SKELETON` / `GENERIC_SKELETON` がどれも出ない。
  - ファイル冒頭のコメント「its box still counts」は、CSS で寸法が決まっている場合にしか成り立たない。
- 修正案（どちらか）:
  - (a) 既存の `render-prototype.ts` / `openCompPage` と同じく、ページ自身のファイル（`assets/*`、`style.css`）を `route.fulfill` で配る。それ以外は abort する。
  - (b) 画像の代わりに、宣言された寸法（または prototype の asset の実寸）を持つ同じ寸法の placeholder を配る。
- どちらの場合も、寸法なし img の fixture を回帰テストに加える。

### High-2 宣言に頼る3側面が合わないと、閾値に届かない

- 場所: `lib/design-agent/structure/descriptor.ts:55`（WEIGHTS）、`:73-90`、`:93`、`measure.ts:278-287`
- 失敗のシナリオ:
  - hero・flow・reading_path の重みは合計 0.45。
  - hero と flow が幾何で測れるのは汎用の形（split・中央寄せ・stacked_bands）のときだけで、reading_path は測らない。
  - したがって、成功例（独自の骨格）を写した案では、この3側面は宣言だけで決まる。
  - 宣言がない、または違う語を宣言しただけで、測った5側面がすべて一致しても類似度は 0.55 が上限になる。これは `siblings_same_skeleton` 0.6 と `too_close_to_reference` 0.75 の両方に届かない。プローブで確認した。
  - 宣言は案の側（Codex）が書くものなので、写した側が検査を外せる。
  - テストは両方に同じ `reading_path` を宣言しているので、このことが表に出ない。
- 修正案:
  - 測った側面だけの類似度を別に出し、それにも閾値を持たせる。または、両側で既知の側面の重みで正規化する。
  - 加えて、宣言と実測が食い違うときや、宣言だけで差が出たときは、所見（例: `DECLARED_ONLY_DIFFERENCE`）として残す。
  - 「不明な側面は一致に数えない」の方針は保ったまま、「宣言だけの差で一致を消さない」ようにする。
  - 回帰テストとして、独自骨格の同一ページを宣言なし・異なる宣言で比べたときに所見が出ることを固定する。

### Medium-1 ブロックを section 直下の1段でしか見ないため、見出しの下の grid / split を取り逃がす

- 修正案: 子が複数でも、面積の大半を占める1つの子（例: 面積が 50% 以上、または見出し以外で最大のもの）へ降りる。または、子孫の中で横に並ぶ兄弟の行を探す。

### Medium-2 隔離テストが lib/design-agent の中からの相対 import を見逃す

### Medium-3 section 自身の背景画像を数えない

### Low-1 `</head>` がない HTML では CSS がエスケープされない

- 場所: `measure.ts:220`（else 側の `` `<style>${page.css}</style>${html}` ``）
- 失敗のシナリオ: CSS の `</style>` から抜け出して、任意の要素を注入できる。JS は無効でリクエストも abort されるので、影響は測定結果の改ざんにとどまる。
- 修正案: else 側でも、同じ `replace(/<\/style/gi, "<\\/style")` を使う。

### Low-2 DOM clobbering で測定が落ちる、または黙って欠ける

- 場所: `measure.ts:156-210`
- 失敗のシナリオ:
  - 測定スクリプトは main world で実行され、`document.querySelectorAll` と `document.body` を直接使う。
  - Document には `[LegacyOverrideBuiltIns]` があるので、`<form name="querySelectorAll">` で TypeError になる。
  - `<img name="body">` の場合は例外が出ず、chars=0 になり、text_direction が null になる。
- 修正案: `Document.prototype.querySelectorAll.call(document, …)` や `document.documentElement` 経由の取得に替える。または、測定前に name 属性の衝突を検出して失敗扱いにする。

### Low-3 空の列が完全一致として数えられる

- 場所: `descriptor.ts:67`、`:70`、`:84-86`
- 失敗のシナリオ:
  - section が1つのページどうしは、edges が両方 `[]` なので layout_sequence が 1 になり、+0.1 が無条件に入る。
  - 宣言した `section_layouts: { value: [] }`（スキーマで許されている）は +0.3 になる。
  - これは「不明は一致に数えない」の方針に反する。
- 修正案: 両側とも空なら 0 にする（または null 扱いにする）。`many()` に `.min(1)` を付ける。

### Low-4 測定は遮断したリクエスト数を返さない

- 場所: `measure.ts:216`
- 内容: `openCompPage` は `blocked` を数えて呼び出し側の安全停止に使っているが、こちらは黙って abort する。外部資源を参照する prototype でも気づけない。
- 修正案: 件数を `PageMeasure` に含める。

### Low-5 幾何の細部

- 同じ背景の section の間を margin で空けると `hard_cut` になる（`measure.ts:264-268`、許容幅 2px）。
- 縦書きの見出しと長い横書きの本文が混ざるページは、文字数比で `horizontal` になる（`:290`）。
- どちらも仮語彙の範囲では許容できる。語彙と閾値を確定する前に、実際の prototype で較正することを勧める。

## 確認した点（問題なし）

- **安全**
  - `newContext({ javaScriptEnabled:false, serviceWorkers:"block" })` と `route("**/*", abort)` を使っている。
  - `setContent` は about:blank 上で動くので、相対 URL ではリクエスト自体が発生しない。
  - ファイル書き込み、子プロセス、モデル呼び出しはない。context は `finally` で閉じている。
  - stylesheet link の除去は、外し損ねても abort されるだけなので安全側。
  - `</head>` がある場合は、`</style` のエスケープで抜け出せないことをプローブで確認した。
- **語彙とスキーマ**
  - `z.strictObject` と enum で、語彙外の値を拒否する。
  - 不明な側面は null で、類似度は 0 として扱い、`ASPECTS_UNKNOWN` として報告する。
  - 実測が宣言より優先されることもテストで固定されている。
- **正直さ**: コメントと所見コードはどれも「構造パターンが見つかったか」だけを述べ、デザインの良し悪しを主張していない。
- **スコープ**

  - 生成器・worker・workflow・package.json への変更はない。
  - 規模（実装約 290 行）は過剰ではない。
- **タスク記録**: `.ai/tasks.json` の DEV-125 は status `review` で、human_approval_triggers（マージ、語彙と閾値の確定）が明記されている。`ai-tasks.test.ts` は通過した。
