## ゲートと上限の再確認（自前の probe で確認した）
- 有料の design は、`decision === "approved"` のときだけ呼ばれ、ループの外で 1 回だけ呼ばれる。`"APPROVED"`・`true`・`"yes"`・`toString` が `"approved"` を返すオブジェクトは `awaiting_approval` になり、design は 0 回。`denied` は `stopped` になる。approval が例外を投げた場合は `PORT_THREW` で、design は 0 回。
- 回数の上限: implement は最大 3 回（初回 + 修正 2 回）。同じ原因の修正は最大 2 回。`[A]×3` は `fix:A:1, fix:A:2` のあと `SAME_CAUSE_FIX_LIMIT`。毎回新しい原因が出る場合は 3 回で `RETRY_BUDGET_EXHAUSTED`。`[A,B]/[A,B]/[A]` は SAME_CAUSE。重複は除かれる。AI_WORKFLOW の「3 回」と、autonomy の「同じ問題は 2 案まで」に合っている。
- identity は `PASS_IDENTITY_ONLY` 以外、package は `render_pair_complete` 以外（大文字の `RENDER_PAIR_COMPLETE` も）で止まる。stopClass が不明・未定義の場合は owner に回る（止まる方向）。
- 新しく fail-open になったものはない。ただし以前からある ID の検証の抜け（M1）が、新しく足したヘッダの約束（「every gate is "expected value or stop"」）と食い違っている。
