# DEV-035 review

## Cause

- On CI, DEV-033's browser diagnose test (`li_auth_platform`, mode C) hung now and then (see `.ai/reviews/DEV-034.md`, where the bounded steps named it).
- In C (no interception), a refused move closed the page inside the `request` handler while its navigation was in flight. The run then awaited `page.close()` and `context.close()`. Under load, one of those closes sometimes never settled.

## Change

- `refuse()` only records why the run stops and wakes the run (a signal re-armed for each page).
- The run stops at once, whether it is loading, sampling or waiting for the home page. It closes the page itself, once, without waiting for the refused navigation.
- `page.close()` and `context.close()` are bounded (10 s). A context that does not close is ended through CDP `Browser.close` and `browser.close()`. A browser that does not answer at all is killed by Playwright's own close.
- New fixed codes: `CLOSE_TIMEOUT` (the run was cut short by a close that did not finish) and `BROWSER_STUCK` (the end of the browser was not confirmed).
- The tracked jail probe `.pyc` is removed, and Python caches are ignored.
- Unchanged: the Navigation Guard allow range, challenge / login-wall handling, cookies / session, the jail, and the helper's permissions.
