# DEV-169 Review — 段 B の 1px 掃引の「測っていない幅」の配線をテストで固定する

- **範囲:** `tests/unit/design-agent/comp-impl/phase-b.test.ts` (テスト1本)、`docs/design/phase-b-design.md` §8 (1行)、`.ai/`
- **触れていないもの:** `lib/**` (本番のコードの差は 0)、`page-css.ts`・`spec.ts` の許可一覧、`APPROVED_CAPABILITIES` (空のまま)、run.ts・worker の道、依存、`.github/workflows`

## 何をしたか

PR #207 の残りの Low (L1): `render.ts` の `displaySweepPass` の `failing.push(...unmeasuredWidths(runs, lo, hi));` を消しても全テストが通った
(純粋な関数 `unmeasuredWidths` だけがテストされていた)。

`mediaSegments` は 320〜1920 で段を切るので、`range: [1916, 1923]` で掃引を呼ぶと 1921〜1923 はどの実行も測らない。
既存のテストと同じく、テストから `displaySweepPass` に `range` と `forceReal` を直接渡す (本番は渡さない)。新しい口は足していない。

テストが確かめること:

- 根の幅を動かす測り方 (`forceReal: false`) と実際の幅の変更 (`forceReal: true`) の両方で、`failing` がちょうど 1921・1922・1923 の `PHASE_B_UNMEASURED` だけ
- それが `phaseBCheck` を落とすこと
- 同じページを段が届く `[1916, 1920]` で掃くと `failing` が空 (ページ自体はどの幅でも通る。落ちるのは配線のせいだけ)

## 変異の証明

その行を一時的に消して走らせると、新しいテストだけが落ちた (`expected [] to deeply equal [ { w: 1921, … }, … ]`)。戻して緑。

## 既知の限界

- 測っていない幅を作る道は「1920 を越える range」だけを使う。掃引の script が少なく数えた場合の数え方は、既存の `unmeasuredWidths` の純粋なテストが受け持つ。
