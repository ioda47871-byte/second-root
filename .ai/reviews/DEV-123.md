## 指摘

### Low-1 `_behavior` / `-ms-behavior` が `behavior` の規則から外れた

- 場所: `lib/design-agent/phase2f/prototype-safety.ts:82` と `:94`
- シナリオ:
  - lookbehind `(?<![\w-])` は、`_`（IE6 のハック。`\w` に含まれる）と `-`（IE8 の `-ms-behavior`）も除外する。
  - そのため、`_behavior:none` や `\5f behavior:url(#x)` が通る。
  - Chromium では無効なので実害はない。ただ、「実際の safety を弱めない」というオーナー条件からみると、規則の意味が名目上狭まっている。
- 修正案: `(?<!scroll-)behavior\s*:` にする。
  - `scroll-behavior` と `overscroll-behavior` はどちらも `scroll-` で終わるので、これで両方を除外できる。
  - `_behavior` / `-ms-behavior` / `*behavior` は従来どおり拒否される。
  - テストの `it.each` に `_behavior` と `-ms-behavior` を1行ずつ足す。

### Low-2 先頭の Unicode 空白で、fragment ではない相対 URL が fragment として通る（既存）

- 場所: `prototype-safety.ts:163`（`a.value.trim()`）と `:166`
- シナリオ:
  - `trim()` は U+3000 などを取り除くが、URL パーサーが取り除くのは C0 と空白だけである。
  - そのため、`href="　#x"` は `…/%E3%80%80#x`（同一オリジンの相対パス）へ解決される。
  - クリックしないと遷移しない。JS は無効、ネットワークは遮断されている。develop でも同じだった。
- 修正案: trim は ASCII の空白（`[\t\n\f\r ]`）だけにする。任意で、別 Task にしてよい。

### Low-3 `--prerender` で `detail` が出ない

- 場所: `scripts/design-artifact/phase2f-steps.ts:85`、`runner.ts:249` の戻り型
- シナリオ:
  - 実行時の値には `detail` が入っている。しかし `prerenderRoute` の宣言型には無く、CLI も出力しない。
  - そのため、pre-render で止まったときは、どの規則で止まったかが分からない。
- 修正案: 戻り型に `detail?: string` を足し、CLI の出力に `...(pre.detail ? { detail: pre.detail } : {})` を加える。`scripts/` は allowed_scope の外なので、別 Task でもよい。

### Low-4 fragment の空白の拒否をテストで固定していない

- 場所: `tests/unit/design-agent/phase2f/parts.test.ts:128`
- シナリオ: 正規表現を `^#` に緩めても、テストは落ちない。
- 修正案: `#\nhttps://example.com` が拒否されることを1行で足す。
