What the reviewer confirmed:

- No function ever returns a run to `running`.

Low findings and what was done:
1. `ingest-api.test.ts`: the new describe is nested inside "run lifecycle through the API". This is cosmetic and matches the existing "one run per day" block, so it stays as is.
2. A run abandoned mid-way blocks new runs for up to 24h. RUN_PROMPT's 409 row and STAGING §7 #7 now say it becomes `failed` automatically after 24h without a checkpoint, or a human can `abort` it by runId.
3. If an environment already had 2 running runs that were not stale, index creation would fail and roll back. That is fail-closed and documented in the migration header, and Staging has 0 running runs. No change.
