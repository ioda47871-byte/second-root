# DEV-070 generated_concept（イメージ画像）の経路の削除

Branch: `feature/dev-070-remove-generated-concept`（develop 46e50a4 から）。人の決定（2026-10-20、正式承認、`.ai/proposals/design-agent-direction-2026-10-20.md` §8.4）:
「generated_concept は、使われていない・依存が無いことを確かめて画像生成経路を削除する。AI 生成の架空の店舗写真は使わない。Instagram 画像は取得・分析とサイトへの再掲載を区別し、利用許可なしに公開しない。」

## 確認（削除の前に。読み取りだけ）

### 1. 公開の経路から generated_concept は描かれない

- `lib/design-agent/assets/manifest.ts`: `PUBLIC_DEMO_ASSETS_ENABLED = false`。`assetUsableIn(asset, "public_demo")` は常に false。generated_concept の `consentAllows` は `local_preview` だけだった。
- 公開 `/demo/[publicToken]`（`app/demo/[publicToken]/page.tsx`）と管理画面のプレビュー（`app/admin/preview/[prospectId]/page.tsx`）は `renderDesignedDemo(demo, profile)`（`components/demo/renderDemo.tsx`）を使い、`ProfileRenderer` に `photos` を渡さない。写真を描けるのは local の `/design-preview/[runId]`（page と `asset/[assetId]` route）だけで、どちらも `SR_DESIGN_PREVIEW_ROOT` が無ければ 404（Vercel では設定しない）。
- 写真の bytes が頁に届く唯一の経路は `readPreviewAsset`（`lib/design-agent/assets/serve.ts`）→ `readVerifiedAsset(..., "local_preview")`。asset store はリポジトリの外（`$HOME/.local/share/second-root-design-assets` または `SR_DESIGN_ASSETS_ROOT`）。

### 2. DB・migration に保存されていない

- `supabase/migrations/`（21 files）に `source_kind`・`generated`・`concept`・`asset`・`photo`・`image` の語は無い（grep 0 件）。manifest は WSL 上の file だけで、DB の列・migration は無い。

### 3. Vercel 側のコードは依存していない

- Vercel で動くコードのうち design-agent を import するのは `lib/sales/design.ts`・`design-bridge.ts`・`design-bridge-schema.ts`・`demo-data.ts`・`lib/admin/today.ts`・`components/demo/renderDemo.tsx` で、使うのは `DesignProfile`（`profile.ts`）と `ReviewSummary` だけ。`photo`・`asset`・`image` の参照は無い（`app/api/internal/sales-design/jobs/route.ts` と `lib/design-agent/bridge/` も同じ）。bridge は写真・画像を運ばない。
- `generated_concept`・`イメージ画像`・`imageLabel`・`human_upload` を参照していたのは、`lib/design-agent/assets/`（manifest・types・intake・render-check）、`lib/design-agent/page-scripts.ts`、`lib/design-agent/worker/`（poc.ts・preview-check.ts）、`components/demo/profile/`（ラベルと CSS）、`scripts/sales-design-assets/assets.ts`、`scripts/sales-design-worker/photo-poc.sh`、test、docs だけ。どれも local preview / worker / 人が動かす CLI の側。

### 4. 画像生成のコードは無い

- `dall-e`・`gpt-image`・`images.generate`・`images/generations`・`image_generation`・`stable diffusion`・`midjourney`・`replicate`・`txt2img`・`generateImage` を node_modules 以外で grep: コードに 0 件。`openai` の出現は、Codex CLI の子 process から `OPENAI_API_KEY` などを外す処理（`lib/design-agent/codex.ts`・`worker/env.ts`）、secret scan の pattern、test、`supabase/config.toml` の既定の注記だけ。`package.json` の依存に画像生成の SDK は無い。
- `sharp` を使うのは `scripts/generate-icons.mjs`・`generate-ogp.mjs`・`optimize-brand-photos.mjs`・`crop-gallery-sources.mjs`・`optimize-screenshots.mjs` だけ（Second Root 自身のサイトの icon・OGP の生成、実写真の crop・再 encode。`package.json` には無く next の依存経由）。design agent・demo とは関係なく、店舗写真を作らない。
- 画素を描くコードは test の fixture（`tests/unit/design-agent/photo-fixtures.ts` の `fakePng`: gradient と円）と `lib/design-agent/worker/preview-check.ts` の `drawPng`（同じ種類の fixture、一時 store で終了時に消す）だけ。
- `docs/operations/design-agent-wsl.md` の `kaii-imagegen` は、人の PC にいる別の Linux 利用者の名前（worker の group に入れない、という注意）で、このリポジトリのコードではない。
- 結論: 「画像生成経路」はリポジトリの中には無く、generated_concept は「人が別に作った画像（実機の PoC 001〜005 では AI 生成の concept 画像）を `human_upload` として入れる」入口と、その表示（ラベル）・検査・PoC の道具だった。

### 5. 実際の使用

- 使ったのは WSL の実機の写真 PoC（poc-photo-001・003・004・005、`.ai/reviews/DEV-029.md`）だけで、すべて local preview。公開 demo・Staging・Production には出ていない。その asset が WSL の asset store に残っている可能性がある → `.ai/blockers.md` HUMAN-016（任意の人の操作。Claude は WSL に触れない）。

以上から、未使用（公開・保存の経路なし）・依存なしと判断し、削除した。

## 変更

- `manifest.ts`: `SOURCE_KINDS = ["approved_real"]`。`GeneratedConceptSchema` を削除し、`AssetRecordSchema = ApprovedRealSchema`。他の種類は parse できない。
- `intake.ts`: `IntakeSource` は approved_real だけ。実行時にも他の種類を `SOURCE_KIND` で拒否（何も読まず書かない）。古い manifest（generated_concept を含む）は `MANIFEST_INVALID` で何も足さない。`loadManifest` は null（= 写真なし）。
- 古い manifest の扱い: worker の `jobPhotos` は manifest が null なら写真なしで進む（既存の挙動、失敗しない）。preview・asset route も null（写真なし・404）。PoC の preflight は `MANIFEST_INVALID`。
- 「イメージ画像」ラベル（`ProfileRenderer.tsx`）と `.imageLabel`（`profile.module.css`）を削除。写真の上には何も描かない。
- `render-check.ts`・`page-scripts.ts`: `labelled` と label 判定を削除。配置（directed と一致・両 device・重複なし）・可視・同意（`assetUsableIn(local_preview)`）・文字との重なりの検査はそのまま。
- `scripts/sales-design-assets/assets.ts`: `--source generated_concept` を削除（usage を表示して exit 2）。
- 写真 PoC: `poc.ts` の preflight は `generated_concept_only` の代わりに `approved_for_local_preview`（全写真が approved_real で同意が local_preview を含む。満たさなければ `NOT_APPROVED_FOR_LOCAL_PREVIEW`）。`photo-poc.sh` は `--consent-id`・`--approved-by`・`--approved-at` と `--human-approval-confirmed`（無ければ何も始めずに止まる）を取り、scope は `local_preview` だけで intake する。既定の ref は `develop`（DEV-029 の branch には generated_concept が残っているため）。
- `preview-check.ts` の fixture（描いた gradient）は approved_real・`local_preview`（一時 store）として記録。
- docs: `docs/operations/design-photo-poc.md`（approved_real と写真ごとの承認）、`docs/MVP_SPEC.md` §7（Instagram の取得・分析と再掲載の区別、AI 生成写真を使わない）、`docs/SECURITY.md` §6・§11、提案書の実装メモ、`.ai/tasks.json`（DEV-070、DEV-029 に注記）、`.ai/blockers.md` HUMAN-016、`.ai/progress.md`。
