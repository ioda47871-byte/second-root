### M-1（Medium）`--image` を渡さなければ、実際に行った C の画像呼び出しを「実行していない」として Artifact にできる

- 場所: `scripts/design-artifact/phase2f-steps.ts:159-166`（`if (!image) return { … image_outcome: "TOOL_NOT_CALLED", stop_code: "IMAGE_NOT_RUN", approval_id: null }`）
- 場面:
  - C の画像を承認して呼び出し、失敗したとする。例えば `TOOL_FAILED_POLICY`（ポリシーによる拒否）で、画像は主役ではない。
  - このあと `--package --route C` を `--image` なしで実行する。
  - 台帳はこの呼び出しを確認しない。そのため結果は「承認されなかった」扱いになる（`IMAGE_NOT_RUN` / `TOOL_NOT_CALLED`、`approval_id: null`）。そのまま B へ明示的に切り替わり、`done` になる。
  - 本来は `IMAGE_POLICY_REFUSAL` で、オーナー確認のために止まるはずである。
  - 比較シートの「実際の呼び出し」にも、この画像の呼び出しは出ない。
  - 成功にはならない。ただし「ポリシー拒否は止まる」「シートは実際の呼び出しを正確に示す」という条件を、渡し方ひとつで満たさなくなる。
- 修正案:
  - `--image` が無いときは `ledger.calls(step.receipt.plan_id)` を調べる。`route: C_hybrid`、`kind: image`、`prompt_sha256 === req.promptSha256`（組み立て直した指示文）の受け取りが1件でもあれば、`IMAGE_RUN_RECORDED`（`--image` が必要）で止める。
  - テストを足す。失敗した画像の呼び出しがあるのに `--image` を省いた場合に止まること。

### M-2（Medium）画像の入口に、PoC の古い状態の掃除が無い。強制終了すると後片付けもされない

- 場所:
  - `lib/design-agent/design-image/image-once.ts:85-96`（掃除の処理が無い）
  - `scripts/design-artifact/phase2f-live-cli.ts:74-85`（2回目の合図か 20 秒後に `process.exit(1)` する。`finally` は動かない）
  - PoC 側: `lib/design-agent/design-image/run.ts:309-316, 603`（`removeStaleDesignAgentState`）。PoC は合図を受けると `activeCleanups` を実行する。
- 場面:
  - 画像の呼び出し中に SIGTERM を2回送るか、中止が 20 秒以内に終わらなかったとする。
  - その場合、`~/.codex/generated_images/<thread>/` と、指示文やモデルの返答を含むセッションログが残る。
  - PoC は、次に実行するときに `removeStaleDesignAgentState` でこれらを消す。image-once にはこの処理が無い。さらに、次の呼び出しは開始前の一覧（`before`）にその画像フォルダーを含めるので、それを消さない。
  - 結果として、PoC か worker が次に動くまで残り続ける。worker が消すのはセッションログだけである。
  - 成功の判定には影響しない（`takeImage` が読むのは自分のスレッドのフォルダーだけ）。ただし、依頼された「PoC と同じ後片付けの安全性」から一つ欠けている。
- 修正案:
  - 次の処理を image-once の `before` を取る前に入れる。`codex.ts` が公開している `listDesignAgentSessions` / `removeStaleCodexSessions` で、PoC と同じ処理ができる。
    - 古い design-agent のセッションのスレッドの画像フォルダーを消す。
    - そのあと `removeStaleCodexSessions` を実行する。
  - 強制終了の前に、実行中の image-once の後片付けを待つ形にする（PoC の `activeCleanups` と同じ）。

## Review 1 への対応（実装者）

Review 1 は PASS（Critical 0／High 0、Medium 3・Low 8）。Medium 3件と、Low の大半を直した。

- **M-1:** `--image` が無いときも台帳を見る。同じ計画に、組み立て直した指示文の SHA と同じ C の画像の呼び出しがあれば止める（`IMAGE_RUN_NOT_GIVEN`）。テストを追加した。既存のテストで「主役の画像を実行したのに渡さない」場合も、この停止になる。

- **M-3:** 3件の検査にテストを足した（`DESIGN_RUN_NOT_SUCCEEDED`、`IMAGE_REQUEST_OTHER_PLAN`、`CODEX_IMAGE_ABORTED`）。
- **L-1:** 画像の結果が記録されていない失敗は、画像ツールの前の停止（サインイン・jail・.env・出力先）だけを `TOOL_NOT_CALLED` とし、それ以外は結果不明として止める（テストあり）。
- **L-3:** 画像が無く CLI の言葉が利用上限なら `CODEX_QUOTA`（PoC と同じ。テストあり）。
- **L-4:** A の Artifact 化は `--expected-prompt-sha256` を必須にし、記録と照合する（テストあり）。
