## Verdict: FAIL

Counts: Critical 0 / High 1 / Medium 1 / Low 5

The adapter fails closed on every unsafe path I tried. No path sets a sendable flag, and none sends anything. It does not loosen the copy audit, facts or rights gates, and it does not touch Protected Scope. But its success path cannot complete for any comp whose directory follows the existing naming convention (the directory name is the direction id), because the staged copy is renamed. The mock-only tests cannot see this.

## What I checked against the real CLIs

- Argument contracts: `comp-copy.ts --audit <dir> --facts`, `comp-lane.ts --dir/--facts/--out`, `comp-lane.ts --check-review <dir> --facts`, `package-local.ts --out --copy --facts`. All four match the CLIs' own parsers.
- Output shapes: the copy gate prints `{step, mayShowOwner, codes}`, exit 0 only at owner_review. Render prints `{status:"OK"|"FAIL"}`. Check-review prints `{ok, codes}`. Package prints `{status:"OK", format:"sales_demo_version_package_v2", bundle_sha256}` when `--copy` is given. These match what `stepCode` expects. Exit 2 with empty stdout becomes `STEP_INVALID_OUTPUT` (fail closed).
- Real run, Chromium included, on a copy of the committed fictional `poc/sendable-tamaki` page + facts, output in the scratchpad. copy=ok (owner_review), render=ok, visual stopped (no review.json, so `STEP_INVALID_OUTPUT`). Exit 1, no package.
- Real copy + real package with render/visual stubbed: `package_prepared_owner_review_required`, a v2 package written outside the repo, bundle SHA recorded.
- `--out` inside the repo: `OUTPUT_IN_REPO`, exit 2, nothing created.
- Stop paths: HOLD/REVISE/FAIL/refused copy, revise/drop review verdicts, a missing review, a facts SHA or shop_id mismatch, symlinks, unexpected files (photos), an existing output, and changed inputs all stop. `sendable` never appears. No network, DB, Supabase, Codex or image calls: the children render offline with the network blocked, and package-local runs only `git rev-parse` locally. `spawnSync` is called with `shell:false` and fixed repo script paths. User strings are passed only as argv elements.

## Findings

### H1: The staged comp is renamed to `comp`, so every real `show_owner` review is refused as `REVIEW_OF_ANOTHER_DIRECTION`
- `scripts/sales/demo-version/prepare-offline.mjs:123` (`const staged = join(out, "comp")`), used at `:149-152`. The check is in `scripts/design-artifact/comp-lane.ts:108` (`directionId: basename(resolve(dir))`) and `lib/design-agent/quality-pipeline/comp-review.ts:72`.
- Scenario: the comp's directory is named for its direction, as every committed comp is (for example `d1-seam-across-v8-info-route`), and its `review.json` holds that `direction_id`. The adapter stages it as `<out>/comp`. Both the render step (structural `REVIEW_*` findings, which become `RENDER_GATE_STOP`) and `--check-review` (`VISUAL_REVIEW_STOP`) then refuse it. Reproduced without a browser: `--check-review` on the committed comp gives `["SHOW_WITHOUT_COPY_REVIEW","COPY_FACTS_PACK_REQUIRED"]`, and on a byte-identical copy at `<tmp>/comp` it gives `["REVIEW_OF_ANOTHER_DIRECTION", ...]`. The success path works only if the direction is literally named `comp`, as in the doc example. That cannot hold for two or more directions per shop.
- The failure mode is fail-closed (no unsafe output), but the PR's main deliverable does not work, and the doc implies it does.
- Fix: stage to `join(out, "comp", basename(comp))`, or `join(out, basename(comp))` with the basename checked against the existing direction-id rules and `.`/`..` refused. Then add a test that runs the real `comp-lane.ts --check-review` (no browser needed) on the staged path.

### M1: The tests only check the adapter against its own mocks, and several stop paths are untested
- `tests/node/sales-demo-prep.test.mjs` (all 9 tests inject `runStep`). `tests/unit/sales/offline-demo-prep.test.ts` only wraps them.
- Scenario: H1 got through with 9/9 green because no test runs a real CLI. Untested: the render-step stop, package-step stop (including a wrong `format`), `STEP_INVALID_OUTPUT`/timeout, a comp file (not facts) changed mid-run, `OUTPUT_IN_REPO`, `INPUT_SYMLINK_PARENT`, `COPY_ROUNDS_MALFORMED`, and copy `revise`/`fail`/`refused` mapping. The browser-free steps (`comp-copy.ts --audit` and `comp-lane.ts --check-review`) could run for real in CI against a fictional fixture.
- Fix: add a contract test that runs the real copy audit and check-review on a fictional comp with a schema-valid review (or asserts the exact refusal codes), plus table tests for each stop code above.
- Note: the wrapper is under `tests/unit/**`, which `vitest.config` includes and `ci.yml` runs (it is not excluded), so the node:test file does run in CI.

### L1: An `--out` inside the comp directory writes into the original comp
- `prepare-offline.mjs:65-71`, `:103`.
- Scenario: `--comp X --out X/run1` succeeds and writes the staged copy, status and package inside the private original comp, despite the doc's "元のカンプへ書き込まず". Every later run then stops with `COMP_UNEXPECTED_FILE`. Reproduced.
- Fix: refuse an `out` inside `comp` or inside the facts file's directory tree (and the reverse), using real paths.

### L2: Stop reasons are discarded
- `prepare-offline.mjs:75-81`, `:160-163`.
- Scenario: child stderr and the exit code are dropped. A missing `review.json` is reported as `STEP_INVALID_OUTPUT`, not as a missing review. Render and package failures record only `RENDER_GATE_STOP`/`PACKAGE_STOP` without the finding codes, so an operator cannot tell why a run stopped without re-running each CLI by hand.
- Fix: record the exit code and a sanitized code list (`findings[].code` / `codes` / `code`, capped, no detail text) for every step. Map exit 2 with an `INPUT_ERROR` stderr to `STEP_INPUT_ERROR`.

### L3: The children read the original facts file between the hash checks
- `prepare-offline.mjs:149-152` pass `facts` (the original path), and `checkUnchanged` runs only before and after each step.
- Scenario: a change to the facts file during a step that is reverted before the step ends goes undetected. The staged comp is also never re-hashed after the copy step, so later steps trust it.
- Fix: copy the facts into `<out>/facts-pack.json` (0600), verify its SHA, and pass that path to all four steps. Record the staged comp hashes after the copy audit and check them before render, visual and package.

### L4: `renders_match_here` from the render step is ignored
- `prepare-offline.mjs:85`.
- Scenario: the existing comp-lane rule reports a render mismatch instead of failing on it (fonts differ between machines). The adapter keeps that rule but does not record that the visual review was made on different renders from the ones packaged, so the owner can be shown renders the reviewer never saw. This does not loosen any gate.
- Fix: copy `review.renders_match_here` into the render step entry in `status.json`.

### L5: Partial outputs and timeout cleanup
- `prepare-offline.mjs:122-129`, `:76`.
- Scenario: if `mkdirSync`/`cpSync` fails after `out` is created, a partial run directory is left without `status.json`. On the 180 s timeout, the Node child gets SIGTERM, but its Chromium child may outlive it.
- Fix: write `status.json` before staging (or wrap staging in a try that records `STAGING_FAILED`), and document that a timed-out run may leave a browser process.

## Findings (round 2)

### L6: New files added to the original comp or facts directory during a step are not detected
- `scripts/sales/demo-version/prepare-offline.mjs:232-235`: `checkUnchanged` re-hashes only the originally listed comp files and the facts file.
- Scenario: a step that creates `<comp>/added-by-step.txt` (or a file next to the facts file, or an extra file in `out/input/`) still ends `package_prepared_owner_review_required`. Reproduced with an injected step. Later runs of that comp then stop with `COMP_UNEXPECTED_FILE`. Steps no longer receive the original paths, so only a misbehaving repo script could do this. The doc's sentence that the guarantee is "検出" is slightly broader than what the code does.
- Fix: snapshot the original comp tree with the existing `snapshot()` and compare full trees, as is done for the staged comp. Optionally also snapshot `out/input`.

### L7: The test wrapper timeout (140 s) is shorter than the default step timeout (180 s)
- `tests/unit/sales/offline-demo-prep.test.ts:9` vs `prepare-offline.mjs:37`. The real-CLI tests call `runRepoStep`/`prepareOffline` without `timeoutMs`.
- Scenario: if a real CLI hung in CI, the wrapper would SIGTERM `node --test` at 140 s. The test fails correctly, but the detached supervised step group can survive until its own 180 s timer fires. That is bounded, but it holds a CI process for up to 40 s more.
- Fix: pass `{ timeoutMs: 60_000 }` in the real-CLI tests (making `prepareOffline` accept a step timeout), or keep every step timeout below the wrapper's.

### Note (no finding)
`DIRECTION_NAME` accepts names the review schema cannot match: generic `comp`, or more than 60 characters (`comp-review.ts` limits `direction_id` to 60). These stay fail-closed at render/visual, and the doc warns about generic names.
