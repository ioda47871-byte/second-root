## Findings

### Critical 1: 位置指定した要素の `box-shadow` が後ろの事実を塗りつぶす

```css
#shop-css dl > div { padding: 0; margin: 0; line-height: 1; }
#shop-css dl > div:nth-child(3) { position: relative; z-index: 1;
  box-shadow: 0 16px 0 16px var(--p-bg), 0 16px 0 16px var(--p-bg); }
```

- 結果: guard OK、render **PASS（accepted）**。
- 360px の screenshot では、電話番号 `052-000-0000` と「Tel 電話」の行がほぼ完全に地の色で消えている。
- 弱い版（`#shop-css li:first-child { position: relative; box-shadow: 0 16px 0 16px var(--p-bg); }`）でも、menu の「テストスコーン」の上半分が消えて PASS した。

なぜ素通りするか:
- 位置指定（と transform）の要素は、通常の流れの兄弟の文字より後に塗られる。
- shadow は hit-test に出ないので、`elementFromPoint` は事実自身を返し、`fact_covered` が立たない。
- contrast の screenshot では、事実の文字の下の「地」が shadow の色になる。文字色との contrast は十分あるので、`fact_contrast` も立たない。

修正案（どちらか、または両方）:
- (a) 要素の `box-shadow` を `inset` だけにする。inset は内容より下に塗られる。
- (b) 位置指定・transform・z-index を使った要素には `box-shadow` と `outline` を禁じる。

render check 側の追加案: 事実の text を残したままの screenshot と、text を透明にした screenshot の差分を取る。行の box の中で文字の画素が実際に出ているかを確かめる（「描かれた文字が baseline と同程度に見える」の検査）。

### Critical 2: footer の注記を `box-shadow` で消せる（notice / footer の検査をすり抜ける）

```css
#shop-css main { position: relative; z-index: 1; padding-bottom: 0; margin-bottom: 0;
  box-shadow: 0 16px 0 16px #761D27; }
```

- 結果: guard OK、render **PASS**。
- 360px で、footer の 1 行目「このページは、EXAMPLE TEST様に向けて Second Root が公」が消える。
- canvas は `isolation: isolate` なので z 0 の層として非位置指定の footer より後に塗られ、その中の shadow が footer に重なる。
- `footer_covered` は `elementFromPoint` だけで見るので、立たない。`footer_changed` は footer の style と大きさだけを見るので、これも立たない。

人の制約「注記を隠す CSS を許さない」に直接反する。

修正案:
- (a) Critical 1 と同じく、shadow は inset だけにする。
- (b) canvas を `overflow: clip`（または `contain: paint`）にして、canvas の外へ塗れないようにする。これは renderer 側で付け、shop CSS からは変えられない。
- (c) footer と notice の検査を画素の比較にする。shop CSS あり／なしで、footer の box の screenshot が一致することを見る。

### High 1: 検査する幅が 360／390／1440 だけで、`@media` の帯で全事実を潰せる

```css
@media (min-width: 400px) and (max-width: 1400px) {
  #shop-css p, #shop-css dd, #shop-css li, #shop-css span, #shop-css h1 { font-size: 1px; }
}
```

- 結果: guard OK、render **PASS**。
- 768px の screenshot では、店名・紹介・menu・住所・営業時間・電話がすべて点になって読めない。1024px も同じ。
- 同じ手で、320px（`max-width: 359px`）や 1920px（`min-width: 1441px`）も壊せる。
- `font-size` は静的には下限が無い。`1px`・`0.1px`・`calc(1vw / 100)` が通る。そのため render check の幅が唯一の守りになっている。

人の制約「PC と phone の崩れを確かめる」は、タブレットや中間の幅を含むと読むのが自然。

修正案:
- (a) media query の境界値を集め、各帯の内側の幅（境界 ±1px、em は 16px で換算）を必ず検査の幅に足す。320・768・1024・1920 も既定に足す。
- (b) または、許す breakpoint を固定の数個（例: 720px・1200px）だけにして、各帯を検査する。
- 併せて、`font-size` に静的な下限を付けると多層の防御になる（px・rem は 12 以上、vw は `max()` の中だけ、など）。

### High 2: 事実ではない固定の見出しと label を検査していないので、事実の意味を変えられる

```css
#shop-css dt, #shop-css h2 { color: transparent; }
```

- 結果: guard OK、render **PASS**。
- 「営業時間」「定休日」「電話」の label と、節の見出しが消える。値（`10:00〜17:00`・`月曜`・`052-000-0000`）だけが並ぶ。
- 「月曜」に「定休日」が付かないと、営業日にも読める。
- `MEASURE_SCRIPT` は fact の文字列に含まれる text node だけを測る。label・見出し・notice の文字は対象外になっている。

設計メモの脅威表は「事実の意味を変える」を挙げている。それに対する検査の範囲が足りない。

修正案: renderer が出す固定の label・見出し（`dt`・`h2`・row label）も「必ず読める text」として同じ検査に入れる。少なくとも次の 4 つ。
- hidden
- contrast
- small
- covered

### Medium 1: `display: list-item` + `list-style-type: decimal` で事実の前に数字が付く

```css
#shop-css dd { display: list-item; list-style-type: decimal; list-style-position: inside; }
```

- 結果: guard OK、render **PASS**。
- 画面は `1. 10:00〜17:00`・`1. 月曜`・`1. 052-000-0000` になる。
- 設計メモの「CSS は文字を足せない」に反する。
- 要素を list-item にする数を変えれば、counter の値（数字）も選べる。電話・価格・住所の番地の前に任意の数字を付けられる。

修正案: 次の 2 つを外し、`list-style-type` は `none`、または既存の `ol`・`ul`・`li` の上だけで許す。
- `display` の許可から `list-item`
- `list-style-type` の `decimal`・`decimal-leading-zero`

### Medium 2: 要素の `outline` が隣の事実の文字の上に塗られる

```css
#shop-css dl > div { padding: 0; margin: 0; border: 0; line-height: 1; }
#shop-css dl > div > dt { outline: 4px solid var(--p-bg); outline-offset: 4px; }
```

- 結果: guard OK、render **PASS**。
- 360px で、営業時間・定休日・アクセスの値の上端に地の色の帯（4px）がかかり、字が欠ける。
- outline は stacking context の最後に塗られる。hit-test にも出ず、contrast の screenshot でも地として扱われる。

修正案: `outline-offset` を 0 か負なしの最小に固定し、`outline` を位置指定のない要素だけにする。あるいは、Critical 1 の「描かれた文字の画素」検査で一括して防ぐ。

### Low 1: `*` と `:not()` で `a`・`img`・`svg` 以外の禁止要素にも届く

- `#shop-css *`・`#shop-css :not(p)` は guard を通る。
- 型名で `a`・`img`・`figure` を外した意図（設計メモ §3）が `*` で崩れる。今は害が render check で止まるものだけだが、文書の主張と合わない。
- 修正案: `*` を外す。または、文書に「`*` は全要素に及ぶ」と明記する。

### Low 2: 大きさの上限は `%`・`em` の入れ子で効かない

- `#shop-css section * { font-size: 140% }` が guard を通る（render で `overflow_x` になった）。
- `400%` も通るので、入れ子 n 段で 4^n 倍になる。
- 設計メモの「大きさの上限」は 1 宣言あたりの値で、計算後の値の上限ではない。資源の面で問題になるのは Chromium の描画時間くらいで、check の timeout で止まる。
- 修正案: `font-size` の `%`・`em` を 0.75〜2 程度に絞る。

### Low 3: record が demo（事実）に束縛されていない

- `shopCssFromRecord` は run・candidate・profile・CSS の hash を見るが、`<run>/demo` の内容は見ない。
- 同じ run で demo が差し替えられると、別の事実で検査した CSS が出る。
- 今は local preview だけで、run の dir は worker が書くので Low とした。
- 修正案: `demoSha256` を record に足す。

### Nit 1

render check の context に `javaScriptEnabled: false` が無い。頁に script は無いので実害は無い。ただ、測定の script は `page.evaluate` で動くので、JS を切ると測れない。`setContent` の後に「頁の中に script element が無い」ことを assert しておくと、意図がはっきりする。

### Nit 2

設計メモ §2 の「疑似要素で自分の文字の上に重ねる」の対策の文が、静的にしか保証されていないことを明記するとよい。

位置指定済み（module CSS で `position: absolute`）の装飾 span の `::before` に地を付ける probe（`header > span[aria-hidden="true"]::before { … height: 2400px; background-color: … }`）は render を PASS した。今回の profile では、装飾が `z-index: 0` で事実の後ろに塗られたので害は無かった。しかし MEASURE_SCRIPT の例外（透明で文字の無い hit は覆いとみなさない）は、疑似要素の地を見ない。別の direction（profile）で装飾の z が事実より上なら、覆いが見逃される。例外の判定で、`::before`・`::after` の `background` も見ること。

すり抜ける理由（3 つの検査の隙間が重なる）:
1. hit-test は各行の**縦の中央**の 3 点だけを見る。上側を覆っても `fact_covered` にならない。
2. 画素の証明は、字ごとの「最初から最後の墨の行」の幅を、字の平均で baseline の 0.6 倍と比べる。上を 40% 削っても、幅は 0.6 以上残る。
   - 縦の中ほどの帯（取り消し線の形）は、最初と最後が残るので幅が変わらない。
   - 数字のうち数個だけを深く削っても、平均で薄まる。
3. contrast は「地」と文字色の比で見る。覆いが地と同じ色なら下がらない。

`transform` は stacking context を作り、位置指定の層で塗られるので、後ろの通常の流れの文字の上に乗る。依頼にあった「≤40% の部分的な覆いは通るか」には、**通る**と答える。

- 静的: `transform` を、子に事実を持たない要素に限るのは難しい。代わりに次のどちらかにする。

  - 「最初から最後の幅」では、中ほどの帯と部分的な削りが見えない。
- render check: hit-test の点を、行の高さの 25%・50%・75% と、横に 5 点以上に増やす。または、字ごとの box の中心で行う。

この手は、grid の 0px の列（`grid-template-columns` は許可されている）で、同じ block の中の文字をいくらでも重ねられる。例: 段落の中の `data-keep` の電話や番地、Stage 1 の抜粋と固定の label。

修正案:
- (a) 文字の box の幾何で重なりを検査する。測った text node の字ごとの box（`chars`）が、別の node の字の box と面積で重なり（例: 小さい方の 20% 以上）、baseline では重ならないなら、`*_overlap`（または `*_covered`）にする。全字の対で見ても数百字なので軽い。例外が要らなくなる。
- (b) 例外を残すなら、hit が `el` と**同じ要素の中の line box**（`hit === el` か、hit が el の祖先で、その点に el 以外の文字が無い）に限る。別の要素の文字は覆いとして数える。atelier-mono の店名で行の box が重なる誤検出は、(a) の字の box で判定すれば起きない（字の box は重ならない）。

### Medium 1: 墨が 6 画素未満の字（`-`・`:`・`.`・`,`・`・`）は、全部消しても通る

- probe は上の表のとおり。電話の `-` が消えて PASS した。
- 12px では `-`・`:`・`.`・`,` の基準の墨が 6 画素未満なので、`inkOf` で `continue` され、`missing`（墨 0 の字）の数にも入らない。

- 修正案: `MIN_REFERENCE_INK` 未満の字も、`ref > 0 && ink === 0` なら `missing` に数える。比の検査だけを、小さい字で飛ばす。

### 追記: CI の失敗（job 118792775207、76b7362）

**現象**: GitHub の runner で、例の stylesheet（kissa / atelier / sakura / stage1-hooks）が多くの幅で `fact_ink` / `label_ink` / `footer_ink` になった。local では通っていた。

**再現**: fontconfig で subpixel（LCD）の antialias と full hinting を有効にすると、local でも同じ失敗が出た（`rgba=rgb`・`hintstyle=hintfull`）。

**原因**: 基準の画が、文字を白地に黒で描いていた。Chromium（Skia）の文字の antialias は、色と地に依存する。
- LCD では channel ごとに覆い方が違い、明暗によって gamma の補正も違う。
- そのため、色の付いた地や反転した地の文字の「墨」が基準とずれた。
- `::first-letter` の色も合わなかった。

**対応**: 閾値は下げず、基準を頁と同じ描き方にした。
- 基準の画では、各要素の文字をその要素自身の色（`currentcolor`。`::first-letter` も自分の色のまま）で描く。地には、頁で実際にその文字の下に塗られている色（文字なしの画の中央値）を不透明で敷く。
  - これで、書体・合成・大きさ・transform・色・地が頁と同じになり、antialias（greyscale でも LCD でも）も同じになる。
  - 違うのは、覆いが無いことだけ。
- 墨は、文字ありと文字なしの画の、channel の差の和で測る。
- 結果: 例 4 つ × Stage 1 の 3 店、元の fixture では、両方の環境で全字の比が 0.98〜1.00 になった。
- 第 2 の書体環境の test（`fonts.test.tsx`）を足した。
  - 環境: LCD の antialias + full hinting の fontconfig に、別の書体（DejaVu と WenQuanYi）。
  - 例 4 つが、元の SHOP・Stage 1 の cafe・bakery（縦書き）で通ることを確かめる。
  - 覆い（伸ばした隣・外側の shadow・持ち上げた装飾）が、同じ環境で落ちることも確かめる。
