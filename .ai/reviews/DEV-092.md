# DEV-092 Fresh Review (probe accepts Linux 6.15+'s implicit dport mask; A-3 backport → X2; PR #108)

- Background: on WSL (kernel 6.18.33), `jail-install` at `fbfce3c` failed with `JAIL_UNSAFE DNS_RULES_NOT_EXACT`. D-3 showed `ip rule show` exactly as designed. D-4 put the jail back on `c066618` (`JAIL_OK`, 4×`SAME`).
- Cause: in Linux 6.15 and later, `fib_nl2rule` gives a single-port rule `dport_mask=U16_MAX` (v6.18 `net/core/fib_rules.c:716-718`), and `fib_nl_fill_rule` returns it as `FRA_DPORT_MASK` (29) (`:1212-1213`). DEV-088's `describe_rule` wrote it as `attr29`. Checked on a live 6.18.44 kernel with `unshare -rn`: only rules 98/99 carry `DPORT_MASK=0xffff`, and no other attribute is new.
- Fix (`probe.py` only): drop `FRA_DPORT_MASK` only when it is 2 bytes of `0xffff` with a single-port `FRA_DPORT_RANGE`. Everything else is written as `dport_mask=0x…`/`?`, so the exact match fails. `FRA_SPORT_MASK` stays unknown. `EXPECTED_RULES` is unchanged.
