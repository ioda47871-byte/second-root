# DEV-024 review: final security review of the Instagram feature (DEV-020..024)

## Round 1: PASS (Critical 0 / High 0 / Medium 0 / Low 4)

Every human-approved requirement was checked end to end and holds:

- **Webhook**
  - The raw body is capped at 2 MB, and `X-Hub-Signature-256` (HMAC-SHA256, constant-time compare) is verified before anything is parsed or stored.
  - Fails closed (503) when the secret is missing, shorter than 16 characters, or no account ID is set.
  - The GET handshake checks the verify token and restricts the challenge to a pattern.
  - Only events for our own account are stored; unmatched senders are kept for the human.
- **Sending**
  - Only one path: `requireAdmin` → the admin saw this exact text → `checkDraft` → `begin_send`.
  - In the database, `begin_send` checks: admin, matched, not DNC, latest message, and the 24h window.
  - The idempotency key prevents a second send of the same text.
  - Ambiguous outcomes become `unknown` and are never resent automatically; `sent` requires Meta's message id.
- **Operational Claude and cold outreach**
  - There is no cold-DM path.
  - The ingest token cannot send, change DNC, or change outcomes.
- **Token and output safety**
  - The token lives only in `server-only` `lib/instagram/graph.ts`, travels only as a Bearer header to the fixed host, and redirects are refused.
  - It is never logged, never stored in the DB, and never `NEXT_PUBLIC`.
  - No `dangerouslySetInnerHTML` anywhere.
- **Retention**
  - Only deletes Instagram threads (cascading to their messages, drafts and sends) and old webhook fingerprints.
  - Keeps conversations whose send is still open.
  - Can only be run by `service_role`.
  - Together with the 7-day event limit, a replayed delivery cannot bring deleted messages back.
- **Connection check**
  - Admin-only, one read-only GET to a fixed URL.
  - Shows whether each setting exists, never a value.

| Sev | Finding | Resolution |
|---|---|---|
| Low | The setup guide's `curl` examples put the token in shell history, and the refresh URL puts it in the query | Fixed. The token is read with `read -rs IG_TOKEN`, sent as a Bearer header, and removed with `unset` afterwards. The refresh uses `--data-urlencode` with the variable; Meta's refresh endpoint only accepts the token in the query. |
| Low | The retention guard relied only on the draft's status | Fixed: it also refuses when any send of the thread is `sending`/`unknown`. |
| Low | The guardrail for `dangerouslySetInnerHTML` did not cover `components/admin/` | Fixed |
| Low | The client-component guardrail did not cover `INSTAGRAM_ACCESS_TOKEN`, `lib/instagram/graph` or `lib/instagram/reply`, and those files were not in the server-only list | Fixed |

The only remaining check needs a real Meta account; it is recorded as HUMAN-006 (`docs/INSTAGRAM_SETUP.md` §8).
