### 判定

| code | 重さ | いつ |
|---|---|---|
| `COPY_FACT_UNSUPPORTED` | fail | 既存の検査 (facts pack の schema、`checkArtifactCopy` = `checkCopyRecord` + 頁の全文言が record にある + 並んだ文言が事実に見えない) のどれかが落ちた。codes はそのまま `base_checks` に残す |
| `COPY_FACT_UNSUPPORTED` | hold | 創作の「言い切り」(…ます。/…る。) が facts に無い語を名指す (監査自身の、より厳しい疑い。例: 出典の無い「クロワッサンは毎朝焼きます。」を creative で書いた場合) |
| `COPY_RHETORICAL_OVERUSE` | revise | Hero 以外の3区画以上が決め台詞の形の行で始まり、Hero 以外の見出し行の半分以上 |
| `COPY_REPETITIVE_CADENCE` | revise | 同じ行の形 (句点止め・「…、…」・体言止め＋句点・助詞止め) が3区画以上 |
| `COPY_GENERIC_FOR_SHOP` | revise / hold | 店名を外すと facts の語を1つも持たず、かつ汎用句の信号に当たる行が2行以上。facts に使える材料が無ければ hold (M3) |
| `COPY_INFORMATION_MISSING` | hold / revise | 提供物・営業時間・場所が facts に無い → hold (創作しない)。facts にあるのに頁に無い、または事実もラベルも無い区画 → revise |
| `COPY_VOICE_UNNATURAL` | revise | 丁寧語の頁に常体の言い切り、読点3つ以上の短い行、感嘆符の多用 |
| `COPY_APPROVAL_MISSING` | hold | 実店舗レーンは常に |

verdict は最も重いもの (fail > hold > revise、無ければ approve_candidate)。5軸の 0–5 は補助で、判定に使わない。

### 仕様レビュー (C0/H0/M5/L6) の規則の反映

- **M2 事実の洗浄の禁止**: `validateCopyRevision(old, new, {facts})`。claim_type の変更・逐語でない事実・事実を言い換えた新しい (または書き換えた) 散文 (事実の値を含む、または文字2-gram の4つ以上かつ4割以上が1つの事実から) はすべて FAIL。テスト: F10 を「スポークを丁寧に締め直し、車輪をまっすぐにします。」と創作で書き直すと FAIL。
- **M3**: 材料が無いときの汎用は HOLD。逐語の事実とラベルは文体・反復・汎用の軸から外す。
- **M5 レーン**: `quality_research_fictional` は全部の文体監査。`real_shop_proposal` は事実とラベルの選び方・並べ方 (情報の欠け・事実の無い区画) と言い切りの出典だけを見て、散文は店の言葉として扱わず、常に `COPY_APPROVAL_MISSING`。
- **L1 束縛**: facts・copy・HTML・CSS の sha256 と `auditor_version` (`copy_quality_rules_v1`)。`checkCopyQualityReview(raw, files)` は実ファイルから hash を計算し直し、監査を再実行して verdict と findings (code・重さ・規則・位置) を照合する。手で書いた PASS も古い PASS も通らない。
- **L2 語彙**: `verdict: fail | revise | hold | approve_candidate`。fail は終端 (`nextCopyStep` が `stop_fail`、`checkCopyQualityReview(..., {previous})` が `REVISION_AFTER_FAIL`)。オーナー承認はこの記録に入れない (`OwnerCopyApproval` は呼び出し側の型)。
- **L3**: 既存の base check は不変。fixture は全部 `checkCopyRecord` を通る (テストで確認)。メニュー見出しを非事実の項目として足していない (`メニュー` は `INVENTED_FACT_SIGNS` に当たる)。メニュー / アクセス / 営業時間の見出しを罰しないことは規則関数のテストで確認。
- **L4**: 「輪」のテストは頁全体の累積だけを確かめる。「一本ずつ。」(F10 が出典) の行への指摘が無いことも確かめる。
- **L5**: 区画は `data-comp-section` / `data-section`、役割は h1–h6・dt/th・aria-hidden から。モデルの申告は使わない。
- **L6**: `MAX_COPY_REVISION_ROUNDS = 2` (schema の `round` の上限も 2)。過去案の corpus に依存しない。

### 設計上の判断 (仕様に余地があったところ)

- 仕様の `page_sha256` は HTML と CSS の2つ (`page_html_sha256`・`page_css_sha256`) にした (L1)。
- 実店舗レーンの営業送信: `copyGateSendBlockers` は review が実ファイルに対して有効・`COPY_APPROVAL_MISSING` を除いて合格・同じ5入力に対するオーナーの approve、のすべてで初めて空になる。架空研究レーンは常に `FICTIONAL_RESEARCH_NOT_SENDABLE`。空でも「このゲートが止めない」だけで、デザイン審査や送信経路の門は別。
- 既存の文言検査は `lib/sales/demo-version/copy-check.ts` の `checkArtifactCopy` を再利用した (サーバーが使うのと同じ包み)。頁の文言は DOM の文言に `<title>` と見える属性 (`VISIBLE_TEXT_ATTRIBUTES`) を足したもの。
- 汎用句の一覧 (`GENERIC_PHRASE_SIGNALS`) は信号だけ。店名を外した名前の入れ替え試験に落ちた行にだけ効く。「こだわりのブレンドコーヒー」のように店の事実を名指す行は汎用にしない。
- 架空店舗の共通語「架空」は店固有の根拠にしない。

### 既知の限界 (DEV-199b / 199c で検証)

- 形の信号は日本語の表記に依存する (句点止め・読点・助詞止め)。句点の無い詩的見出しの累積は、反復の形に当たらない限り見逃しうる。
- 体言止めの判定は末尾の文字種 (漢字・カタカナ) による近似。
- 創作の言い切りで facts に無い語を名指すと hold になる。facts に無い一般語 (例: 「気軽」) でも言い切りなら hold になる側に倒している。
- 実画像・実際の生成フローでの PC/SP 全頁の比較はまだ (DEV-199c)。
