# Design Intelligence v0.2 — Structure First / 構成を発明してから装飾する

**Status: research pilot, unapproved, 2026-10-27. No production integration.**

## 変更する考え方

v0.1は店固有の特徴をデザイン知識として記録してきたが、最近の研究作品では「Heroが左コピー＋右写真、その後は文章と写真を交互に配置」の**ページ骨格**が繰り返されていた。写真・色・波線を変えても、構成が同じなら新しい作品とは評価しない。

このv0.2では画像生成前に**3つの互いに異なる構造設計図**を作り、見た目ではなく最初の画面・視線の順番・セクション構造・閲覧操作・モバイル変換を明示する。既存の研究事例は **`v01/success-patterns.json`** を参照して人間が重複を判断する。過去作9件のセクション単位の実測値は保存されていないため、根拠なく定量化しない。

## 7段階の工程（制作プロセスの提案）

| Gate | 工程 | 次へ進む条件 |
| --- | --- | --- |
| 1 | 店の事実と画像利用権の確認 | 出典・確認日・未確認事項を区別 |
| 2 | **構成を3案発明** | 各案のHero/章構造/導線/スマホ設計が実質異なる |
| 3 | **構成の重複監査** | 新案同士の類似性警告を確認、既存CP-001..009は人間が照合 |
| 4 | **ユーザーが構成を選ぶ** | 自動決定せず候補を示して選択理由を記録 |
| 5 | 選択案のビジュアル制作 | 配色・写真・文字だけで骨格を上書きしない |
| 6 | 写真/文字分離とレスポンシブ実装 | ブラウザPC・モバイル表示、機能と可読性を比較 |
| 7 | デザイン承認と商用公開判断 | 研究成功・実装成功・店舗許諾・公開を別々に判定 |

**注意:** このv0.2の最初の段階ではGates 2–3を研究実装し、その後PT-02 v3のローカルHTML PoCをユーザーが研究成功として承認した。Claude/Codexへの自動プロンプト注入・CI必須ゲート化・公開処理は行わない。

| --- | --- | --- | --- |

共通するのは「店の実態に確認を要する」「アクセシブルな文字と明確な連絡先がある」ことだけ。レイアウト共通化は目的ではない。

## 静的監査ツール

```bash
node design-library/intelligence/v02/structure-audit.mjs
node --test design-library/intelligence/v02/structure-audit.test.mjs
```

- v0.2の`structure-audit.mjs`は、**申告された構造トークン**で各案を比較する。Hero一致30%、ナビゲーション一致15%、閲覧順一致10%、章の構造の重複30%、隣接構造の重複15%で算出（0～1）。
- 0.75以上は「構造の重複疑い」、0.50以上は「人間が比較すべき」と表示する。**閾値は実験的な警告値で、審査の合否や品質の点数ではない**。
- 同一の写真と文章の2カラムが3章以上、同じ章が3回連続、単調なHero、実用情報欠落などを発見できる範囲で警告する。
- トークン名を適当に変えれば検知できない。スクリーンショットを見る最終判断の代わりにはならない。過去の事例と根拠なしに数値比較することもしない。
- 店舗確認ができない場合は情報を作らず、フォームやマップへの偽リンクは設置しない。

## 人が比較すべき「構成」6項目

1. **Heroを写真なしのワイヤーで見ても、他作と違うか。**
2. **写真を同じグレーに置き換えても、章の形が異なるか。**
3. **章の順序が店舗の実体験に由来するか（任意の差替えではないか）。**
4. **一章のサイズ・空白・操作が次章へ影響するか。**
5. **モバイルがPCの縮小ではなく、その構成の適切な再解釈か。**
6. **実用情報が見つかり、装飾のために情報を隠していないか。**

## 安全な境界

- 本ファイル群は専用研究ブランチの実験ファイル。既存参考候補80件、成功研究9件、審査待ち20件のラベルは変更しない。
- 既存の`lib/design-agent`、プロンプト、CSS許可表、ワーカー・営業AI・Supabase・Vercel・本番サイトに**接続しない**。
- ブランドのロゴ・画像・既存レイアウトの模倣や流用をしない。
- ユーザー選定前に`chosen_proposal_id`を勝手に記入しない。今回、PT-02 v3の採用は`owner_approval_evidence`およびCP-010の個別研究記録を伴う。
- 先に新規構成のワイヤーを3つ見比べ、その後にビジュアル制作へ進む。

## CP-016｜ズールー工作所：成功作と構図が重なる問題の再発防止（2026-10-28）

最初の金属モビール画像に対するオーナー評価は**「同じような構成になってきた」**。店ごとの材料が違っても、上部横ナビ／左の日本語コピー／大写真Hero／線や手書き注釈／波型境界／写真下層という**骨格が反復**したため、初稿を**研究成功例として採用しない**。

[CP-016の3つの非テンプレート構造案](experiments/CP016-zulu-structural-reset.json)を記録。ZK-01 重力と釣り合うレイアウト（中心支点／空白／重りの関係）、ZK-02 影の展示室（ほぼ空白の壁／影と作品／周辺の展示番号）、ZK-03 部品の分解組立図（部品番号／工程／図面索引）。**推奨はZK-01**。ただしオーナー未選択・画像未生成・Web未実装。JSONの語彙だけの類似度が低いことは実画面での独創性を証明しない。

**今後の条件:** 3案でHero構造・ナビゲーション・情報の閲覧順・スマホ展開を変える。構造だけのラフを先に作り、過去の成功作（特にCP-015の一枚絵探索）との違いを**見た目で**確認してから写真・質感を足す。写真/色の変更を構造の改善と数えない。制作は研究専用、本番システムは変更しない。**研究成功例は依然14件、CP-014/CP-016は未承認**。
