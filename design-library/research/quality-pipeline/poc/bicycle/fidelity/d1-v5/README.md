2026-11-05。オーナーの確認 (Issue #193、2026-11-05) の「601〜999px でスポークがハブにつながっているか」を描いて確かめ、つながっていなかったので直した版。

- これは**カンプ `comps/d1-wheel-hub-v4` の実装**である。この C はカンプと**同じ HTML・copy.json** を使い、CSS は先頭の注記だけが違う。描画はカンプと同じバイトになった。

## 変えたこと (601〜999px だけ。PC 1000 以上と SP の描画は前の版と同じバイト)

- **スポークとハブ。** 601・700・768・860・999 を描くと、4本の黄のスポークの内の端がハブ (輪 の黄の円) の縁の手前 8〜11px で切れ、ハブにつながって見えなかった
  (スポークの始点が 768 幅の単位で半径 88、ハブの円は半径 80)。
  始点をハブの縁 (半径 80.5) に移し、端を四角にした (丸い端だとハブの中へ 4.5 単位入る)。外の端は板のピンの下に隠れる。
  ハブを上に重ねる作りも試したが、Hero が重なりの文脈を作るので効かず、スポークが 輪 の上に描かれたので採らなかった。
- **板の影。** タブレットの板の影 (24px 下、22px のぼかし) が 26px 下の駅の名前に届いていた。8px 下・6px のぼかしにした。
- **締める の余白。** 字の高い書体 (下の wide) で、締める の字の箱が上の事実 (…まっすぐにします) と下の事実 (どこを…) から 4.4px しか離れていなかった。
  タブレットで修理の区画の下と確かめの区画の上に 16px ずつ足した (20px 以上になった)。

## 確かめたこと (リポジトリの外の使い捨ての道具)

601〜999 の全部の幅 (1px ごと、399 幅) を、3つの書体の設定 (`ipa`・`alt`・`wide`、ゆげ湯 d1-v5 の README と同じ) で数えた。

| 設定 | 幅 | 巨大な語の字の箱の重なり | 板・要素が文字の上 | 画素の差 (飾り→文字) | はみ出し / 切れ | 4.5:1 未満 | 巨大な語といちばん近い文字 |
|---|---|---|---|---|---|---|---|
| ipa | 399 (601〜999) | 0 | 0 | 399 (すべて 輪 の字の箱の角。墨では 0。HOLD) | 0 / 0 | 0 | 37px |
| alt | 399 (601〜999) | 0 | 0 | 399 (すべて 輪 の字の箱の角。墨では 0。HOLD) | 0 / 0 | 0 | 22px |
| wide | 399 (601〜999) | 0 | 0 | 399 (すべて 輪 の字の箱の角。墨では 0。HOLD) | 0 / 0 | 0 | 20px |

**輪 は HOLD (未解決として数えない)。** 字の箱は 1.3em の四角で、その角が丸いハブの外へ出て、車輪の細いスポークの画素に掛かる。
字の墨の画素 (文字を黒と白で描き分けて差のある画素) で数え直すと、390・601・768・999・1440・1920 の6幅 × 3つの書体のすべてで、飾りに掛かる墨の画素は 0 だった。
箱の角を消すにはハブを約 35% 大きくするか字を小さくする必要があり、構図が変わるので、オーナーの判断に残す。

**見たもの:** 601・700・768・860・999 の Hero と駅 (前と後、0.42 倍)、601・768・999 のハブの等倍の切り抜き (前と後)、PC 1440 と SP 390 の全体 (カンプの描画)。
