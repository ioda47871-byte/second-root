# つぐ手 d1 v2: カンプと Web 実装の見比べ (DEV-160、Issue #193)

2026-11-03。カンプ `comps/d1-seam-across-v2` を、実装レーンの規則 (`lib/design-agent/comp-impl/page-css.ts` の CSS 許可一覧と、HTML の許可一覧) の中で Web ページにした。
PC 1440 と SP 390 を描き、Claude がカンプと並べて自分で見た。**ここでの判断は品質の判定ではない。** 採るかはオーナーが決める。

- 2つの実装はどちらも、`htmlSourceProblems` と `cssProblems` で問題 0 件だった。
- 写真は、1色の仮の板 (`assets/board.png`、64×64 の単色) である。
- 描いた画像はリポジトリの外に置き、SHA だけを残す。条件は JS 無効・自分のファイル以外への通信拒否・deviceScaleFactor 1・ページ全体。

## a: 規則の中で素直に組んだ版。見て分かった品質の低下

- **金の線が切れた。** カンプの核である「1本の線が全区画を通る」が、区画ごとの短い縦線になった。SP では線が無い。
- **破片の区画がテンプレートになった。** 同じ大きさの正方形の板と文字が、3回同じ向きに並ぶ。原因は Claude の実装の誤りである。単色の 64×64 の画像を `width: 100%` で置いたので、板がすべて正方形になった。
- **割れた器が1枚の半円になった。** 割れ目が無い。
- 縦書きと、縁取りの巨大な文字が無くなった。巨大な文字は薄い塗りで、区画の境もまたがない。
- 傾いた板・影・重なりが無くなった。

## b: 低下を直した版 (規則はそのまま)

- **線を1本に戻した。** すべての行を同じ3列 (`1fr auto 1fr`、中央は幅 4px の線) の格子にした。PC では、線が Hero から来店の結び目まで途切れない。SP では、線を行の左の罫として左の余白に通した。
- **破片を千鳥にした。** 文字と板を左右交互に置き、板の縦横比と大きさをそれぞれ変えた。
- **器を2つの半分に割った。** 間に線を通し、右の半分を少し下げた。
- **相談の区画:** 線を写真と文字の間に通した。

## まだ残る低下と、その出所

| 低下 | 出所 |
|---|---|
| 線がまっすぐで、器の割れ目をジグザグに通らない | 規則 (SVG・position・transform が使えない) |
| 縁取りの巨大な文字が無い。境をまたがない | 規則 (`-webkit-text-stroke`・負の margin・position が使えない。文字は最大 256px) |
| 板が傾かない。影も重なりも無い | 規則 (transform・clip-path・外側の影・position が使えない) |
| 縦書きが無い (店名・見出し・一か月の事実) | 規則 (横書きだけ) |
| 写真が単色の板 | 規則 (仮の画像は単色だけ)。実際の写真は別の承認が要る |
| SP: 線が器では中央、その下では左の余白で、つながらない | Claude の実装の選択。中央に線を置くと、文字の列が 180px になって読めない |
| SP: ページがカンプより 830px 短く、密である | Claude の実装の選択 |

**このカンプの表現の核 (割れ目を通る線・境をまたぐ要素・縦書き) の大半は、今の実装レーンの規則では作れない。**
規則を緩めるのは安全の門を変えることなので、ここでは行わない (オーナーの判断事項)。

## 道具の食い違い (見つけたこと)

- `impl-compare` (DEV-139) は `[data-section]` で区画を測る。
- 一方、実装レーンの HTML 許可一覧は `data-section` を許さず、`data-comp-section` だけを許す。
- そのため、同じ実装を両方へそのまま通せない。この見比べでは `impl-compare` の数値を使わず、Claude が画像を並べて見た。
