# Phase 2f-1：A/B/C 実証の実行プログラム（DEV-115）

オーナーが 2026-10-29 に承認した範囲は、Phase 2f-1 の実装・テスト・独立 Fresh Review・develop 向け PR まで。実際の Codex 実行、画像生成、2f-2 の実証は含まない。

目的は、Codex が店舗固有の独創的なデザインを作れるかを、同じ架空店舗で A（画像）・B（HTML 試作）・C（併用）を比べて確かめる基盤を作ることである。**技術的な検証を通っても、デザインが凡庸なら成功にしない。**

## 1. 流れ

| 経路 | 流れ | 結果の状態 |
|---|---|---|
| B | Codex の答え（`codex_design_v1`、試作 HTML/CSS は文字列）→ 答えの検査 → 試作の安全検査 → PC1440・SP390 で描画 → 区画を実測 → PNG を実際に復号 → パッケージ → DEV-114 の Intake | `render_pair_complete`／`incomplete` |
| C | B と同じ。加えて、試作が表示する素材ごとに画像生成を1回（素材ごとに別の承認 ID）。依頼文は試作の `<img alt>` | 同上。画像が失敗し主役でなければ、明示的に B へ切り替え |
| A | 既存の画像生成 PoC の出力（report と PNG 1枚）を構想画像として包む | 構想画像。390 の別設計が無いので `incomplete`、実装へは渡さない |

Codex と画像ツールは、呼び出し側が渡すポート（`DesignPort`・`AssetPort`）からだけ呼ぶ。2f-1 は擬似ポートだけを使い、本物のポートは 2f-2 で別承認を受けて作る。

## 2. 既存資産の再利用とガードの例外

- **comp-impl の描画部品（オーナー承認）:** `lib/design-agent/phase2f/render-prototype.ts` の1ファイルだけが、comp-impl の次を読み込む。
  - 安全なページの開き方（`openCompPage`：自分のファイル以外の通信を遮断し、JavaScript 無効、service worker 遮断）
  - 高さの上限（`MAX_PAGE_HEIGHT` = 16000）
  - 型 `Viewport`・`PageAsset`

  comp-impl の隔離テストは、この正確なパスと、読み込む名前だけを例外として固定している。comp-impl 本体、実装用 CSS 許可リスト、comp の仕様、品質基準は変えていない。
- **実復号:** worker の PNG 読み取り（`decodePng`）を使い、実際に展開して画素を数える。
- **DEV-114 の Intake:** パッケージは毎回 Intake で検査する。Intake の隔離テストも、読み込むファイルを正確なパスで固定している。

## 3. 試作の安全検査（描画の前）と、デザインの自由

- **止めるもの:** コードの実行や外部への通信につながるもの。
  - 要素: script、iframe、object、embed、form、base、meta refresh、SVG の foreignObject と script
  - 属性と URL: on* 属性、javascript:・data: の URL、自分のスタイルシート・申告した素材・ページ内アンカー以外への URL
  - CSS: @import、申告した素材以外への url()、expression()
- HTML は Chromium のパーサーで解析する。CSS は2回調べる。
  - 元の文字列（エスケープを展開してから）
  - Chromium 自身が解析して書き直した文字列（コメント・文字列・エスケープを renderer と同じように解決したもの）

  `url()` は引用符の中の `)` を理解して取り出す。SVG の属性（fill・mask・filter など）に入った `url()` にも同じ規則をかける。
  - 通すもの: `\201C` のような正当なエスケープ、ページ内参照の `url(#id)`、Content-Type などの無害な meta
  - 止めるもの: `u\72l(` のような隠し方、文字列の中の偽のコメント、meta refresh。`@import` は、コメントを除く前の文字列でも探す（Chromium が書き直すときに `@import` を落とすため）
- **かけないもの:** comp-impl の実装用 CSS 許可リストや、決まったページ構造。研究段階の試作は、グリッド・変形・縦書き・clip-path・インライン SVG など、どんな表現でも使ってよい。テストで確かめている。
- 描画もネットワーク遮断・JavaScript 無効で行う（2段目の防御）。それでも外への通信があれば停止し、オーナー確認に回す。

## 4. 描画と実測

- PC1440・SP390 とも deviceScaleFactor=1 で描画する（CSS px と PNG px が一致）。
- 390 はスマホのエミュレーションを使わない。使うと、viewport の meta タグが無い試作が 980px 幅で組まれ、不必要に止まるためである。メディアクエリは 390px で効く。
- 全ページの撮影は、画面幅で切り取る。横にはみ出すページは `PROTOTYPE_HORIZONTAL_OVERFLOW` として記録する（`incomplete`）。隠さないし、止めもしない。
- **構造仕様の位置と大きさは、描画結果から実測した値**（`data-section` の要素の矩形）を Artifact に書く。役割・順序・読む順・表示する文字は Codex の宣言のまま。Codex が見積もった位置は、比較のため実行記録（`declared_geometry`）に残す。
- 区画を画面幅によって非表示にするのは正当なデザインなので、止めない。DEV-114 のスキーマも、幅・高さ 0 を「その画面幅では非表示」として受け入れるようにした（各画面幅に表示中の区画が最低1つは必要）。
- 区画の外枠が大きさ 0 のとき（中身がすべて絶対配置、`display: contents` など）は、中の要素と文字が描かれた範囲で測る。外枠が大きさ 0 で中身を切り取る（overflow・contain の paint・clip-path）場合は何も描かれないので、非表示として記録する。それでも大きさを測れないのは、高さ 0 の枠に縦書きを入れて文字が1点に重なるような壊れたレイアウトで、非表示として記録する（`incomplete`）。
- 目印の無い区画は欠落として記録する（`incomplete`）。すべての画面幅で非表示の区画も記録する（`section_hidden_everywhere`、`incomplete`）。真っ白なページも記録する（`RENDER_BLANK`、`incomplete`）。

## 5. 生成の失敗と回復（自動の再試行はしない）

| 原因 | 扱い |
|---|---|
| 画像が失敗し、主役でない（`TOOL_FAILED`・一時的な失敗・呼び出し無し等） | 明示的に B へ切り替える。素材は中立のプレースホルダーになり、失敗の結果と停止コードはそのまま記録する |
| 画像が主役（実測で hero・半分以上が最初の画面・区画外）で失敗 | 停止し、オーナー確認（再生成するか、オーナーが判断する） |
| ポリシーによる拒否 | 同じ実行内で切り替えずに停止し、オーナー確認。誤判定か修正できる原因なら、オーナーが新しい実行を承認して再開できる（新しい承認 ID、修正後の指示文の SHA と前の実行への参照を記録） |
| 利用上限 | 停止。上限が戻るまで待つ |
| 停止コードの無い失敗、ファイルの無い「保存成功」 | ポートの不具合として停止する（失敗の内容を補ったり書き換えたりしない） |

上限（オーナーの計画）:
- 1回の実行の中: 設計の呼び出し1回・素材の呼び出し1回、1回の呼び出しは最大15分、全体で約2時間。実行プログラムが自分で守る。15分を過ぎると、ポートに中止の合図（AbortSignal）を送り、ポートが応じなくても実行は止める（`CODEX_TIMEOUT`・`CODEX_IMAGE_TIMEOUT`）。本物のポートは合図を受けたら Codex のプロセスを止める必要があり、これは 2f-2 でテストする。
- 実行をまたぐ上限（初回最大4回・再試行最大2回）: 2f-2 の承認 ID 台帳で数える。

実行プログラムが上限を自分で増やすことはなく、再試行も自動ではしない。

**C の事前描画:** 画像生成を呼ぶ前に、素材をプレースホルダーにして一度描画する。外への通信があれば、承認済みの画像生成を使う前に止める。各画像が実際にどの区画にあり、最初の画面に入るかもここで実測する。

**主役の画像の判定（実測）:** 置き場所は `<img>`・SVG の `<image>`・要素と `::before`/`::after` の背景やマスクから測る（content の無い疑似要素は描かれないので数えない）。次のいずれかなら主役とする。
- hero の区画にある
- PC か SP で、画像の半分以上、または最初の画面の半分以上を画像が覆う（指示文でも Codex に伝える）
- どの区画にも属さない

Codex の申告と実際の置き場所が違えば止める（`CODEX_ASSET_PLACEMENT_MISMATCH`）。

## 6. 比較シートと、不必要な停止の測定

- **評価項目:** 既存の評価表の5項目（美しさ・店舗との相性・独自性・Web サイトとしての構成・実装可能性）に、PC/SP の完成度を加える。
- **合格の条件:** 致命的な欠陥が無い、合計 22/25 以上、各項目 4 以上、PC/SP の完成度 4 以上、オーナーが「凡庸ではない」と判断、オーナーが採点を確定。
- 点数と判断は、すべてオーナーが手で入れる（初期値は空）。
- A は構想画像なので「構想として」だけ判定し、実装まで進める合格にはしない。
- 停止と警告の一件ごとに `stop_was_correct` を付け、オーナーの判定から不必要な停止の率を出す。
