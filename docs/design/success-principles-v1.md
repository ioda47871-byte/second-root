# 成功例20件の設計原理 (DEV-156、Issue #193)

2026-11-03。Second Root の採用成功例のうち、**実際に画像を見て分析できた20件**から、成功の設計原理を取り出す。機械で読む版は `design-library/research/quality-pipeline/principles-v1.json` にある (テストで形を固定)。

**この文書は研究の整理である。** ここに書いた原理を満たしても、「成功例レベル」に達したとは言わない。それを決めるのは、オーナーが実際の PC/SP の画像を見たときだけである。

## 2. 共通の原理

### P1 店固有のものが、色や写真ではなく「構造」に翻訳されている

- 20件すべてで、Hero の主役は店の固有の物・素材・工程・時間・空間である。例: カップ、枝、布の円、支点、糸、版、蝋、棚、パーツ、断面、看板、階段、ZINE、氷、時計の壁、裁断台、翅。
- それが飾りではなく、**画面の組み方そのもの**になっている。例: 支点 → 左右の釣り合い (016)、棚板 → 情報の区画 (020)、階段 → 章立て (027)、工程 → 読み順 (021・031)。
- 反例: 業種の記号に留まった CP-030 v1 (文字盤と歯車)、業種の雰囲気で作った CP-025 v2 (不採用。CP-025 は登録された成功例ではなく、文章の記録だけ)。

### P2 強い成功例は、中心のモチーフ1つから全体が派生している

- 1つの中心のモチーフが、Hero・区画の順序・区切り・注釈・SP まで貫く。例: 縫い糸 (009)、黄色の線 (008)、重さの対比 (016)、版ずれ (018)。

### P3 Hero だけでなく、下層の区画まで世界観が展開されている

- 区画ごとに、同じモチーフの**別の面**を見せる。例: 009 は STITCH・THINGS・TOGETHER・ATELIER、012 は石肌・結晶・制作・コレクション・情報。
- 最後の区画が終点を持つ (009 の赤い扉、030 の来店)。
- 反例 (文章の記録、画像は未見): Hero は良いが下層が平凡 (CP-011 v1)、Hero だけで全頁が無い (CP-025 以前の納品)。

### P4 区画ごとにリズムが変わる (同じ帯・同じカードを並べない)

- 地の色・写真の大きさ・文字の大きさ・密度のうち、少なくとも1つが区画ごとに大きく変わる。CP-001 は不規則なモザイクにし、CP-002 は区画を千鳥に並べる。参考 (20件の外。オーナーの記録では未見、Claude が登録 WebP を見た): CP-003 は地の色を全幅で切り替える。
- 反例: 均等な商品カード、写真の帯の繰り返し、左右交互の写真と文 (CP-023 v5、CP-016 初稿、PT-02 初稿)。

### P5 文字・線・注釈が、モチーフの言語になっている

- 巨大な文字が写真や区画の境をまたぐ (001・008・018)。
- 細い線・ラベル・番号の注釈が、観察や工程の読み順を作る (012・018・021)。
- 線そのものがモチーフである (009 の縫い糸、008 の黄色の線)。

### P6 PC と SP は、縮小ではなく別の設計で成立している (SP がある9件から)

- SP では、PC の主役の構造を狭い画面のための並び・操作に組み直す。例: 009 は PC と SP で配置を変える、016 は1画面の空間を保ち操作部だけを移す、028 は紙面の順序を組み直す。
- JSON で P6 を付けたのは 009・016・028 の3件。CP-026〜032 の SP は候補の画像で、SHA は照合していない。
- 参考 (20件の外。オーナーの記録では未見、Claude が登録 WebP を見た): CP-003 は豆の弧を SP で横一列の選択にし、PC の重なりを縦に重ねて保つ。原理の根拠には数えない。

### P7 磨くときは「守る核」を先に決め、局所だけを直す

- 採用版の多くは、初稿の核を守った局所の調整である (008 v3、017 v1.1、023 v4、031 v3)。
- 核を名指しせずに作り直した版は核を失った: 全体を再生成して巨大な GO. や糸の輪が消えた (008 v2、017 の再生成)。説明とカードを足した 023 v5 は、看板の主役性を消した。
- 色や反射だけを変えた全体の再生成は「何が変わった？」になる (021 v2)。採用されたのは手を入れていない初稿 v1 で、局所の調整の例ではない。

### P8 実店舗の事実と空気から始め、業種の一般論で埋めない

- 記録の分析 (`design_analysis`、オーナーの発言ではない) では、実際の店内の明るさ (026)、実際の陳列と接客 (030)、実際の1階と2階 (027) に戻った版が採用された。026〜032 の記録はドラフト審査待ちなので、この原理は独立の審査で確かめる。
- 店の取り違え (028 の他店名の混入) は、即座に不採用である。

## 3. 失敗しやすいパターン

符号は `principles-v1.json` の `failure_codes` と同じ。根拠は研究記録 (文章) と、既存の `failure-patterns.md`。

- 根拠の種類 (JSON の `evidence_kind`): 記録で見た失敗 (`observed`)、原理の逆から導いたもの (表で「(導出)」)、仮説 (表で「(仮説)」)。
- CP-026〜032 を根拠にした符号 (`GENRE_CLICHE`・`SPLIT_HERO_DEFAULT`・`TOO_CLOSE_TO_REFERENCE`・`ATMOSPHERE_MISMATCH`・`PROP_OVER_PRODUCT`・`TOO_QUIET`) は、ドラフト審査待ちの記録の分析による。
- 20件の外の件 (CP-011・014・015・025・PT-02) は、文章の記録だけで、画像は見ていない。

| 符号 | パターン | 根拠の例 | 見分け方 |
|---|---|---|---|
| `MOTIF_NOT_TRANSLATED` | 店固有のものが写真や色に留まり、構造にならない | (導出) P1 の逆。近い記録: CP-030 v1 は業種の記号に留まった | Hero から主役のモチーフ写真を外しても、構図が成立してしまう |
| `GENRE_CLICHE` | 業種の記号・雰囲気で作る | CP-030 v1 (歯車)、CP-025 v2 | 入れ替えテスト (同業の別の店でも成立する) |
| `HERO_ONLY_WORLD` | Hero だけ強く、下層は別の世界 | CP-011 v1、CP-025 以前 | 区画ごとにモチーフのどの面かを言えない |
| `LOWER_SECTIONS_GENERIC` | 下層が帯・カード・左右交互の繰り返し | CP-023 v5、PT-02 初稿、CP-016 初稿 (既存の成功例に似た骨格) | 構造記述子の `grid_cards` / `split_copy_media` / `stacked_bands` |
| `SPLIT_HERO_DEFAULT` | 理由の無い左右分割の Hero | CP-027 v1、CP-022 の留保 | Hero が `split_copy_media` で、店の事実から来た理由が無い (`GENERIC_SKELETON`) |
| `PC_SP_NOT_DIFFERENTIATED` | SP が PC の縮小・単純な縦積み | (導出) Web PoC の採用版にはない。DEV-083 の指摘 | SP の並び・大きさ・重なりの扱いが PC と同じ |
| `IMAGE_TYPE_RELATION_WEAK` | 写真・図形・文字が別々に置かれ、重ならず関係しない | (仮説) #180 パイロットの実装レーンの制約 (`position: static`) | 文字と写真が区画の境をまたがない。線や注釈が無い |
| `READABLE_BUT_FLAT` | 情報は読めるが、印象が弱い | CP-025 v1「技術的に壊れていないだけ」 | 機械の検査はすべて通るが、記憶に残る所を1つ言えない |
| `NO_PAGE_STORY` | ページ全体の読み順に物語が無い | (導出) 成功例の逆 (P3) | 最後の区画に終点が無い。区画の順が入れ替え可能 |
| `CORE_LOST_IN_REFINEMENT` | 磨いて核を失う | CP-008 v2、CP-017 再生成、CP-014 v2 | 守る核を先に名指ししていない |
| `SURFACE_ONLY_CHANGE` | 色・反射だけを変え、構造は同じ | CP-021 v2 | 改良の前後で構造記述子が同じ |
| `TOO_CLOSE_TO_REFERENCE` | 直前の案や参照に似すぎる | CP-029 v1 (CP-028 に似た)、CP-016 初稿 (「同じような構成になってきた」) | 構造記述子の近さ、比喩の重なり |
| `ATMOSPHERE_MISMATCH` | 実店舗の空気と違う演出 | CP-026 v4 (暗い異国風) | 事実 (店内の明るさ・品揃え) と演出の照合 |
| `PROP_OVER_PRODUCT` | 小道具が商品より目立つ | CP-029 v2 (のれん) | 主役の面積と位置 |
| `OVERCROWDED_INFO` | 情報やカードを足して主役を消す | CP-023 v5 | 追加した区画が主役の面積を減らしていないか |
