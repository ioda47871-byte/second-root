# second-root-design-director スキルの評価 (DEV-133、2026-10-31)

スキル: `.claude/skills/second-root-design-director/`。評価のケースは同じ場所の `evals/` にある
(`claude plugin eval` の形式)。

## 方法

- 架空店舗3つ (月見湯・ひびや継工房・紙縁堂)。事実パックはわざと薄くし、価格・沿革・写真・電話などを
  入れていない (でっち上げの誘惑を作るため)
- 同じ依頼文を、スキルありとスキルなし (依頼文と入力ファイルだけ。リポジトリもスキルも読まない) で
  1回ずつ実行した。どちらも同じモデルのサブエージェント
- 依頼: 方向案2つ (A/B) を、B方式の試作 (`index.html` + `style.css`、画像・スクリプト・外部読み込みなし) で、
  PC1440 と SP390 の両方で作る
- 実モデル (Codex)・画像生成・有料 API は使っていない

採点は2つ。

1. **機械の検査** — リポジトリ自身の検査で採点した (`score-direction-prototypes.mts.txt`、
   SHA-256 `2d1db582…8461e49`)。安全検査 `checkPrototype`、1440/390 の横はみ出し、12px 未満の文字、
   Identity Lock `auditPageText`、構造の計測と兄弟案の類似度・汎用骨格、見える文字のうち事実に無い文。
   結果は `scores-iteration-1.jsonl`
2. **盲検の比較** — 別のエージェントが、どちらがスキルありかを知らずに、24枚の全頁画像と事実パックだけを見て
   6観点 (店らしさ、2案の違い、テンプレートの癖、SP、出来、事実の規律) を 1〜5 で採点した

採点スクリプトはリポジトリの実行コードとしては登録していない (`.txt`)。Identity Lock・構造記述子・
Phase 2f の安全検査は、隔離テストが取り込み元を固定しており、評価の道具のために例外を増やさないためである。
動かすときは、**リポジトリの外** (scratchpad など) へ `.mts` として写し、`../../lib/...` の import を
リポジトリの絶対パスへ書き換えて `npx tsx` で実行する。リポジトリの中 (`scripts/` など) に置くと隔離テストが
落ちる。置いたまま commit しない。隔離テストに例外を足さない。

### スキルありの弱点 (iteration-1 のあと SKILL.md と点検表へ反映)

- 順番の無い4項目に 一〜四 の番号 (ひびや継工房 B) → 既定値チェックに「順番の無い内容の番号」を足した
- PC で大きく空いた面 (月見湯 A、紙縁堂 A、ひびや継工房 B) → 点検表に「意図の無い大きな空白」を足した
- SP で飾りの線が店名に掛かる (ひびや継工房 A) → 点検表に足した
- 短い創作の一行の禁止を SKILL.md に明記した (スキルありでは出ていないが、スキルなしの失敗の型として)

### 費用

スキルありは1件あたり約16〜19万トークン・9〜12分、スキルなしは約9〜10万トークン・3〜4分。
スキルありは参照の読み込み、リポジトリの検査の実行、自己批評の描画に時間を使っている。

## 限界

- 1店1回ずつの小さな評価である。ばらつきは測っていない
- 盲検の審査も同じ系統のモデルであり、オーナーの目の代わりではない。数値の合格はデザインの承認ではない
- スキルありの実行は、スキルの段 7〜8 でリポジトリの検査を自分で回しているので、機械の検査の一部
  (兄弟案の類似度など) は、スキルが検査を知っていることで有利になっている。盲検の比較はその影響を受けない
- iteration-1 のあとの小さな修正 (上の4点) は、再実行で効果を確かめていない
- 実装レーン (Claude による実装と比較) と Codex による生成は、この評価の範囲外である
- 試作・画像・審査の全文はリポジトリに置いていない (作業領域にだけある)。ここにあるのは採点の結果
  (`scores-iteration-1.jsonl`) と採点スクリプトだけで、画像を見直すことはできない
