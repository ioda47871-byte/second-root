## 2. 縦書き: `vertical_text`

### 2.1 文法 (旗のときだけ足す)

| 性質 | 値 |
|---|---|
| `writing-mode` | `horizontal-tb`・`vertical-rl` (`vertical-lr`・`sideways-*` は不可) |
| `text-orientation` | `mixed`・`upright` (`sideways` は不可) |
| `text-combine-upright` | `none`・`all` (`digits <n>` は不可) |

### 2.2 役割

- **縦にしてよい:** 語 (店名でも事実でもない 16 字以下・20px 以上の文字。見出し・巨大な語) と、店名の役割の要素 = **全体の文字が店名 (正式名、または最後の語の短い名: 架空銭湯 ゆげ湯 → ゆげ湯) と等しい要素**。`h1` であるだけでは店名の役割にならない (Fresh Review M1: 最初の版は どの `h1` も通し、`<h1>水曜定休</h1>` が縦で通った)。店名の役割の要素でも、事実を含めば事実が勝つ (`PHASE_D_PROTECTED_VERTICAL`)。
- **縦にしてはいけない:** 守る文字 (事実・免責・dt/dd。店名を除く) — `PHASE_D_PROTECTED_VERTICAL`。17 字以上の文 (`…_LONG_TEXT`)、20px 未満 (`…_SMALL`)。
- **縦の箱は葉 (leaf) だけ。** 子の要素を持てるのは `text-combine-upright: all` の `span` (縦中横) だけ。`html`・`body`、子を持つ縦の箱、縦の箱の中の縦中横でない要素は `PHASE_D_VERTICAL_CONTAINER` (縦の入れ物は中のブロックを右から左の段に並べ替える: 読む順が DOM と変わる)。

### 2.3 危険と検査

| 危険 | 検査 (試作) | コード |
|---|---|---|
| 字の並び (縦の列を下へ、次の列は左へ) が崩れる、字が描かれない | 字ごとの Range の箱の順。縦中横は1字 | `PHASE_D_VERTICAL_ORDER` |
| 字が重なる (列の方向の送りが 0.4em 未満を含む。DEV-102 で見た形) | 箱の重なり > 1px、送り < 0.4em | `PHASE_D_VERTICAL_GLYPH_OVERLAP` |
| 箱からあふれる、切れる | 字の箱が要素の箱の外、要素の scroll の大きさ > client | `PHASE_D_VERTICAL_OVERFLOW` |
| **読む順 (DOM と見た目)。** スクリーンリーダーは DOM の順に読む。縦の語が見た目で前の要素より「上かつ右」に来ると、横の読みでも縦 (右から左) の読みでも先に読まれる | **縦の根のそれぞれを、DOM でその前とその後のすべての文字の要素と**比べ、DOM で後のものが前のものより上 (4px) かつ全体が右なら落とす (Fresh Review M3: 最初の版は DOM で隣り合う組だけで、間に小さな札 `<p>印</p>` を挟むと逆転が見えなくなった)。**縦にしたことで生じた逆転だけを数える:** 同じ組を縦の要素を横に戻して測り直し、横でもう逆転しているもの (ジグザグの配置。V9 の範囲) は数えない | `PHASE_D_READING_ORDER` |
| 字が横倒しで描かれる (ラテン文字の `mixed`、どの字でも `sideways`) | 縦の要素の自分の文字にラテン文字があり `upright` でない、または計算値の `text-orientation` が `sideways` (かな漢字も。Fresh Review L1) | `PHASE_D_VERTICAL_SIDEWAYS` |
| 数字が1字ずつ縦に並ぶ (12 が 1 と 2 に) | 縦中横でない2字以上の数字 | `PHASE_D_VERTICAL_DIGITS` |
| 縦中横に長い文字 (15:00 が潰れる) | 縦中横は ASCII の英数字 2 字まで | `PHASE_D_COMBINE_TEXT` |
| `vertical-lr` (左から右の段) | 計算値が `vertical-rl` でない | `PHASE_D_VERTICAL_MODE` |
| SP の幅 | 1px の掃引 320〜1920 で上のすべてと横のはみ出しを見る | `PHASE_D_HORIZONTAL_SCROLL` |
| 書体の差 (縦の字形・代わりの書体) | 字の並び・重なり・あふれは、その機械で描いた Range の箱で測る (数字を書かない)。3店は strict を同じ機械で測って比べる | — |
| 段 C との関係 | 段 C の縦の字形の箱は「Range の箱を 1.3em に切ったもの」で、短い字の箱は fail closed (`GLYPHS_UNMEASURED`)。縦の墨は段 C も段 D も測っていない (§9) | — |

### 2.4 見つけたこと

- **縦の入れ子の span は Chromium が inline-block にする。** 横の行の中の縦の語 (`<p>ここに<span class="v">縦の語</span>がある</p>`) は計算値の `display` が `inline-block` になり、行の中で立った語として描かれる。読む順は DOM と同じなので通す (通るべき例)。最初は「インラインの縦」を落とす予定だった。
- **縦の字は書体に強く依る (CI に近い書体で見つけた、本物の描き崩れ)。** 3店の 明朝 の指定 (`"IPAMincho", serif`) のまま縦にすると、IPAMincho の無い書体の組 (`fonts-ci.conf`) では `serif` がラテン文字の書体に解決され、縦の かな漢字 が列の足もとに横向きに積み重なって描かれた (Claude が画像で見た。割れ の 割 の Range の箱は高さ 0)。検査は `PHASE_D_VERTICAL_GLYPH_OVERLAP`・`_OVERFLOW` で止めた (つぐ手の全幅)。この容器の書体では起きない。**縦の語の書体の並びに、どの機械にもある縦の CJK の書体 (IPAGothic) を `serif` の前に入れた** (`VERTICAL_FACES`)。本番では書体を固定する能力 (`web_font`、段 B の判断) と一緒に決める必要がある (オーナーの判断 10)。
- **縦の店名 ゆげ湯 は `vertical_name` では通らない。** `vertical_name` は「全体が店名 (架空銭湯 ゆげ湯) の要素」だけを縦にしてよい。h1 の短い名前は `VERTICAL_NOT_NAME`。提案は h1 も店名の役割に含める (オーナーの判断 3)。

## 3. 小さな回転: `small_rotation`

### 3.1 文法

| 性質 | 値 |
|---|---|
| `transform` | `none`、または `rotate(<角度>)` を1つだけ。角度は `deg` で |±8| 以下 (または `0`)。`turn`・`rad`・`grad`・`calc()`・2つ以上の関数・`translate`・`scale`・`skew`・`matrix`・`rotateZ`・3D は不可 |
| `transform-origin` | 方向の語 (`center`・`top`・`bottom`・`left`・`right`) と 0〜100% を 1〜2 個 |
| 個別の `rotate`・`translate`・`scale` | 不可 |

### 3.2 役割

- **回してよい:** 文字を持たない箱 (画像・装飾) と、語 (守る文字でない・12 字以下・24px 以上)。
- **回してはいけない:** 守る文字を中に持つ箱 (店名も。`PHASE_D_PROTECTED_ROTATED`)、それ以外の読む文字 (`PHASE_D_ROTATED_TEXT`)。C′ の「札を持つ板を回す」は落ちる (§7.3)。

### 3.3 危険と検査

| 危険 | 検査 (試作) | コード |
|---|---|---|
| 回転以外の変形が紛れる (計算値は行列) | 計算値の行列が純粋な回転でなければ (個別の性質を含む) 落とす (fail closed) | `PHASE_D_ROTATION_UNMEASURED` |
| 入れ子で角度が足される (6° の中の 6°) | 自分と祖先の角度の和も ≤ 8° | `PHASE_D_ROTATION_ANGLE` |
| **大きな箱は小さな角度でも端が大きく振れる** (幅 700px の帯を 4° で端が 24px 以上) | 変形を外して測った広がりから、回した広がりが 24px を超えて出ない。**広がり = 罫の箱 ∪ 子孫の箱 ∪ 中の文字の字の箱** (回したものと外したもの。再レビュー L1: 高さ 0 の箱の中の文字のない 800px の子が約 110px 振れて左の外へ出ても、文字だけを見ていた版は何も出さなかった。Fresh Review M2: 最初の版は罫の箱だけで、高さ 0 の幅 64px の箱からあふれた 12 字の語を 8° 回すと字が約 107px 振れて画面の左の外へ出ても何も出さなかった) | `PHASE_D_ROTATION_REACH` |
| 画面の横の外へ出る (SP) | 回していない広がりが中にあり、回した広がりが外へ出る (もともと外にある箱はレイアウトのはみ出しで、`HORIZONTAL_SCROLL` と strict の側の問題) | `PHASE_D_ROTATED_OFFSCREEN`、`PHASE_D_HORIZONTAL_SCROLL` |
| 切り抜く祖先で語が切れる | 回した文字の広がりが、`overflow` が見える以外の祖先の padding box の外 | `PHASE_D_ROTATED_CLIPPED` |
| **当たり判定と字形の箱。** 回した文字の Range の箱は、回した字の箱の外接矩形である (墨より大きい)。段 C の墨の箱は canvas の墨を回さずに置くので、回した墨を含まない (段 C の画素の検査が `PIXEL_INK_OUTSIDE_GLYPHS` を出す: テストで確かめた。段 C は fail closed で止まる) | 回した語は「墨の対象」: 外接矩形が別の文字の箱に届くなら、画素で墨を測る (§3.4)。画素なしでは `PHASE_D_INK_UNPROVEN` (fail closed) | `PHASE_D_INK_UNPROVEN`、`PHASE_D_INK_ON_TEXT` |
| 回した文字を持たない箱が文字に届く (重ねの文脈を作る: 段 C の領分) | 段 C の検査がそのまま裁く (回した箱は逆行列で当たり判定)。例: 事実の上を通る 4° の棒は段 D では 0、段 C で `OVERLAP_PAINT_ABOVE_PROTECTED` | 段 C のコード |
| 縦の字の順を回転の下で測ると、外接矩形が重なりずれる | 縦の検査と読む順は、変形をすべて外したレイアウトで測る (回転は剛体で小さい) | — |

### 3.4 墨の測り方 (画素、回転と縁取りで共通)

対象 (回した語・縁取りの語) ごとに、その外接矩形 +12px を3枚撮る。X: 対象の文字だけを描く。G: 文字を何も描かない。O: 対象以外の文字を描く。地・画像・箱はそのまま。対象の墨は X と G の差 (チャンネルの最大 ≥ 24)、ほかの文字の墨は O と G の差。**その機械で描いたものを測るので、書体に依らない** (数字を書かない)。

- 対象の墨 (1px 広げる) とほかの文字の墨が 3 画素以上で接する: `PHASE_D_INK_ON_TEXT`。
- **縁取りのあるすべての要素がそれぞれ1つの対象** (回した語の中の一部でも、入れ子の子でも)。**1つの縁取りの測りは、その要素自身の文字の節 (直の子の文字) だけを見る:** X の絵はその要素の文字だけを描き、子孫の文字は縁取りがあってもなくてもすべて消す。縁取りのある子孫は、それぞれ自分の対象として別に測る。広がりも自分の文字の箱だけ。(根の直し。混ざった測りが3回続いた: Fresh Review H1 は回した語を「回転」の対象としてだけ測り、再レビュー M1 は回した語を1つの対象にして縁取りのある部分と無い部分を混ぜ、3回目の再レビュー M1 は親の測りに縁取りを受け継いだ見える子を描いて親の見えない文字を隠していた): 墨の画素ごとに X と G の WCAG のコントラストを出し、**上位 4 分の 1 の画素が届くコントラスト** < 3 で `PHASE_D_OUTLINE_LOW_CONTRAST`、墨が 20 画素未満で `PHASE_D_OUTLINE_INVISIBLE` (§4)。
- **同じ語の残りはほかの文字ではない (3回目の再レビュー L1):** 縁取りの対象の「語」 = その要素から inline の祖先をたどって、まだ語 (守る文字でない・12 字以下・24px 以上) である一番外の要素。語の中のほかの字は、`near` (掃引の fail closed) にも O の絵 (`INK_ON_TEXT`) にも数えない (最初の版は、一字だけ縁取った回した語が、隣の字に対して全幅で `INK_UNPROVEN` になった)。語の外の文字は今までどおり数える。ブロックの祖先へは上らない (2つの段落を1つの語と数えない)。
- **色の固定の順 (再レビュー M1 で見つけた道具の誤り):** 文字の色を固定する前に、すべての文字の元の色を先に読む。塗りと縁の色は受け継がれるので、親を先に固定すると子は親の固定した色を元の色として読んでいた (透明な塗りの子が濃い塗りで描かれ、見えない縁取りが見えると測られた)。
- 1px の掃引では画素を撮らない (確かめる幅だけ)。掃引では、外接矩形が別の文字に届く対象は `PHASE_D_INK_UNPROVEN` で落ちる (fail closed)。だから 3店の版は、回した語・縁取りの語の外接矩形が全幅で別の文字に届かないように作った。

## 4. 縁取りの文字: `outlined_type`

### 4.1 文法

| 性質 | 値 |
|---|---|
| `-webkit-text-stroke-width` | 0.5〜3px |
| `-webkit-text-stroke-color` | 不透明な色 (#rgb・#rrggbb・white・black・アルファの無い rgb())。`transparent`・`currentcolor`・アルファ・`var()` は不可 |
| `-webkit-text-stroke` | 上の幅と色 (順不同) |
| `paint-order` | `normal`・`stroke`・`stroke fill` |

**入れないもの:** `-webkit-text-fill-color` (塗りは `color` だけで決める)、`text-shadow` (影を4つ重ねる縁取り。当たり判定に出ない描き方で、段 C は `ORDER_UNPROVEN` で落とす)、SVG の文字。

### 4.2 役割

- **縁取ってよい:** 語 (守る文字でない・12 字以下・24px 以上)。
- **縁取ってはいけない:** 守る文字 (`PHASE_D_PROTECTED_STROKED`)、読む文字・小さな文字 (`PHASE_D_STROKE_ON_TEXT`)。**縁取りは受け継がれる** (`-webkit-text-stroke-width` は継承する性質) ので、箱に掛けた縁取りが中の事実に届く形を描画の計算値で止める (落ちるべき例)。

### 4.3 危険と検査

| 危険 | 検査 | コード |
|---|---|---|

## 4.5 守る文字の判定 (3つの機能で共通)

- 守る文字: 守る選択子 (dt・dd・h1・免責) の中、要素の文字の全体が事実を含む、6 字以上で事実の一部、**または、その文字の節が、要素をまたいで書かれた事実の出現と重なる** (4回目の再レビュー H1)。
- 最後の形は文字の位置で測る (`overlap-harness.ts` の `FACT_NODES_JS`、段 C と共通): **body の文字の節を DOM の順に1本につなぎ**、元の1字ごとに正規化した字 (NFKD、結合記号・書式文字 (Cf: ゼロ幅スペース・ソフトハイフン …)・空白を落とす) とその持ち主の節を覚える。各事実も同じく正規化し、1本の文字の上のすべての出現について、出現と重なる字の持ち主の節を守る。短い文字がたまたま別の所に現れても、その出現に重ならなければ守らない (事実のすぐ後の飾りの語は通る: 通るべき例)。
- **紛らわしい字を1つの形に寄せる (DEV-178、DEV-175 のレビューの Low)。** U+2010〜2015 (ハイフン・ダッシュの類)・U+2212 (負の記号)・U+30FC (長音) を `-` に、U+FF5E (全角のチルダ)・U+301C (波ダッシュ) を `〜` に寄せる。ページの文字と事実の両側に、1字を1字へ、NFKD の前と後の両方で掛ける (NFKD は U+FF5E を `~` に変えるので、前に掛けないと寄せられない)。1字が1字になるので、出力の字の持ち主の節は元の字の節のままである。例: `000‐0000‐<span>0712</span>` (U+2010) と `10:00～<span>16:00</span>` (U+FF5E) の末尾を縁取ると、守る文字として落ちる (段 D の例 2 つ。段 C にも U+2010 の例 1 つ)。
- **ブロックをまたいで照らすこと、結合記号を落とすこと (が と か を同じに読む)、紛らわしい字を寄せることは、守る文字を増やす向きだけ**である (fail closed)。事実のハイフンでないダッシュや長音が事実の `-` に当たって守られることはありうる。
- 経緯: 最初の版は要素自身の文字だけで判定し、`000-0000-<span>0712</span>` の縁取り・`水曜・<span>木曜</span>` の回転と縦を通していた (4回目の再レビュー H1)。次の版は一番近い inline でない祖先ごとにつないだので、ブロックになる flex・grid の項目や2つの段落に分かれた事実を通し、全角の数字やゼロ幅スペースで事実の照らし合わせそのものが外れた (5回目の再レビュー H1・L1)。段 C の試作も同じ道具を使う (段 C の設計 §2)。

## 9. 証明していないこと

- **縦の墨。** 縦の字は Range の箱で測る (書体の content area)。縦の字形の墨の外へのはみ出し (大きな字の飛び出し) は見ない。段 C も同じ穴を持つ。
- **回した縦の字の並び。** 字の並びは回転を外したレイアウトで測る。8° までの剛体の回転は順を変えないという前提で、回した後の見た目の順は確かめていない。
- **読む順の網羅。** 読む順の検査は「縦の根と、DOM でその前後のすべての文字の要素」の組で「上かつ全体が右」の形だけ。縦を含まない組の順、段組み・グリッドの全体の順 (V9)、「上だが右ではない」形 (左上へ戻る) は見ない。スクリーンリーダーで実際に読ませてはいない。`aria-hidden` の語は今の run が拒む (`TEXT_ARIA_HIDDEN`) ので、縦の語も読まれる。
- **画素のコントラストの尺度。** 「墨の上位 4 分の 1 の画素が届くコントラスト ≥ 3」は、太い字では塗りの中心、細い縁では縁の芯の色を測る。字の太さ・縁の細さそのもの (読めるか) は測らない。中抜きの最小 1.5px と縁の 0.06em が代わりの決まりである。
- **画素は確かめる幅だけ。** 1px の掃引の間では、墨は外接矩形の fail closed (`INK_UNPROVEN`) に任せる。
- **段 C との組の網羅。** 回した文字を持たない箱は段 C が裁くこと、縁取りの墨が段 C で見えないことは例で確かめたが、段 C と段 D を同時に ON にした検査の組み立ては作っていない (段 C の glyph の箱を段 D の墨で置き換えるのは本番の PR の仕事)。
- **1920 より広い幅、320 より狭い幅、整数でない幅、900 以外の窓の高さ、拡大率、Chromium 1194 以外の描画系。** 縦の要素の利用できる高さは窓の高さに依る (直交する流れ) が、高さを変えて確かめていない。
- **3店以外のページ。** 合成の例と3店だけである。

## 10. 書体

- 3店のテストは strict を同じ機械で毎回測って比べ、幅・文字の一覧を書かない。合成の例は IPAGothic を名指しし、書体に依る隙間はその機械の墨から作る。
- この容器の書体と、CI に近い書体の組 (`scratchpad/dev173/fonts-ci.conf` を `FONTCONFIG_FILE` に。IPAMincho と Noto Sans CJK の無い組) の両方で、テスト全体を走らせた (数はレビューの記録 `.ai/reviews/DEV-175.md`)。
- §7.2 の帯 (686〜691px・870〜878px・1290〜1294px) と strict のはみ出し (つぐ手 601〜1128、輪 320〜369・601〜1399、ゆげ湯 601〜1289) はこの容器の書体での値で、書体で動きうる (テストには書いていない)。

## 11. 危険

- **役割の判定は文字の長さと大きさに頼る。** 「12 字以下・24px 以上」は語の近似で、短い事実 (例: 水曜) は事実の一覧 (facts pack) で守る。一覧に無い大事な短い語は守られない。
- **画素の測り方は文字の色を差し替える。** 対象の文字の色を inline の `!important` で固定し、ほかを透明にする。`currentcolor` の罫など、文字の色に依る描き物は3枚の間で変わる (墨の誤った数え) ので、本番では文字の色だけを変える別の方法 (段 C の `TEXT_INK` と同じ) と照らす必要がある。
- **縁取りはベンダー接頭辞の性質である。** 本番の許可一覧の「接頭辞は通さない」の例外になる。
- **費用:** 1px の掃引は 3店の版 1 ページ 約 15〜30 秒 (この容器)。画素は対象ごとに 3 枚の切り抜き。ファイル全体で約 7〜14 分 (負荷による)。CI では時間に敏感なテスト (`guardrails`・`browser.test.ts`) と同じ組で並び、最初の版の CI でその2件が落ちた。Chromium の起動とページの使い回しで確かめる幅の CPU を 36% 減らしたが、掃引 (1幅ずつの順の仕事) の CPU は変わらない。本番では掃引を run の段に入れる前に、時間の予算と並べ方を決める必要がある。

## 12. オーナーの判断が要ること

>
> 1. 3つを別々の能力 (`vertical_text`・`small_rotation`・`outlined_type`) として、それぞれ §8 の lib の PR に進むか。どれを先にするか (どれもしないか)。merge は改めて明示の承認の後。

> 3. 店名の縦: `vertical_name` の「全体が正式名の要素」から、短い名 (最後の語) の要素まで広げるか (ゆげ湯の版は今の `vertical_name` では `VERTICAL_NOT_NAME`)。試作は `h1` であることを店名の役割の条件にしない。
> 4. 回転の上限: 角度 8° と振れ 24px。大きな語は振れの上限で 1〜2° になる。
> 5. 回転の作る重ねの文脈を `STACKING_CONTEXT` で数えないこと (段 C の判断 2 と同じ形。描画の門を狭める)。段 C より先に段 D の回転だけを ON にするなら、回した箱が文字に届くかを裁く段 C の検査が要る。

> 10. 縦書きの書体: 縦の語の書体の並びに、どの機械にもある縦の CJK の書体を必ず含めることを規則にするか (`web_font` で書体を固定するまでの代わり)。今の試作は描き崩れを検査で止めるだけである。
