# 店舗固有の Design DNA の提案（DEV-107）

**状態: AI の提案。オーナーの判断待ち。** 画像生成・Codex・worker・DB には接続していない。参考サイトの記録は pending のまま。

## 仕組み

1. **店舗の分析（Claude）:** fixture の事実から、店舗の特徴を「逐語の引用」として書き出す（`traits`）。
   種類は、名前・店の性格、商品、看板商品、つくり方のこだわり、実用の事実、商品の属性、注文の流れ、予約手段。
   プレースホルダー（`テスト` で始まる品名。`テスト` を外した部分も不可）と「架空の店です」の断り書きの文は特徴にできない。
   「看板商品」「こだわり」「商品の属性」「注文の流れ」は、品名の一覧ではなく店自身の説明文からしか引けない。
   それでも種類の付け方は分析側の主張であり、オーナーが確認する。
2. **技法の適格判定（コード）:** `lib/design-agent/design-image/shop-proposals.ts` の `techniqueEligibility` は、
   特徴だけから「この店で使える技法と変形」を決める。**業種や category は読まない**（test で業種を入れ替えても結果が同じことを固定）。
   - オーナーの判断（2026-10-25）を反映: T3・T4・T8 は採用、T1・T2・T5・T6・T7 は条件付き。
   - 条件の例: T4 はこだわりの事実が2つ以上、T2 は種類の違う実用の事実が2つ以上、T8 は看板商品の事実が1つ以上。
   - T1 は予約手段の事実が要る。今の入力項目（`DESIGN_FACT_KEYS`）には予約の欄が無く、説明文に予約制と書かれた店だけが対象になる。
     どちらの fixture にも無いため、今は使えない（入力欄の追加が要る）。
   - 未承認の変形は拒否: T1 の固定バー、T7 の波形・切り欠き（clip-path）、T3 の営業日カレンダー（入力欄が無い）、店名以外の縦書き。
3. **案の作成（Claude）:** 店ごとに2案。各案は使う技法（最大4）と理由、使える技法を使わない理由、8つの設計項目を持つ。
4. **検証（コード）:**
   - 引用が事実に実在すること。技法の条件を、引用した特徴が満たすこと。
   - CSS は今の許可表（`page-css.ts`）の範囲だけであること。
   - コントラストを計算で確かめる: 文字色はすべての地色と帯に対して 4.5 以上、強調色は 3 以上、帯は地色と 1.2 以上の差。
   - 選択の文章も句ごとに読む（英語と日本語）: 固定表示・clip-path や波形・縦書き・カルーセルやアニメーション、画像なしの案での写真、
     事実に無い価格・予約・通販を書いた句は拒否する。否定は、語のすぐ前（3語以内の no / not / without 等）か
     すぐ後（固定しない等）にあるときだけ認める。これは語句による選別で、文意の理解ではない。オーナーがすべての選択を読む。
   - 実装の状態が、使う機能から導かれる値と一致すること。
   - 2案の技法の組が違うこと。
   - 各案を既存の Design DNA 形式（`design-dna.ts`）に変換して検査し、2案同士・他店の案・既存の brief と、8項目の選択文が同じ文でないこと
     （同じ文の使い回しの検出で、言い換えは検出しない）。
   - 許可される CSS の名前（`ALLOWED_CSS` / `REFUSED_CSS`）は `page-css.ts` の許可表を手で写したもので、許可表が変われば合わせて直す。

これは「業種のテンプレート」ではなく「事実が許す技法の中から、その店の性格に合うものを選ぶ」仕組みである。
同じ技法でも、根拠の事実と形が店ごとに変わる（例: T7 の形は、和菓子店では「小さな店頭」から、パン屋では店名の二語から）。

## 店ごとの適格な技法

| | 和菓子店（架空菓庵） | パン屋（Boulangerie Pâtisserie Exemple） |
|---|---|---|
| 事実の量 | 多い（説明文・営業時間・定休日・アクセス・電話） | 少ない（名前・住所・営業時間。品名2つはプレースホルダー） |
| 使える技法 | T2・T3・T4・T7・T8 | T3・T7 だけ |
| 使えない理由 | T1: 予約手段の事実が無い。T5: 商品の属性が無い。T6: 注文の流れが無い | 上に加え T2: 実用の事実が営業時間だけ。T4: こだわりの記述が無い。T8: 看板商品を示す事実が無い |

パン屋は事実が少ないため、技法を無理に増やさず、店名・営業時間・区名だけから設計した（品名は `テスト` 付きのプレースホルダーなので使わない）。
事実が増えれば使える技法も増える。

## AI の所見（オーナーの判断の材料）

- **最も今すぐ作れて安全なのは 和菓子 B。** 画像も未承認の機能も要らない。ただし雰囲気は弱い。
- **最も店の性格が出るのは 和菓子 A。** ただし AI コンセプト画像1枚の承認が前提。
- **パン屋は事実が足りない。** 品名もプレースホルダーで、どちらの案も商品を出せない。成立はするが短く個性が弱い。
  品質を上げる一番の近道は、デザインではなく事実（実際の品名、説明文、看板商品、こだわり）を増やすこと。
- **作れない既存案の発見:** 既存のパン屋の brief は、今の CSS では書けない疑似要素と「sticky 風」の見出しを前提にしていた。新しい検証では、こうした案は作る前に止まる。
