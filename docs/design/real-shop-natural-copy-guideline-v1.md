# 実店舗デモの自然な文章レビュー v1（人間向け補助基準）

> Issue #263・#258。これは**既存の `copy_quality_review_v1` や送信ガードを置き換えない**。オーナーが実店舗のページを読む際に、AI的で汎用的な言い回しを減らし、店ごとの情報を自然に伝えるためのレビュー補助。特定店舗の本文・事実・連絡先は公開リポジトリに保存しない。

## 目的と優先順位

読者が実際に知りたいのは「何のお店か／どんな商品・サービスか／何が特徴か／どこにあり、来店前に何を確認すればよいか」。デザインを引き立てる文章は、それらを**簡潔に、間違いなく**伝える。

優先順位は、**事実と権利の正確さ > 分かりやすさ > 店舗固有性 > 読み心地 > キャッチコピーの美しさ**。事実が足りないとき、コピーの巧さで埋めない。

## 文章作成のルール

1. **「店を入れ替えても成立する言葉」を主文にしない。** 「特別なひととき」「小さなご褒美」「想いを込めて」のような表現は、店固有の具体的な情報を伴わない限り削るか減らす。単語だけの禁止リストではなく、文章の役割と文脈で判定する。
2. **最初の一画面で何の店かが分かる。** 店名、業種、確定した代表商品/サービス、地域のうち、事実として裏付けた項目を自然に示す。
3. **見出しは説明に使える言葉でよい。** 奇をてらった詩的な見出しを連続させない。「どんな商品？」「店舗案内」など普通の言葉を選んでよい。強いキャッチはHeroの1箇所に絞ってもよい。
4. **事実は正確に、提案は提案のままに。** 実店舗の `comp_copy_v1` は `lane: real_shop_proposal`。裏付けのある `fact` はfacts packの原文/規定の単位を用い、コピーの言い回しは `proposal_pending_review` にする。店舗の言葉に見せない。最終の文章承認はオーナーが行う。
5. **価格・時間・休業日・原材料・人・人気・歴史・効果・商品ラインナップは推測で書かない。** 事実の出典、確認日、適用時点を持つ。過去のイベント掲載商品は「現在の店頭販売品」へすり替えない。営業時間が食い違うなら固定掲載を避け、確定まで止める。
6. **文章の長さに役割を持たせる。** Heroは短く、Aboutは1〜3文、商品は名称と特徴、アクセスは具体的な情報を優先。各セクション冒頭を「名詞止め→詩的な一行」で機械的に揃えない。
7. **語り口を混ぜすぎない。** 客への案内として、過度なポエム、営業トーク、妙な英日混合、断定・誇張、同じ語尾・同じ句読法の連続を避ける。英語は情報構造やタイポグラフィに使ってもよいが、日本語の意味を曖昧にしない。
8. **写真や装飾に未確認の事実を代弁させない。** AI生成の食べ物・包装・内装を「店が提供する実物」の写真のように見せない。写真の使用許可は別の権利審査。写真のない版でも情報の魅力が分かる構成を検討する。

## 比較例（下記はすべて一般的な架空の例。実店舗の事実ではない）

| 情報が伝わりにくい例 | 方向性の例 | 判断ポイント |
|---|---|---|
| 「いつもの日常に、小さな幸せを。」 | 「焼き菓子とコーヒーのお店。」 | 何を扱うかを先に伝える（実際に提供する場合のみ） |
| 「ひと口ごとに、想いを紡ぐ。」 | 「カヌレやクッキーを紹介します。」 | 提供する商品が事実確認できた場合だけ名前を出す |
| 「一杯の物語が、ここからはじまる。」 | 「ドリンクについて」 | 見出しを無理に詩的にしない |
| 「あなたの暮らしに寄り添う場所。」 | 「アクセス・営業時間」 | 来店判断を助ける情報を優先する |
| 「こだわりの厳選素材を、毎朝職人が。」 | **裏付けがないなら全文削除** | 事実の新規生成を禁止する |
| 「人気No.1の商品を今だけ。」 | **検証できないなら全文削除** | 実績・人気・在庫/期間の主張は最も危険 |

## オーナー向けの目視レビュー（各項目 Yes / No / 要修正）

- [ ] Heroを5秒見て店名・主な提供内容が分かる。
- [ ] この店以外でも使えるだけの抽象文が、Hero/見出し/本文を支配していない。
- [ ] 重要な商品の名前や特徴が、確認済みの事実に根拠を持つ。事実の改変や未知情報の創作がない。
- [ ] 来店・問い合わせの判断に必要な情報が分かる。未確認情報は正確な値を装わない。
- [ ] 同じ調子の短文、体言止め、詩的な見出しを各セクションで反復していない。
- [ ] 店の人が読んでも「自分たちが言ったことにされている」と誤解しない。
- [ ] PC 1440 / SP 390の全ページを読み、改行で語句が不自然になっていない。
- [ ] 写真・画像・alt文が事実や権利を誤認させない。

上のどれかにNoがあれば文と構成を修正。**ただし見た目のために事実を追加しない**。判断がつかない場合はholdし、未確認事項と責任者を記録する。

## 既存の機械的検証との関係

- `docs/design/comp-lane.md` に従って、見えるすべての語句を `copy.json` に載せる。CSSの表示文字・未記録テキストを使って抜け道を作らない。
- `comp-copy --audit` の `COPY_APPROVAL_MISSING` 等は意図どおり扱う。実店舗 `real_shop_proposal` の自然な文章を機械的に「店の公式な言葉」と認定することはできない。
- `hold` / `fail` や `COPY_FACT_UNSUPPORTED` を「見た目が良いから」と回避しない。
- この基準は**成功例テンプレートではない**。サイトごとに店の固有性、画面構成、語り口を選び直す。自然な文体が生まれた経緯は記録してよいが、同じ見出しを各店舗に使い回さない。

## 承認・運用境界

本書の追加は、実店舗のfacts承認、画像利用許可、共有フラグの有効化、本番migration、実際の営業送信を承認しない。顧客の文章・写真は別途審査し、オーナーが明示的に承認した版のみ共有・送信する。
