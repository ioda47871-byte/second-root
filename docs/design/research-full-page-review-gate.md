# Second Root｜Heroだけではなく全ページで評価するための研究ゲート

**根拠:** 2026-10-28 CP-024（Boheme.）へのオーナー指摘「いいと思いますが全体像がさっきからなくないですか？」。CP-020〜024では美しいHero画像だけで各研究の評価を求めており、ページ全体の構造が隠れていた。**今後の新規研究で、Heroの高評価だけを「Webサイト全体が完成」と扱わない。**

## 評価は2段階に区別する

| 段階 | 必要資料 | 選定と記録 |
| --- | --- | --- |
| 1. **Hero方向の評価** | 店舗事実、Identity Lock、静止Hero画像、構図の選定理由、過去作との差分 | ユーザーがHeroを好評価なら「Hero優先参照案」。明示的に成功例採用と言われた場合も、成功したのは**静止コンセプト**であり完成Webではない |
| 2. **全ページの評価** | **PC全体像、スマホ全体像、Heroの次の情報構造・店舗に行く導線、必要なら操作可能なHTML** | ユーザーが全体を評価。Hero画像と全ページ版を別バージョン・別SHAで保持し、未評価の下層を勝手に成功認定しない |

## 全ページ初稿の最低チェック

1. **構造:** Hero／店舗の哲学・特徴／独自の体験または商品説明／実在・確認可能な店舗情報／適切な問い合わせ導線を、**店舗に固有の読み順**でつなぐ。普通の写真帯や3枚カードを足すだけでは構造検証不合格。
2. **一貫性:** 主役の装飾が下層のグリッド・文字・インタラクションに続いているか。よかったHeroは原本を保持し、むやみに全面再生成しない。
3. **閲覧性:** PC/スマホの実際の下層まで見せる。横はみ出し、文字崩れ、操作、表示品質を可能な環境で確認。ローカル検証と本番の違いを明記。
4. **事実・権利:** AI生成画像は実店舗写真として扱わない。本人の公式サイト/ECが検索未発見でもSNSプロフィール外部リンク未確認なら営業候補HOLD。価格、営業時間、正式メニュー、住所、店内写真、キャンペーンは確認できる情報だけ使用。
5. **成功登録:** 明示的なユーザー承認の対象が「Hero」「全体静止デザイン」「ローカルWeb試作」のどれか記録。静止画をWeb完成と誤集計しない。

この文書は研究用ゲート。既存成功事例を遡及取り消さない。営業AI/ワーカーの本番コード変更や自動化への自動適用は行わない。

## 2026-10-28｜全案件の標準納品フォーマットに固定

**ユーザーからの明示的な恒久方針:** Boheme.のPC/スマホ全ページ比較、下層画面、ブラウザ操作可能なHTMLを提示したあと、ユーザーが**「いいじゃん毎回これで出して」**と指示。**CP-025以降、これを新規研究デザインのデフォルト提出形式として必須化**する。店舗ごとの独創的な表現は維持し、Boheme.の花のラック等の具体的なデザインはテンプレート複製しない。

### 毎回の納品物（必須）

1. **PCフルページスクリーンショット**：Heroだけでなく、下層構造・Story/Concept・店固有の体験・実在確認済み店舗情報・フッターまで見せる。少なくとも1枚で全ページの縦の流れが確認できるようにする。
2. **スマホフルページスクリーンショット**：PC画像を単純縮小するだけでなく、読み順、写真の切り抜き、タップ領域、余白がスマホ用に設計されていること。
3. **PC/スマホ俯瞰比較画像**：2つを同じ場で比較できるサマリー。必要に応じて下層の見せ場の接写・操作状態も追加。
4. **実際に開けるHTML/CSS/JS Web試作**：読める独立テキスト、ナビ、動作する必要最小限のUIを備える。単なる静止画像に「操作可能」と表示しない。元Heroの文字が画像焼き込み等の未完成要素は明記。
5. **再現に必要な元画像・HTML・画面画像・操作/テスト結果をまとめたZIP**：GitHubへは原則メタデータ/照合値のみ。ユーザーが確実に開ける形で会話へ添付する（実ファイル存在とリンク検証）。
6. **品質検証**：PC/スマホ複数幅の表示、予期せぬ横スクロール、リンク先、画像読み込み、JS例外、主要操作、Webサイトとして情報が最後まで繋がるか。ChromiumのみならChromiumのみと明記。実ブラウザ/実機/公開まで検証したと誤認させない。
7. **資料の性質の明記**：本人が確認した事実とAI創作画像の区別、「Webが検索未発見」と「サイトが存在しない」の区別、本人の発注/素材許諾/営業対象の確定/本番公開の有無。研究成功への採用はユーザーの指定を待つ。

**順番：** 店舗とWebサイト有無の調査 → 過去成功例との構造差チェック → Hero/ページ構造の設計 → 一貫した下層までHTML構築 → PC/スマホ全体のブラウザ画像を出力/比較 → 検証 → 画像・操作できる試作・ZIPをセットで提示 → ユーザー評価。工程途中にHeroを相談することはできるが、**最終提示をHero画像1枚で終えてはいけない**。

**実現できない項目がある場合：** 代替で作成した成果物と欠けた項目を明確に説明し、全ページ完成と主張しない。静止画像の成功例とHTML研究PoCの成功例は別集計を継続する。

**研究方針の確定 ≠ 研究成功例CP-024の自動採用。** 「毎回これで出して」は提出形式への承認であるため、デザインの明示的な成功登録指示があるまで成功カウントは22件のまま。
