# 品質優先パイプラインの現状監査 (DEV-154、Issue #193 の納品物 1)

2026-11-02。develop `705b415` を起点に、既存コード・研究台帳・成功例の画像の状態を監査した。
**この文書は監査だけで、品質を上げたとは主張しない。**
実 Codex・画像生成・有料 API・実機の操作はしていない。

## 0. 結論 (先に)

1. **Claude が実際に見られる成功例の画像は、3件の「登録 WebP」だけである** (CP-001・002・003)。
   - 登録 WebP は、原本 PNG から閲覧用に作った派生物である (`CP-001-Mond.md`「PNG を、閲覧用 WebP に変換」)。
   - SHA-256 は、manifest の `webp_sha256` / `mobile_webp_sha256` と一致した。原本 PNG の SHA (`original_png_sha256`) とは別のものである。
   - **原本 PNG そのものは、どの件もリポジトリに無い。**
   - CP-009・CP-016 を含む20件は、SHA-256 の記録だけがあり、バイトはオーナーの ChatGPT の会話アーカイブにある。
   - CP-026〜032 の7件は、画像の SHA-256 も無い。
   - 一覧は `design-library/research/quality-pipeline/originals-inventory.json` にある (機械で作り、テストで固定)。
2. **リポジトリは public である。**
   - 権利が確認できていない原本 (実在の店名、AI の写真) を commit すると、外へ公開することになる。Issue #193 §3 が禁じている。
   - この研究では原本をリポジトリに入れない。受け取った原本は manifest の SHA-256 と照らし、残すのは導いた記録だけ (SHA・測った特徴・座標つきの観察)。
   - テストが、manifest に記録されたどの SHA (原本・会話側の閲覧用 WebP・アーカイブ・HTML) と同じファイルも追跡されていないことを確かめる。例外は、manifest が自分でリポジトリに登録した4つの WebP だけである。受け取りの置き場 `design-library/research/quality-pipeline/.intake/` は `.gitignore` にした。
   - なお、CP-001〜003 の登録 WebP (AI の写真を含む) は、この PR より前から public である。
3. **仮説:** #180 のパイロットと成功例の差は、主に3つの制約から来ている。
   - **これは仮説である。** 成功例の画像の観察と、パイロットの規則・CSS 許可一覧の文面から立てたもので、原因を実験で確かめてはいない。
   - 3つの制約は次のとおり。
     1. 画像の数。パイロットは 0〜1枚、成功例は 6〜10枚 (§2)。
     2. 重なりと配置の自由。実装レーンの CSS は `position: static` のみで、`transform`・重なり・背景画像を禁じている。
     3. 文の規則。パイロットは事実の値と中立なラベルだけ。成功例は、各区画に短いキャッチコピーを持つ。
   - どれも安全や研究のために意図して置いた制約で、勝手には緩めない。
   - 緩めるかどうかはオーナーの判断である (§4)。
4. 次の作業 (§6) は、画像参照レーン (読み取り専用の取り込みと SHA の照合)、3方向の設計、品質判定の分離の順である。CP-009・CP-016 の原本はオーナーからの受け取りが要る (§5)。

## 1. 画像の在庫 (`originals-inventory.json`)

### 種類 (kind)

記録された画像の SHA を、次の種類に分ける。

| kind | 意味 |
|---|---|
| `original` | 採用された画像そのもの (全ページ PNG・コンセプト PNG) |
| `registered_preview` | 登録 WebP (原本からの派生) |
| `comparison` | 比較のための並べた画像 |
| `superseded` | 置き換えられた前の版 |
| `rejected` | 不採用・好まれなかった版 |

- `comparison`・`superseded`・`rejected` は、成功の参照の正本には数えない。反例は `rejected` だけである (`superseded` は置き換えられた前の版、`comparison` は比較の資料)。
- HTML・アーカイブ・オフラインのプレビューの頁 (CP-015・024 の `*offline_preview*`) は、画像に数えない。

### 状態

| 状態 | 件数 | 例 | 意味 |
|---|---|---|---|
| `preview_in_repo` | 3 | CP-001・002 (静止のコンセプト)、CP-003 (Web PoC の PC/SP) | 登録 WebP がリポジトリにあり、SHA が記録と一致。原本 PNG は無い |
| `recorded_sha_only` | 20 | PC/SP あり: CP-004・005・007・009・010・011・015・016・024。静止画のみ: CP-006・008・012・013・017〜023 | SHA-256 は記録されているが、バイトは無い |
| `metadata_only` | 7 | CP-026〜032 | 画像の SHA-256 も無い (`original_binary_unverified`) |

- 採用版の PC と SP の両方の記録がある件は10件 (CP-003・004・005・007・009・010・011・015・016・024)。
  - CP-015 は「ノート表示」の状態の PC1440 / SP390 の画像である。
  - このうち画像が見られるのは CP-003 (登録 WebP) だけである。
- 登録件数は manifest の `registered_case_count` = 30 と一致する (テストで固定)。
- CP-024 の疑似復元 v3 は、採用された v2 ではない (manifest の方針)。在庫は v2 の記録だけを持つ。

## 2. 登録 WebP からの観察 (CP-001・002・003)

画像を、実寸と切り出しで開いて見た。座標は **登録 WebP の画素** である (原本 PNG とは大きさが違いうる。例: CP-003 の PC は幅 1080 で、原本の 1440 から縮めた可能性がある)。

以下は観察で、**作品の構図・写真・文をよそへ写すためではない** (`success-cases/README.md` の方針)。

### CP-001 Mond (静止のコンセプト、960×1440)

- **店の特徴の比喩:** ヴィンテージのカップ。藍の花柄のカップが、Hero の写真 (x 330〜720) と、2段目の棚の写真 (x 720〜960, y 530〜850) に繰り返し出る。
- **構造:** 写真と生成りの文字の板が、不規則な3列のモザイクに組まれる。区画どうしは同じ大きさではない。
- **文字:**
  - 巨大なセリフの `MOND` (y 80〜215) が、Hero の写真に食い込む。
  - 縦書きの和文 (x 895)、手書き風の英字 (y 970〜1065)、番号つきの見出し (01〜04) を併用している。
- **色:** 暗い木の茶と生成り。藍は写真の中にだけある。
- **写真:** 約7枚。

### CP-002 Sissi (静止のコンセプト、960×1440)

- **店の特徴の比喩:** 花の枝の「線と形」。
- **構造:**
  - 枝が画面の上半分を斜めに横切る。
  - 写真の枠そのものが曲線や台形に切られる (y 580〜880 の弧、y 875〜1190 の傾いた帯)。
  - 番号 01〜03 の区画が、斜めに千鳥に並ぶ。
- **文字と色:**
  - 細いセリフの店名 (y 95〜275) の上に、枝が重なる。
  - 色見本の丸 (x 920, y 290〜390) が、ページの構成要素になっている。
- **写真:** 9〜10枚。
- **注意:** 写真の切り抜きの形 (`clip-path`)・重なり・傾きは、どれも今の実装レーンでは作れない。

### CP-003 なごやビーンズ v4 (Web PoC、PC 1080×3308・SP 390×4502)

リポジトリの中で、PC/SP の両方が見られる唯一の件である。

- **店の特徴の比喩:** 焙煎度の地図。
  - PC の最初の画面では、9粒の豆が右上へ弧を描いて並ぶ (x 315〜1075, y 100〜510)。焙煎度 01〜09 の目盛りがページの最初の構造になっている。
  - SP では、同じ地図を横に流れる3粒の列に組み直す (y 640〜860)。「横にスライドして焙煎度を選ぶ」の操作を伴う。
- **区画のリズム:** 背景の色を区画ごとに変えている。生成り → 深緑の全幅 (`DEPTH`) → 生成り (`ROAST`) → 薄いセージグレー (`YOUR CUP`)。
- **文字と写真の関係:**
  - 区画ごとに、巨大な英字の見出し (`DEPTH.` 高さ約 210px、`ROAST.`、`YOUR CUP.`) が写真の後ろと前に重なる。
  - 写真は PC で6枚と、豆の切り抜き9粒。傾いた写真や、白い枠の写真が、区画の境をまたぐ。
- **SP:** PC を縮めていない。
  - 見出しの大きさ・写真の重なり・順序を、狭い画面のために組み直している。
  - 背景の大きな文字 `ROA` が右端の外へ切れている。横スクロールが出ないかは、静止画からは確かめられない。
  - **ただし、承認版にも重なりの欠陥がある。** SP の y 1070〜1080 付近で「NOW EXPLORING」と本文「焙煎を、選ぶ。」が重なっている。成功例でも完全ではない。
- **文:** 各区画に、事実ではないキャッチコピーがある (「一杯を、好みから。」「深くなるほど、表情が変わる。」)。

### 3件に共通すること (観察から)

1. 店の固有の物 (カップ・枝・豆の焙煎度) が、**最初の画面の構造そのもの**になっている (色や飾りではない)。
2. 区画ごとに、リズムが変わる (背景の色・写真の大きさ・文字の大きさ・配置)。同じカードは並ばない。
3. 巨大な文字と写真が重なり、区画の境をまたぐ。
4. 写真が多い (6〜10枚)。写真は、Hero・物・場所・手元など、役割を分けて使われる。
5. 短いキャッチコピーと番号つきの小見出しが、読み順を作る。

Issue #193 §0 の CP-009 (布の円形・赤い扉・縫い糸)・CP-016 (支点と重り)・CP-030・CP-032 の観察は、**Claude はまだ画像を見ていない**ので、ここでは引用しない (§5 で受け取ってから記録する)。

## 3. #180 のパイロットとの差 (比べられるもの・比べられないもの)

パイロットの側は、規則と CSS 許可一覧の文面から書いた (パイロットのページを測った値ではない)。

| 観点 | 成功例 (CP-001〜003 で見たもの) | #180 パイロットの規則 | 規則の出どころ |
|---|---|---|---|
| 画像の数 | 6〜10枚、役割が違う | 0〜1枚 | パイロットの予算 (研究 §4、方式ごとに画像 0〜1) |
| 重なり・傾き・切り抜き | 多用 | 作れない | 実装レーンの CSS 許可一覧 (`lib/design-agent/comp-impl/page-css.ts`: `position: static`、`transform` 不可、`clip-path` 不可、背景は単色) |
| 縦書き | CP-001・002 で使う | 作れない | 同上 (横書きだけ。DEV-102 の `vertical_name` は未承認) |
| 文 | 各区画にキャッチコピー | 事実の値と40字以内のラベルだけ | 研究の内容の規則 (研究 §4、design-director の評価と同じ) |
| 区画の背景 | 区画ごとに色を変える | 可 (単色) | 制約ではない (設計の差) |
| 参照 | — | Codex に成功例の要約を渡さない。Claude はスキルだけ | パイロットの暫定方針 (研究 §10) |
| 修正のきっかけ | — | 横はみ出しだけ | 研究 §4 |

- **比べられないもの:** パイロットの評価 (Y > Z > X、採用0/3) は、上の制約の下での方式の比較である。「成功例を十分に活かした品質優先の工程」の成績ではない (Issue #193 §0)。
- **比べられるもの:** 区画のリズム、最初の画面の構造、店の固有の物の使い方。これは制約の中でも変えられる。

## 5. 原本の受け取り (オーナーに1回だけ頼むこと)

画像参照レーン (納品物 2) は、まず CP-003 の登録 WebP で作って試す。そのあと、オーナーから次を受け取る。

| case | 欲しいもの | 照らす SHA-256 (manifest) |
|---|---|---|
| CP-009 豆＊豆 | PC の全ページ PNG | `aee4dcc2e41fd15fddf5bdf26d46835ced3208135342dfa866c6ec94aa9526f5` (`desktop_original_png_sha256`) |
| CP-009 | SP の全ページ PNG | `b4513ecd14e7f12cd52dcce6b3d9379475864736cc92316c4933a0c20303ec14` (`mobile_original_png_sha256`) |
| CP-016 ズールー工作所 | PC 1440 の PNG | `9ea42fe1cc87056d2810069343aa937468048917650897fe69780f1e7e08107e` (`desktop_1440_png_sha256`) |
| CP-016 | SP 390 の PNG | `3b67d554b68e36aaf98fcebc8e45f960a267f3d2f80fcba51cd988b9e37c2e58` (`mobile_390_png_sha256`) |
| CP-030・CP-032 (任意) | PC/SP の PNG | **記録が無い。** 照らせないので「未照合の画像」として受け取り、成功の参照には数えない |

- **渡し方:** #180 と同じ tar の形 (`SHA256SUMS` つき) で、このセッションにアップロードする。
- **Claude が行うこと:**
  - SHA-256 を照らす。合わないものは使わない。
  - 照らせたものだけを、画像を見て記録する。
  - **画像はリポジトリに入れない** (public のため)。
- **受け取れない間:** 原本の要る作業 (CP-009・016 の分析) だけを HOLD にする。ほかの作業は進める。
