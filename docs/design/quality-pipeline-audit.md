# 品質優先パイプラインの現状監査 (DEV-154、Issue #193 の納品物 1)

2026-11-02。develop `705b415` を起点に、既存コード・研究台帳・原本画像の状態を監査した。
**この文書は監査だけで、品質を上げたとは主張しない。**
実 Codex・画像生成・有料 API・実機の操作はしていない。

## 0. 結論 (先に)

1. **Claude が実際に見られる成功例の原本は、3件だけである** (CP-001・CP-002・CP-003)。
   - リポジトリにある画像は4枚 (WebP) で、どれも SHA-256 が manifest と一致した。
   - CP-009・CP-016 を含む20件は、SHA-256 の記録だけがあり、画像のバイトはここに無い (オーナーの ChatGPT の会話アーカイブ)。
   - CP-026〜032 の7件は、画像の SHA-256 も無い。
   - 一覧は `design-library/research/quality-pipeline/originals-inventory.json` にある (機械で作り、テストで固定)。
2. **リポジトリは public である。**
   - だから、権利が確認できていない原本 (実在の店名、AI の写真) を commit すると、そのまま外へ公開することになる。Issue #193 §3 が禁じている。
   - この研究では原本をリポジトリに入れない。受け取った原本は manifest の SHA-256 と照らし、残すのは導いた記録だけ (SHA・大きさ・測った特徴・座標つきの観察)。
3. **#180 のパイロットと成功例の差は、主に3つの制約から来ている。** 画像を見て確かめた。
   1. 画像の数。パイロットは 0〜1枚、成功例は 4〜8枚。
   2. 重なりと配置の自由。実装レーンの CSS は `position: static` のみで、`transform`・重なり・背景画像を禁じている。
   3. 文の規則。パイロットは事実の値と中立なラベルだけ。成功例は、各区画に短いキャッチコピーを持つ。
   - どれも安全や研究のために意図して置いた制約で、勝手には緩めない。
   - 緩めるかどうかはオーナーの判断である (§4)。
4. 次の作業 (§6) は、画像参照レーン (読み取り専用の取り込みと SHA の照合)、3方向の設計、品質判定の分離の順である。CP-009・CP-016 の原本はオーナーからの受け取りが要る (§5)。

## 2. 実際の画像からの観察 (CP-001・002・003)

画像をそのまま開いて見た。座標は元の画素である。以下は観察で、**作品の構図・写真・文をよそへ写すためではない** (`success-cases/README.md` の方針)。

### CP-001 Mond (静止のコンセプト、960×1440)

- **店の特徴の比喩:** ヴィンテージのカップ。藍の花柄のカップが、Hero の写真 (x 330〜720) と、3段目の棚 (x 720〜960, y 530〜850) に繰り返し出る。
- **構造:** 写真と生成りの文字の板が、市松のように交互に組まれる (2列×4段)。区画どうしは同じ大きさではない。
- **文字:**
  - 巨大なセリフの `MOND` (y 80〜215) が、Hero の写真に食い込む。
  - 縦書きの和文 (x 895)、手書き風の英字 (y 970〜1060)、番号つきの見出し (01〜04) を併用している。
- **色:** 暗い木の茶と生成り。藍は写真の中にだけある。

### CP-002 Sissi (静止のコンセプト、960×1440)

- **店の特徴の比喩:** 花の枝の「線と形」。
- **構造:**
  - 枝が画面の上半分を斜めに横切る。
  - 写真の枠そのものが曲線や台形に切られる (y 580〜880 の弧、y 880〜1180 の傾いた帯)。
  - 番号 01〜03 の区画が、斜めに千鳥に並ぶ。
- **文字と色:**
  - 細いセリフの店名 (y 90〜280) の上に、枝が重なる。
  - 色見本の丸 (x 920, y 300〜390) が、ページの構成要素になっている。
- **注意:** 写真の切り抜きの形 (`clip-path`)・重なり・傾きは、どれも今の実装レーンでは作れない。

### CP-003 なごやビーンズ v4 (Web PoC、PC 1080×3308・SP 390×4502、唯一の承認済み PC/SP)

- **店の特徴の比喩:** 焙煎度の地図。
  - PC の最初の画面では、9粒の豆が右上へ弧を描いて並ぶ (x 330〜1050, y 120〜500)。焙煎度 01〜09 の目盛りがページの最初の構造になっている。
  - SP では、同じ地図を横に流れる3粒の列に組み直す (y 640〜860)。「横にスライドして焙煎度を選ぶ」の操作を伴う。
- **区画のリズム:** 背景の色を区画ごとに変えている。生成り → 深緑の全幅 (`DEPTH`) → 生成り (`ROAST`) → 薄い生成り (`YOUR CUP`)。
- **文字と写真の関係:**
  - 区画ごとに、巨大な英字の見出し (`DEPTH.` 高さ約 200px、`ROAST.`、`YOUR CUP.`) が写真の後ろと前に重なる。
  - 写真は 4〜6枚。傾いた写真や、白い枠の写真が、区画の境をまたぐ。
- **SP:** PC を縮めていない。
  - 見出しの大きさ・写真の重なり・順序を、狭い画面のために組み直している。
  - 背景の大きな文字 `ROA` が右へはみ出しても、横スクロールは出ない。
  - **ただし、承認版にも重なりの欠陥がある。** SP の y 1060〜1075 付近で「NOW EXPLORING」と本文が重なっている。成功例でも完全ではない。
- **文:** 各区画に、事実ではないキャッチコピーがある (「一杯を、好みから。」「深くなるほど、表情が変わる。」)。

### 3件に共通すること (観察から)

1. 店の固有の物 (カップ・枝・豆の焙煎度) が、**最初の画面の構造そのもの**になっている (色や飾りではない)。
2. 区画ごとに、リズムが変わる (背景の色・写真の大きさ・文字の大きさ・配置)。同じカードは並ばない。
3. 巨大な文字と写真が重なり、区画の境をまたぐ。
4. 写真が多い (4〜8枚)。写真は、Hero・物・場所・手元など、役割を分けて使われる。
5. 短いキャッチコピーと番号つきの小見出しが、読み順を作る。

Issue #193 §0 の CP-009 (布の円形・赤い扉・縫い糸)・CP-016 (支点と重り)・CP-030・CP-032 の観察は、**Claude はまだ画像を見ていない**ので、ここでは引用しない (§5 で受け取ってから記録する)。

## 3. #180 のパイロットとの差 (比べられるもの・比べられないもの)

| 観点 | 成功例 (CP-001〜003 で見たもの) | #180 パイロット (X/Y/Z) | 差の出どころ |
|---|---|---|---|
| 画像の数 | 4〜8枚、役割が違う | 0〜1枚 | パイロットの予算 (方式ごとに画像 0〜1、研究 §4) |
| 重なり・傾き・切り抜き | 多用 | 無し | 実装レーンの CSS 許可一覧 (`lib/design-agent/comp-impl/page-css.ts`: `position: static`、`transform` 不可、`clip-path` 不可、背景は単色) |
| 縦書き | CP-001・002 で使う | 無し | 同上 (横書きだけ。DEV-102 の `vertical_name` は未承認) |
| 文 | 各区画にキャッチコピー | 事実の値と40字以内のラベルだけ | 研究の内容の規則 (研究 §4、design-director の評価と同じ) |
| 区画の背景 | 区画ごとに色を変える | 可 (単色)。方式により使った | 制約ではない (Claude の設計の差) |
| 参照 | — | Codex に成功例の要約を渡さない、Claude はスキルだけ | パイロットの暫定方針 (研究 §10) |
| 修正のきっかけ | — | 横はみ出しだけ | 研究 §4 |

- **比べられないもの:** パイロットの点数 (Y > Z > X、採用0/3) は、上の制約の下での方式の比較である。「成功例を十分に活かした品質優先の工程」の成績ではない (Issue #193 §0)。
- **比べられるもの:** 区画のリズム、最初の画面の構造、店の固有の物の使い方。これは制約の中でも変えられる。この3つが、パイロットで成功例より弱かった。

## 5. 原本の受け取り (オーナーに1回だけ頼むこと)

画像参照レーン (納品物 2) は、まず CP-003 (ここにある原本) で作って試す。そのあと、オーナーから次を受け取る。

| case | 欲しいもの | 照らす SHA-256 (manifest) |
|---|---|---|
| CP-009 豆＊豆 | PC の全ページ PNG | `aee4dcc2e41fd15fddf5bdf26d46835ced3208135342dfa866c6ec94aa9526f5` (`desktop_original_png_sha256`) |
| CP-009 | SP の全ページ PNG | `b4513ecd14e7f12cd52dcce6b3d9379475864736cc92316c4933a0c20303ec14` (`mobile_original_png_sha256`) |
| CP-016 ズールー工作所 | PC 1440 の PNG | `9ea42fe1cc87056d2810069343aa937468048917650897fe69780f1e7e08107e` (`desktop_1440_png_sha256`) |
| CP-016 | SP 390 の PNG | `3b67d554b68e36aaf98fcebc8e45f960a267f3d2f80fcba51cd988b9e37c2e58` (`mobile_390_png_sha256`) |
| CP-030・CP-032 (任意) | PC/SP の PNG | **記録が無い。** 照らせないので「未照合の原本」として受け取り、成功の参照には数えない |

- **渡し方:** #180 と同じ tar の形 (`SHA256SUMS` つき) で、このセッションにアップロードする。
- **Claude が行うこと:**
  - SHA-256 を照らす。合わないものは使わない。
  - 照らせたものだけを、画像を見て記録する。
  - **画像はリポジトリに入れない** (public のため)。
- **受け取れない間:** 原本の要る作業 (CP-009・016 の分析) だけを HOLD にする。ほかの作業は進める。
