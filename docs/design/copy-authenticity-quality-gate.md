# Second Root: 文章の自然さ・店舗固有性ゲート（仕様案）

状態: **提案 / 未実装**（2026-11-13）。対象は**今後生成する**店舗専用デモのコピー。過去の研究採用例 SR-001「輪」の画像・レイアウト・登録済み v1 は変更しない。

## 背景・オーナーの指摘

SR-001「輪」はAI画像とPC/SPレイアウトの再現に成功した一方、サイトの文章が「AIっぽい」。典型例は「スポークの先に、修理がある。」「一本ずつ。」「空気を入れる日。」「一周して、店先へ。」のような、ほぼ全区画に付けた詩的・暗示的な決め台詞。コピーが情報を伝える代わりにデザインの穴埋めをしている。**目的は「輪」を今すぐ書き換えることではない。以後の自動デモ生成の品質ルールにする。**

重要: 「AIっぽい単語のブラックリスト」だけでは解決しない。語彙だけでなく、全ページの文体・韻律・区画間の繰り返し・情報の有無・店固有の事情を評価する。店の一番強い表現が一つ残ってよい。全部を平板なラベルに変えるのも不合格。

## 既存の安全境界（維持）

- `lib/design-agent/quality-pipeline/copy-record.ts`: `comp_copy_v1`、`fact` / `creative_expression` / `proposal_pending_review`、事実のソースとSHA。**既存の型・判定を緩和しない。**
- `lib/design-agent/quality-pipeline/facts-pack.ts`: `shop_facts_pack_v1`、出典のある情報のみ。事実を業界の一般論で補わない。
- `lib/design-agent/quality-pipeline/comp-review.ts`: PC/SPカンプのレビューは見た目の審査であり文章品質の代用にはしない。
- 架空店舗の研究コピーと実店舗向けの提案文を混同しない。実店舗の未検証文を「店の言葉」「実際のサービス」として表示・共有しない。自動で送信・公開しない。研究成功例を遡及取り消さない。
- 参考サイトの**表現のコピー**は禁止。学ぶのは情報の順序・言葉の密度・利用者に役立つ説明の設計。

## 設計する新工程（既存工程に追加）

| 段階 | 入力 | 出力 | 通過条件 |
|---|---|---|---|
| 1. 店舗調査 | 出典付き facts pack / 足りない情報 | 店らしさの根拠・提供価値・用語メモ | 推測と確認済みを分離。情報不足が明示される |
| 2. コピー設計 | facts、デザイン方向・客の目的 | セクション別の役割、見出し、本文、出典の紐付け | 「何を知れるか」が各区画にある。デザインに合わせて無意味な決め台詞を作らない |
| 3. コピー生成 | `comp_copy_v1` の制約 | PC/SPに入るコピー候補 | 現場の言葉で自然。事実創作なし。見出しと本文で役割が分かれる |
| 4. 文章品質監査 | ページ全体、facts、copy record、同業種の過去案 | 指摘箇所、理由、最小修正案、判定 | 安全の失敗はFAIL、文体の疑義はREVISE/HOLD。機械採点だけで成功宣言しない |
| 5. 再生成 / 再審査 | 指摘と保護対象 | 差分・再審査記録 | 良い箇所を維持して局所修正、原則最大2回。事実不足は創作せずHOLD |
| 6. オーナー審査 | PC/SP全ページとコピー監査 | approve / revise / reject | **文章品質とデザイン品質の両方が承認されるまで営業送信候補として完了にしない** |

## 品質軸と結果

五つの軸を区別する。各0–5点の採点は**補助**であり、単独で公開・送信を承認しない。

1. **自然な日本語**: 言い切り・断片文・不自然な読点・過度の体言止めの連続、接客に使わない借り物の口調がない。
2. **店舗固有性**: 別の店名に入れ替えても通用する文章になっていない。店舗ごとの事実・商品・作業や顧客の疑問に根拠を持つ。
3. **情報の有用性**: 各セクションに目的があり、商品・サービス・来店方法など必要な情報に素早くたどり着ける。
4. **表現の抑制と一貫性**: 全区画がキャッチコピーではない。ページ内で同じ語調・比喩・構文が繰り返されない。象徴的な表現は店に結び付いている。
5. **事実・出典の正しさ**: 未確認の価格・予約・在庫・経験年数・店主の発言・お客様の声・商品特徴を発明しない。架空と実在の区別が保たれている。

判定コードの候補（仕様案）:
- `COPY_FACT_UNSUPPORTED` → FAIL（既存`copy-record`の失敗を優先）
- `COPY_RHETORICAL_OVERUSE` → REVISE（意味の薄い決め台詞の多用）
- `COPY_REPETITIVE_CADENCE` → REVISE（複数の見出しが同じ型）
- `COPY_GENERIC_FOR_SHOP` → REVISE（店固有の説明が欠ける）
- `COPY_INFORMATION_MISSING` → REVISE/HOLD（必要な内容がない。情報そのものが不足するならHOLD）
- `COPY_VOICE_UNNATURAL` → REVISE（話し方が業種・顧客と合わない）
- `COPY_APPROVAL_MISSING` → HOLD（実店舗向け提案と営業前にオーナーの確認が必要）

**単語単位で機械的にFAILにしない**。例えば「ひとつずつ」は製法の事実なら自然。「想い」「丁寧」「特別」の文字列だけで不合格としない。AIの文章かどうかの断定もしない。

## 監査レコード（実装する場合）

現行`comp_copy_v1`は変更せず、別のsidecar `copy_quality_review_v1` として保存する。最低限:
- `shop_id`、`facts_sha256`、`copy_sha256`、`page_sha256`、対象レーン（架空研究／実店舗提案）
- 区画別`section_id`、見出し／本文の役割、観察した文言の位置
- 五軸の採点と具体的根拠、`findings[]`（code・該当箇所・理由・根拠）
- `verdict: approve_candidate | revise | hold`、修正履歴と未解決項目
- オーナーの承認は別の記録。モデルの`approve_candidate`だけでは送信可能にならない。
- 審査入力のハッシュが変わったら審査は無効。新案を審査せずに古いPASSを再利用しない。

## 実装順・責任分界

1. **基準を固定**: 本仕様と、良いコピー/AI的なコピー/事実未確認の多業種テストケースを追加する。少なくともパン屋・美容室・自転車修理・飲食店の4業種、PC/SP全ページ。
2. **監査関数**: `lib/design-agent/quality-pipeline/` に独立した監査ロジック／schema／テストを追加する。入力は既存 `facts-pack`・`copy-record` とページテキスト。既存検査の結果を包み、**事実検査より緩い抜け道は作らない**。
3. **生成プロンプト**: 実際に使用している生成ルートごとに、セクション役割・コピーの根拠・禁止する作業（未確認事実の創作）を追加する。既存のowner-approved/pinned promptのSHAを黙って変更しない。必要なら新versionとして提案・承認を受ける。
4. **パイプライン接続**: 文章レビュー `revise/hold` なら次の提出・営業候補完了に進まない。根拠が足りなければ再生成せずHOLD。オーナーの承認を尊重。
5. **検証**: false positiveとfalse negativeを両方テストし、既存のrights/HTML/DB/隔離/runner/CIが退行しないことを確認する。Fresh Review C/H/M=0 を目標にする。**外部送信はテストしない。**

## 最低限の受け入れ試験

- SR-001「輪」の元コピーを監査に通すと「スポークの先に、修理がある。」「一本ずつ。」「空気を入れる日。」「一周して、店先へ。」の**累積**した説明不足・比喩の繰り返しを検出する。単独のHero「まがった車輪も、まっすぐに。」は文脈と整合するため自動拒否しない。
- 「パン屋のクロワッサンは毎朝焼きます」は**その店の出典がある場合だけ**事実として許可する。出典なしなら保留/拒否。
- 美容室・カフェ・整体のコピーをすべて同じ「こだわりの」「特別なひととき」で埋めた場合に類似・汎用性を指摘する。一方、普通の「メニュー」「アクセス」「営業時間」を罰しない。
- 出典付きの短く平易な文章に対して「詩的でない」を理由に不合格にしない。独自性だけで安全性を上書きしない。
- 検査レコードのコピーSHAを変えると旧承認が失効。現行の研究v1・ローカル写真パッケージ・管理者表示・営業送信不可の安全境界は維持。
- オーナー承認がないまま「文章監査PASS」を送信・実店舗向け完成の唯一の条件にできない。
