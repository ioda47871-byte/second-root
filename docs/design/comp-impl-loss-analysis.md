# カンプから実装で失われるもの: 3業種の分析 (DEV-160、Issue #193)

2026-11-03。架空の3店舗 (金継ぎ工房 つぐ手・自転車修理 輪・銭湯 ゆげ湯) で、カンプと実装レーンの Web 実装を比べた。
PC 1440 と SP 390 を描き、**Claude が画像を自分で見て**、失われたものを出所ごとに分けた。

記録は `design-library/research/quality-pipeline/poc/loss-analysis.json` にある。
`tests/unit/design-agent/quality-pipeline/loss-analysis.test.ts` が、記録と各カンプの判定、記録と今の実装の規則が食い違わないことを確かめている。

**これは品質の判定ではない。** 採るかはオーナーが決める。オーナーが画像を見るまで、成功例の水準とは言わない。

## 出所の4つ

| 出所 | 符号 | 何か |
|---|---|---|
| カンプの質 | `COMP_*` | カンプそのものの見落とし。実装の前から在る |
| 仮の写真 | `PLACEHOLDER_PHOTO` | 写真が単色の仮の板。実際の写真は別の承認が要る |
| 実装の規則の限界 | `IMPL_RULE_*` | 実装レーンの CSS と HTML の許可一覧で作れない。規則は変えていない |
| 実装の誤り | `IMPL_MISTAKE_*` | 規則の中で作れたのに、Claude の実装が落とした |

## 件数

| 店 | カンプの判定 | カンプの質 | 仮の写真 | 実装の誤り | 規則の限界 |
|---|---|---|---|---|---|
| つぐ手 (金継ぎ) | `show_owner` | 2 | 1 | 6 | 6 |
| 輪 (自転車修理) | `revise` | 4 | 1 | 5 | 6 |
| ゆげ湯 (銭湯) | `revise` | 4 | 1 | 5 | 7 |

`show_owner` は、オーナーに見せる候補という意味で、成功ではない。

実装の誤りには、fidelity-measure で測ったタブレットの幅 (1024・768) の誤りも入れた。B が横にはみ出し、巨大な文字が折れていた (`view: tablet`)。

## 3店に共通して分かったこと

1. **まっすぐ組んだ実装 (a) は、どの店でも店の核を落とした。**
   - つぐ手の金の線、輪のスポーク、ゆげ湯の温度計の帯が消えた。
   - 原因は規則ではなく Claude の実装の誤りだった (`IMPL_MISTAKE_MOTIF_BROKEN`)。
   - b では、規則の中で次のように戻した。
     - 同じ3列の格子で、線を途切れなくした。
     - 罫でスポークと帯を描いた。
2. **写真の板が均質になる誤りも、3店すべてで起きた。**
   - 単色の仮の画像を幅いっぱいに置くと、縦横比が消えて正方形になる (`IMPL_MISTAKE_ASPECT_RATIO`、`UNIFORM_GRID`)。
   - `aspect-ratio` で直る。**仮の画像には、カンプの写真の比を必ず付ける。**
3. **SP の語の途中の改行** (まわ/る、ありま/す)。
   - `nowrap` と `keep-all` は規則で使えない。
   - 大きさと `<br>` で避けられるので、実装の誤りに数えた。直っていないので、合格にはしない。
4. **残る損失の多くは規則の限界である。** 3店で共通するのは次のとおり。
   - 区画の境をまたぐ重なり
   - 傾きと影
   - 縁取りの巨大な文字
   - 縦書き
   - 自由な形 (割れ目のジグザグ、放射状のスポーク、山)
   - 256px を超える文字
   - グラデーションと模様

   各店のカンプの核のうち、規則の中で作れたのは、線や帯の連続 (罫) と、大きさと位置のずらし (格子) だけだった。
5. **カンプの質の問題は、実装とは別に残る。**
   - 輪では、核 (スポークの先の修理の駅) がカンプでも図になっていない。
   - ゆげ湯では、カンプの下半分が平板である。
   - 実装を忠実にしても、これは直らない。

## 次 (Issue #193 コメント `6596798696` の順)

- **研究専用の忠実な実装 (`experimental_fidelity`)。**
  - 実装レーンの規則は変えない。
  - 代わりに、B方式の隔離された描画レーン (`checkPrototype`、JS 無効と通信遮断の `renderPrototype`) で、カンプの核を再現する実装を作る。
  - 本番用の実装とは別のラベルにし、規則の違反を隠して合格にはしない。
- **3つを同じ PC/SP で並べて、Claude が見る。** 承認候補のカンプ (A)、規則の中の実装 (B)、忠実な実装 (C) である。
- **比較の道具の食い違いを直す。** `impl-compare` が測る属性の食い違い (`data-section` 対 `data-comp-section`) を、比較の道具の側の別の実行条件で解く。
- **`motif_preservation` を測る。** 店の核が残ったかを数字で示し、画像と並べる。
- **規則の将来の変更は、別 PR とオーナーの承認による。** 研究レーンで安全に再現できると示してから、要る性質だけを最小の粒度で挙げる。

## A・B・C の見比べ (2026-11-03、Issue #193 コメント `6596798696` の 3〜6)

同じ店、同じ方向について、3つを並べた。

- **A:** 承認候補のカンプ
- **B:** 規則の中の実装 (`impl/*-b`)
- **C:** 研究用の忠実な実装 (`fidelity/*`)

C は `experimental_fidelity` であり、本番用ではない。B方式の隔離された道 (`checkPrototype` と、JS 無効・通信遮断の描画) を通っている。

### C の作り

C はカンプの写しではなく、実装として作った。

- 区画に `data-comp-section` を付けた。
- 高さは中身で決まる。
- 写真の板に縦横比を付けた。
- 1024 と 768 でも崩れない。
- B の実装の誤り (語の途中の改行、均質な格子、SP の線の段差) は直した。

C は、本番の実装レーンの許可一覧では通らない。使っているのは position・transform・SVG・writing-mode・text-stroke・グラデーション・負の margin である。**許可一覧は変えていない。**

### Claude が見たこと (PC 1440・SP 390 の A|B|C を並べて)

- **つぐ手**
  - C は、金の線が器の割れ目を通り、ページを蛇行して結び目まで途切れない。縁取りの 継ぐ・待つ が区画の境をまたぐ。傾いた板と縦書きもある。Claude の目では A に近い (直す前の版 `d1-v2`)。
  - B では、線がまっすぐになった。PC では店名 つぐ手 が2行に折れた。
- **輪**
  - C は、32本の放射状のスポークの車輪が、Hero から暗い区画へまたがる。縁取りの まわる・締める、目盛りと斜めの針の空気入れ、ページの外へ出る最後の車輪もある。Claude の目では A に近い (直す前の版 `d1`)。
  - B では、スポークが縦横4本になり、修理の板が並ぶだけになった。
  - C の暗い区画は、A より約 360px 高い。縁取りの文字と名札がぶつからないように空けた。
- **ゆげ湯**
  - C は、左端の温度計の帯が滑らかなグラデーションで下る。縁取りの ぬるい は境をまたぎ、熱い・冷たい は縦書きで、傾いた湯船の板もある。Claude の目では A に近い (直す前の版 `d1`)。
  - B では、帯が区画ごとの色の段になった。巨大な文字は小さな塗りになった。
  - **C は山に雪の白を足していて、カンプに無い。** 忠実さから外れているので、記録しておく。

カンプ自身の問題は、C にもそのまま残る。

- 輪: 縁取りの まわる が黄の地で消える。駅がスポークにつながらない。
- ゆげ湯: 下半分が平板である。
- 3店すべて: 写真は仮の板である。

### 比較の道具の食い違い (`impl-compare`)

- `impl-compare` に、実装側の区画を測る属性を選ぶ別の実行条件を足した (`--section-attr data-comp-section`、既定は今までどおり `data-section`)。
- デザイン側は、今までどおり runner の測った箱を使う。どちらのページも変えていない。
- 次のことをテストで固定した。
  - `data-comp-section` で印した同じページを、その属性で測ると、`data-section` で測ったときと同じ箱と同じ比較になる。
  - 既定の測り方は変わっていない。

### この研究から言えること、言えないこと

- **言えること:** つぐ手・輪・ゆげ湯のカンプの核 (線・車輪・温度計の帯) は、隔離された B 方式の道でなら、PC・SP・タブレットの幅で実装として描けた。これは Claude の目と位置の数による判断で、品質の判定ではない。失われていた原因の多くは、本番の実装レーンの規則だった。
- **言えないこと:**
  - 成功例の水準に達したこと (オーナーが画像を見ていない。写真も仮)。
  - 本番の許可一覧を広げてよいこと。
    - 広げるなら、要る性質を最小の粒度で挙げる必要がある。候補は、装飾の SVG の線、`position` と `z-index` の重ね、`transform: rotate`、`writing-mode`、`-webkit-text-stroke`、グラデーションである。
    - 隔離のテスト (外への通信、JS、別レーンへの汚染) と一緒に、別 PR とオーナーの承認で行う。

**数:** 新しい C は3店とも、4つの幅で、覆われた説明の行・横切られた説明の行・**巨大な語の**途中の改行・横のはみ出しが 0 のままだった。
核の覆いは前の C と同じ水準である。

**この節の最初の版は言い過ぎていた (Fresh Review round 1、PR #205)。** 最初の版は「この計測は `pointer-events: none` の線を数えないので、
線と文字が交わらないことは描いた画像を見て確かめた」と書いた。実際には次のとおりだった。

- 計測は `pointer-events` を戻して引いている。数えなかった理由は、説明の行ごとに横の3点でしか引かないので、細い線が点のあいだを通ることである。
  大きな 割れ・欠け・ひび の字は説明の行ではなく、巨大な語として折れだけを数える。
- つぐ手は 601〜1199px で、線が 割れ・欠け・ひび の字、説明、修理名の上を通っていた (1024・768 で各10文字)。破片の格子の % が詰め物の内側で解かれ、
  言葉の列が線の左から始まったためである。見て確かめたと書いたが、見落としていた。
- 「語の途中の改行 0」は巨大な語だけで、本文・事実の文は 輪 で 架空町四丁|目8-1、締め|て などと割れていた。
