# 品質検証の実写真: 受け取りから差し替えまでの設計 (DEV-163、Issue #193 コメント `6601921731` の判断3)

2026-11-03。**設計だけで、写真は1枚も取得も生成もしていない。**

- 画像生成・有料素材・外部 API は使わない。他人の画像を集めたり公開したりもしない。どれも別の承認が要る。
- コードは次の2つである。
  - 受け取りの門 (`lib/design-agent/quality-pipeline/photo-rights.ts`)
  - 写真の枠と切り抜きの計算 (`lib/design-agent/quality-pipeline/photo-slots.ts`)
- 3店の C ページの枠の一覧は、`design-library/research/quality-pipeline/poc/<shop>/photo-slots.json` にある。
- 差し替えて描く道具は、まだ作らない。写真が届き、オーナーが承認したら作る (§6)。

## 1. 入れてよい写真、入れない写真

**入れてよい** (どちらかに当たり、記録がそろっているものだけ):

- (a) オーナーか店が渡した写真で、使う許可があるもの (`owner_provided` / `shop_provided`)。
- (b) 規約が、編集・切り抜き・商用の利用をはっきり許す素材 (`licensed_stock_with_terms`)。
  - 規約の本文の SHA-256 (`terms_sha256`) を記録して、規約を固定する。
  - 有料のもの (`paid: true`) は、別の承認が無い限り拒む。

**入れない:**

- 他のサイトの写真。種類 (`source_kind`) に、その値が無い。
- 成功例の写真。SHA-256 で拒む (`FORBIDDEN_SOURCE_HASH`)。
  - 禁止の一覧は、原本の目録 (`design-library/research/quality-pipeline/originals-inventory.json`) から `loadForbiddenSha256` が読む。リポジトリにある成功例の4枚と、各成功例が記録する原本・プレビューの SHA すべてである。
  - `checkPhotoRights` は、この一覧 (`forbiddenSha256`) を**必須**の引数として受け取る。渡し忘れて空の一覧で通ることは無い。目録が空か壊れていれば、読む時点で止まる。
- AI で生成した画像。
- 人の顔や体で、誰か分かるもの (`IDENTIFIABLE_PERSON`)。
- 実在の店。3店は架空なので、実在の店の写真は使わない (`REAL_SHOP_DEPICTED`)。
- 看板・店名・住所・電話番号・車のナンバーが読める写真。これらは記録の項目に無いので、渡す側への依頼 (§8) と、受け取るときの目視で止める。

## 2. 流れと役割

| 段 | すること | 誰が | 止める門 |
|---|---|---|---|
| 1. 依頼 | 枠ごとに枚数・形・最小の画素・写すもの・権利を伝える (§8) | Claude が文を作り、オーナーが送る | — |
| 2. 受け取り | 写真と権利の記録 (`photo_rights_v0`) を、リポジトリの外で渡してもらう | 提供者 → オーナー | — |
| 3. 権利の記録を検める | 項目の欠け、日付、許された使い方、有料、人・実在の店、期限 | 機械 (`checkPhotoRights`) | `RIGHTS_MISSING_*`・`RIGHTS_DATE_INVALID`・`RIGHTS_RECEIVED_IN_FUTURE`・`NOT_ALLOWED_FOR_*`・`PAID_SOURCE_NOT_APPROVED`・`IDENTIFIABLE_PERSON`・`REAL_SHOP_DEPICTED`・`RIGHTS_EXPIRED` |
| 4. ハッシュ・大きさ・形式 | ファイルの頭から幅・高さ・形式・向き (JPEG の EXIF) を読み、SHA-256 と大きさを記録と照らす | 機械 (`measurePhotoBytes` / `readPhotoHeader`) | `HASH_MISMATCH`・`SIZE_MISMATCH`・`DIMENSION_MISMATCH`・`FORMAT_MISMATCH`・`FORBIDDEN_SOURCE_HASH`・`PHOTO_EXIF_UNREADABLE` |
| 5. 非公開の置き場 | `design-library/research/quality-pipeline/.intake/photos/` にだけ置く (git が無視する) | オーナーか Claude (手元) | `PATH_NOT_PRIVATE`・`PATH_SYMLINK`・`PHOTO_HARDLINK` (`resolvePrivatePhoto`) |
| 6. 枠に割り当てる | どの写真をどの枠 (`slot_id`) に入れるか決める | オーナー (Claude が案を出す) | — |
| 7. 切り抜きと焦点 | 枠の形ごとに、焦点を中心にした切り抜きを計算する | 機械 (`coverCrop` / `fitSlot`) | `PHOTO_TOO_SMALL`・`RATIO_MISMATCH_EXTREME` |
| 8. C ページで差し替える | 非公開の写しの中で、板を写真にする (§6) | Claude | — |
| 9. PC/SP で描く | 1440・1024・768・390 で描く。JS 無効、自分のファイル以外への通信は拒否 | Claude (手元) | — |
| 10. オーナーが見る | 描いた画像を見て決める。**Claude は成功例の水準とは言わない** | オーナー | — |

- 段3と段4の門は、理由を1つ目で止めず、すべて返す。
- 日付はすべて **UTC の日** で比べる (日本時間ではない)。日付だけの `expiry: "2026-03-01"` は、日本時間では 3月2日 9時まで有効と扱われる。期限を日本時間の日として決めるときは、1日前の日付を書く。
- 期限は、`now` を渡さなければ**今日 (UTC の日付)** と比べる。だから、期限の切れた記録は、呼び方によらず必ず拒む。テストは `now` を固定する。
- `resolvePrivatePhoto` が拒むもの:
  - 品質パイプラインの根・`.intake`・`photos`・ファイルのどれかが、シンボリックリンクであるもの。根より上のフォルダは、先に realpath で解く。
  - ファイルに名前が2つ以上あるもの (ハードリンク、`nlink > 1`)。別の場所のファイルと同じ中身を指せるからである。
  - **既知の限界 (Low):** 検める (lstat) のと読むのは、別の2段である。その間にファイルを差し替えられると、気づけない。置き場はオーナー自身の手元の機械で、共有の機械ではないので、今は直さない。
- 段8〜10の画像は、リポジトリの外に置く。リポジトリには SHA だけを残す。

## 3. 公開に残すもの、残さないもの

リポジトリは公開である。

| 公開に残す (リポジトリ) | 非公開だけ (`.intake/` か、オーナーの手元) |
|---|---|
| 写真の SHA-256・バイト数・幅・高さ・形式 | 写真のバイト列 |
| 種類 (`source_kind`)、許された使い方 (真偽値)、受け取った日、期限 | 権利者の名前 (`owner`) |
| 依頼主の確認があったか (真偽値) | 同意の記録 (`consent_record_ref`)、許可や規約の本文 (`license`) |
| 枠の一覧 (`photo-slots.json`)、切り抜きの数値 | 置き場の道 (`private_path`) |
| 差し替えて描いた画像の SHA | 差し替えて描いた画像そのもの |

- 公開の形は `toPublicPhotoRecord` が作る。これは `photo_public_record_v0` で、`bytes_committed: false` を持つ。
- `.intake/` は `.gitignore` が無視する。テストは、次の3つを固定している。
  - `.intake/` の下が1つも追跡されていないこと。
  - リポジトリ全体の画像のファイル (追跡されているものと、無視されていない未追跡のもの) が、DEV-163 の前からある35個 (`app/favicon.ico` を含む) から増えないこと。
    - アプリのアイコン、`public/` のブランドと作例の画像、成功例の4枚、研究の 64×64 の仮の板8枚である。
  - 研究の板が 64×64 のままであること。
- 写真を git に入れる道は無い。`git add -f` もしない。

## 4. 評価のラベル `placeholder_limited`

- 写真の枠が1つでも仮の板である間、そのページの評価は `placeholder_limited` とする。
- 枠の一覧は、このラベルを固定で持つ (`evaluation_label`)。
- このラベルの評価は、写真の質感・色・密度を判断していない。だから、成功例の水準かどうかの判断には使わない。
- すべての枠に権利の確かな写真が入り、オーナーが描いた画像を見るまで、このラベルを外さない。

## 5. 写真の枠 (3店の C ページ)

- 枠は、「写真｜」で始まる文のそばにある板である。その文は、文の記録の `ph-*` の項目である。
  - 測る道具: `scripts/design-artifact/photo-slots.ts`
  - 条件: JS 無効、自分のファイル以外への通信は拒否、deviceScaleFactor 1
  - 大きさは、ページが回転させる前の箱で測る。
- 最小の画素は、描いた箱の2倍である (2倍の画面のため)。
- 写真の幅と高さは、**表示される向き**で数える。
  - 携帯電話で縦に構えて撮った JPEG は、多くが横長 (4032×3024) のまま保存され、EXIF の向き (orientation 6 か 8) で縦に表示される。
  - `measurePhotoBytes` は、APP1 の EXIF (II と MM の両方) から向きの値 (タグ `0x0112`) を読む。5〜8 なら幅と高さを入れ替え、`orientation` も返す。
  - EXIF があるのに読めない JPEG は、`PHOTO_EXIF_UNREADABLE` で拒む。向きが分からなければ、切り抜きの形も分からないからである。
  - 権利の記録の `width`・`height` も、表示される向きで書く。
- 半分を残せるかの判定 (`MIN_KEPT_AREA`) は、丸める前の値で比べる。記録の `kept_area` だけを小数3桁に丸める (0.4996 は 0.5 と書かれるが、拒まれる)。
- 一覧は、測ったページの HTML・CSS・文の記録の SHA を持つ。ページが変わればテストが落ちるので、測り直す。
- テストはブラウザで測り直し、2px 以内で一致することも確かめる。

- 1024 と 768 の箱も、一覧にある。
- 「頼む形」と「最小の画素」は `requestFor` が出す。
  - すべての幅で、写真の面積の半分以上を残せる形を選ぶ。その中で、最も悪い幅で残る面積が最も大きい形にする。
  - その形で、どの幅でも2倍を下回らない、最も小さい大きさを出す。
  - テストは、その大きさがすべての幅に収まり、9割の大きさでは `PHOTO_TOO_SMALL` で落ちることを確かめている。
- **PC と SP で形が大きく違う枠** (`ph-bench` は PC 横長・SP 縦長、`ph-garden` は PC 2.4:1・SP 0.93:1、`ph-dry`、`ph-d`) は、1枚の写真で両方を切ると、最も悪い幅で写真の4〜7割しか残らない。
  - 写すものを中央に寄せ、周りに余白を取って撮ってもらう。
  - 1つの形で半分を残せない枠は、`requestFor` が `NO_SINGLE_SHAPE` を返す。その時は、幅ごとに1枚ずつ頼む。今の15枠には無い。
- 携帯電話で撮ったままの写真 (4032×3024 ほど) で `fitSlot` を計算した。
  - 横に撮った写真は、`ph-bench` を除く14枠に、大きさも形も収まる。
  - `ph-bench` は、縦に撮った写真 (表示で 3024×4032。保存が 4032×3024 で EXIF の向きが 6 か 8 のものを含む) で収まる。
  - だから依頼の「頼む形」は撮り方の目安で、切り抜きは Claude が計算する。

## 6. C ページで板を写真に替える方法 (設計、まだ作らない)

> **DEV-166 (2026-11-04) で、つぐ手の6枠だけ道具を作った。** 下の設計から変えた点は次のとおり。正本は `docs/design/tsugute-photo-request.md`。
> - 出力は `.intake/renders/` ではなく、**リポジトリの外**の新しいディレクトリ (オーナーの判断)。
> - 背景ではなく `<picture>` と `<img alt>` にした。「写真｜」の文を消し、alt にするため。
> - 写真は画素で切る (sharp)。CSS の区切り (1200px 以上・601〜1199px・600px 以下) ごとに1枚。
> - 最小の画素は 2倍。1.5倍はオーナーの例外の記録がある時だけ (下の §10 の3)。

C ページ (`experimental_fidelity`) は研究用で、B方式の隔離された道にある。差し替えは、リポジトリのページを書き換えず、**非公開の写し**の中だけで行う。

1. C ページのディレクトリを、`.intake/renders/<shop>/<日時>/` へ写す。HTML・CSS・文の記録は、SHA が枠の一覧と同じであることを確かめる。
2. 割り当てた写真を、`resolvePrivatePhoto` で開く (リンクは拒否)。`checkPhotoRights` を通す。
3. 写しのディレクトリへ写真を写す。描画の通信の許可は、今と同じく、そのディレクトリの中だけに限る。
4. 枠ごとに、`board_selector` (例: `[data-comp-section="damage"] article.shard.shard-ware > figure.board > div.photo`) を対象に、写しの CSS の末尾へ規則を足す。

   ```css
   <board_selector> {
     background-image: url("photos/<asset_id>.<ext>");
     background-size: cover;
     background-position: <fitSlot の object_position>;
   }
   ```

   - 板の切り抜き (`clip-path`)・傾き・影は、ページのものをそのまま使う。
   - `<img>` を足さず背景にするのは、枠の中に文 (写真｜…) や SVG を持つ板があるからである。
5. 仮の表示を消す。
   - 「写真｜…」の文は、写しの中でだけ見えなくする。文の記録の項目としては残し、画像の代わりの文の候補にする。
   - ゆげ湯の `ph-mural` は、板の上に SVG の山を描いている (`placeholder: css_board_with_svg`)。その SVG も、写しの中でだけ消す。
6. 1440・1024・768・390 で描く。条件は fidelity-measure と同じである。描いた画像の SHA を記録し、画像はオーナーへ非公開で渡す。

この差し替えは、**本番の実装レーン (`page-css.ts`) の許可一覧を何も変えない**。本番は今も、すべての `url(` を拒む。写真を本番の B レーンで使うには、次の2つが要る。どちらも、この設計の範囲の外である。

- 資産の道への `url(` を許す、別の承認 (`expressive-allowlist-proposal.md` §3)
- 実在の店なら、依頼主の確認

## 7. 実在の店の写真を公開するとき

- 今の3店は架空なので、この設計の写真は**品質の検証のためだけ**に使う (`purpose: "quality_verification"`)。
  - 必要な使い方は、編集・切り抜き・商用の3つである。
- 実在の店の公開サイトで使う時は、`purpose: "public_site"` で検める。
  - 次の2つが追加で要る。
    - `public_web` の許可
    - 依頼主の書いた確認 (`client_confirmation_ref`)
  - どちらかが無ければ、`NOT_ALLOWED_FOR_PUBLIC_WEB` / `CLIENT_CONFIRMATION_MISSING` で拒む。

## 8. オーナーへの依頼の型

店ごとに、枠の数だけ頼む。**合計 15 枚** (つぐ手 6・輪 5・ゆげ湯 4)。少なく始めるなら、店を1つに絞る (§10 の問い1)。

```
件名: 品質検証用の写真のお願い (<店の名前>、<枚数>枚)

架空の店のデザインの品質を確かめるために、写真を <枚数> 枚お願いします。
公開のサイトには使いません。リポジトリにも入れません (SHA だけを記録します)。

■ 写すもの (どれも、どこの店か・誰か分からないもの)
  <枠>  <写すもの>  形 <頼む形>  最小 <幅>×<高さ> px
  …

■ 写さないでください
  - 人の顔、誰か分かる体の特徴
  - 看板・店名・ロゴ・住所・電話番号・車のナンバー
  - 実在の店や家だと分かる場所
  - 他のサイトから保存した写真、AI で作った画像

■ 撮り方
  - 写すものを真ん中に寄せ、周りに少し余白を残してください
    (PC と スマホで切り抜く形が違うためです)
  - 形式は JPEG・PNG・WebP のどれか

■ 権利 (1枚ごとに教えてください)
  - 撮った人 / 権利を持つ人
  - 編集・切り抜き・商用の利用をしてよいか (3つすべて要ります)
  - 使ってよい期限があれば、その日
  - 有料の素材でないこと
  - 素材サイトの無料の素材なら、規約のページ (本文を保存して SHA を記録します)

■ 渡し方
  公開の場所 (GitHub の Issue や PR) には貼らず、<非公開の渡し方> でお願いします。
```

例 (つぐ手):

- 6枚。
  - `ph-ware` ふたつに割れた器の接写 (4:3、1200×900 以上)
  - `ph-kake` 縁の欠けた器 (4:3、1040×780)
  - `ph-hibi` ひびの入った器 (16:9、1200×675)
  - `ph-dry` 乾くのを待つ器 (1:1、1100×1100)
  - `ph-hand` 筆で金を蒔く手元 (1:1、1240×1240)
  - `ph-desk` 線を相談する机と器 (4:3、870×653)
- 手元の写真は、手だけで、顔・指輪・入れ墨など誰か分かるものが写らないこと。

## 9. 権利の記録 `photo_rights_v0` の項目

| 項目 | 意味 | 欠けた時 |
|---|---|---|
| `asset_id` | `photo-<店>-<枠>-<番号>` | `SCHEMA_INVALID` |
| `sha256`・`bytes`・`width`・`height`・`format` | ファイルから測った値。`format` は `png`・`jpeg`・`webp`。幅と高さは表示される向き (EXIF の向きを当てた後) | `SCHEMA_INVALID`、測った値と違えば `*_MISMATCH` |
| `source_kind` | `owner_provided`・`shop_provided`・`licensed_stock_with_terms` | `RIGHTS_MISSING_SOURCE` |
| `owner` | 権利を持つ人 (非公開) | `RIGHTS_MISSING_OWNER` |
| `license` | ライセンスの id か、許可・規約への参照 | `RIGHTS_MISSING_LICENSE` |
| `terms_sha256` | 素材の規約の本文の SHA (素材の時は必須) | `RIGHTS_MISSING_TERMS_SNAPSHOT` |
| `paid` | 有料か | `RIGHTS_MISSING_PAID`。`true` なら `PAID_SOURCE_NOT_APPROVED` |
| `allowed_uses` | `edit`・`crop`・`commercial`・`public_web` (真偽値) | `RIGHTS_MISSING_ALLOWED_USES`。`false` なら `NOT_ALLOWED_FOR_*` |
| `consent_record_ref` | 同意の記録の場所 (非公開) | `RIGHTS_MISSING_CONSENT` |

## 補足: 確かめていること・いないこと (Fresh Review 2回目)

- EXIF のブロックが2つある JPEG は `PHOTO_EXIF_UNREADABLE` で拒む (ブラウザは最初のものを読むので、記録と表示が食い違い得る)。
