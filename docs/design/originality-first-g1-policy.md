# G1独自性優先のアートディレクション運用（DEV-113 / 2026-10-26 オーナー決定）

**状態:** 制作方針として決定。既存の `docs/design/design-first-workflow-decision.md` のG0–G6を補足する**G1の事前審査とG2の事後審査の方法**。新しいテンプレート・技法採用許可・モデル呼び出し・既存の安全ゲート解除ではない。現時点は文書だけで、コードによる自動審査、プロンプト変更、WSL実行は未実装。

## なぜ必要か

Mondの探索画像で、参考資料を3件列挙しただけでは、一般的な `大きなHero写真→こだわり3カラム→商品3カラム→写真＋About` を避けられなかった。画像生成後に「データベースを参考にした」と説明しても、採用技法の実際の構図への影響は証明できない。

**原則:** デザインの「見た目」を固定せず、**店舗固有の根拠から独自の構図を選び、選択理由と出力との差を評価する判断手順**を固定する。良いHero、色面、写真の美しさは必要条件になり得るが、独創性の代わりにはならない。複数技法を採用した数も独創性の代理指標ではない。

## 0. G0入力で固定すること

1. 実店舗の**確認済みの逐語的な事実**、出典URL・取得日・根拠種別・未確認事項を分ける。宣伝コピーや客層を推測で補完しない。実在の取扱商品の現状、価格、営業時間も確認できないなら表示しない。
2. 写真を `source_observed_reference_only` / `rights_verified_model_input` / `rights_verified_demo_use` / `fictional_concept` / `unavailable` といった**用途別の状態**で記録する（この列挙は説明上の分類で、既存rights schemaの変更ではない）。権利・本人の許可・素材のSHAを確認する。スクショ・公開ページ・ログイン済みhelperの画像は自動的に利用許諾を意味しない。
3. 第三者画像・店舗ロゴ・参考ページのレイアウト/文章/商品写真をコピーしない。実店舗に見えるAI店舗写真や架空のメニューを事実として載せない。写真がない場合は**写真無しの独立案**も候補にする。

## 1. 参考DBの根拠選定は画像生成より前に

- `design-library/research/v02/secondroot_design_library_v02_20261021.json`（DR系列）と `design-library/research/v03/viewport-evidence-20261025.json`（DX系列）に実際にアクセスし、対象に適する**抽象的な技法**だけを抽出する。URLが実在するだけで画面を見たことにしない。
- 各候補で `reference_id`、参照対象、記録された視覚観察、現在のレビュー/検証状態、適用技法、**店舗のどの固有事実に対応するか**、**使わない要素**を先に記録する。
- `DR`/ `DX` / `T1–T8` / `A01–A09` は**異なるデータ群**。IDを混同しない。DEV-107の技法 `T1–T8` の適格性は既存 `shop-proposals.ts` の事実種別と条件で判断する。参照の `human_review: pending` は承認済みと記さない。
- 既存の参考URLから画像・CSS・文言を直接転用しない。参照画像にAI入力権限がない場合、記録済みのテキスト観察を使用するにとどめる。

## 2. G1で必ず2つの**構図**を先に作る

各案に、画像を生成する前に次を文章とワイヤー/構図指定として出す：

| 必須 | 記述する内容 |
|---|---|
| `shop_anchor` | その店舗の出典つき固有情報 1〜3件（何がないとこの構図が成立しないか） |
| `reference_decisions` | 採用ID・出典状態・参考技法・採用理由・使わない表現 |
| `hero_focal_point` | 写真、文字、商品、器、建築など最初の主役を1つだけ特定 |
| `composition` | 1440pxでの写真/文字/余白の比率、視線の出発点、重なり、揃えの軸 |
| `section_rhythm` | Hero・中盤・後半で主役をどう交替するか。理由なき同寸カードの反復を避ける |
| `photo_direction` | 利用可能な素材だけで成立する視点・光・トリミング。無許可なら写真なし案 |
| `mobile_390` | スマホでの視線・主役・CTA・情報順・文字サイズの独立指定 |
| `fact_rights_constraints` | 未確認の事実/権利/再現できないCSSの停止事項 |
| `anti_template_explanation` | なぜ他店へ名前だけ入れ替えても成立しないのか |
| `implementation_gap` | 既存CSS allowlist外の表現と代替案（使えると偽らない） |

- A案/B案は**配色・写真だけの違いを禁止**。少なくともHeroの主役/配分と、セクションの順番/情報の重心/視線導線の双方で意味のある差を持つ。共通要素（実用ナビ、営業時間一覧等）は必要なら維持してよい。
- **「店名・商品写真入替テスト」:** 別の同業店名・写真に差し替えても設計理由がほぼ変わらないなら `GENERIC_CONCEPT` として再提案。これは人の観察に基づくレビュー項目であり、ソフトウェアが主観的独自性を証明できるという意味ではない。
- **「定番骨格テスト」:** `全面Hero + こだわり3枚 + 商品3枚 + About写真` のような並びが出たら「なぜこの店の固有要素でその構成が必要か」を説明させる。理由が無ければ見直す。一般的な構成を機械的にすべて禁止するわけではない。
- **「参考因果テスト」:** 参考カード3件を列挙するだけなら不合格。各技法が実際に**どの位置/寸法/視線/情報順**へ影響するのかを記述し、画像完成後も照合する。

## 3. G2の実行と事後審査

- G1記録を承認/確認する前に「なんとなく良い画像」を先に生成しない。モデルへ渡すプロンプトは入力版・利用した参考ID・禁止事項を固定し、生成手段と出力SHAを追跡する（これは将来実装する要求であり、既存v4ランチャーを無断変更しない）。
- **画像を出しただけで品質PASSにしない。** まず実店舗の誤表現・画像権利・未確認の事実/コピー・ロゴ・開示文・誤った文字などのハードフェイルを検査。失敗なら採点せず停止。
- 続いて既存の5項目各5点のルーブリックを使用（**合計22/25以上、各項目4以上、オーナー確認**）。「独自性」では別店舗への入替テスト、各節のリズム、参考技法の**位置/寸法への反映**を具体的に確認する。
- `LAYOUT_GENERIC` / `REFERENCE_NOT_REFLECTED` / `FACT_NOT_CONFIRMED` / `ASSET_RIGHTS_UNKNOWN` / `TYPE_UNREADABLE` などを**レビュー時の説明カテゴリ**として記録する（現行workerの実装済みエラーコードではない）。次の改善対象を限定する。自動点数だけで「人の審査済み」にしない。
- PC画像だけで390pxの実画面が確認できたことにしない。G4実装・G5の忠実度、アクセシビリティや横はみ出しは別途実測する。
- **合格画像も、営業配布・無認証公開・外部送信・実店舗写真の利用許可とは別問題**。

## 4. 今回のMondで固定する**探索方向**（実店舗デモ使用は未承認）

名称：**Mond — The Cup Archive（ヴィンテージカップの図録 × 喫茶店）**。以前の「月/夜景/紺/金/商品3カード」中心の画像は**独自性不合格の探索例**として残し、デザイン正本にしない。

**確認済み情報の候補（各文の現在掲載と有効性は実制作前に再確認）**:
- 公式 `https://www.mond.nagoya/` はMond=ドイツ語で「月」、自家焙煎・ハンドドリップ、バタートースト、1960〜70年代ヨーロッパのヴィンテージカップ、2021年11月リニューアルを記述している。
- 写真使用権限は未確認。実店舗写真・公式ロゴをデザイン素材として取り込まない。

**参考研究の暫定候補**（技法・観察記録だけ。直前の生成に実際に反映された証明ではない）:
- `DR-009` Stereoscope Coffee：店名主役、大きなタイポグラフィ、思い切った余白。登録されたギャラリースクショ観察であり、実物の権利なし。
- `DR-004` Seven Grams Caffé：写真を大胆に見せつつナビを控えめにする。ただし写真が許可されていないときは適用しない。
- `DR-038` Bonte Caféコンセプト：写真と単色面の交互リズム。**部分的な視覚確認**であり、審査済みの実サイトとはしない。

**A候補:** 写真許可がない場合は、生成りの図録風グリッド＋器の形を抽象化した独自の細線モチーフ＋大型のMond文字。一般的な3つのメニューカードを初手に置かず、ブランドストーリー・カップの来歴・コーヒーとトーストの順で情報を設計する。第三者のカップ柄・ブランド固有グラフィックも模倣しない。

**B候補:** 写真利用が許諾された場合に限り、コーヒー抽出の手元またはトーストのクローズアップを主役にした**まったく別の編集構図**を検討。写真がないなら写真なしの別案を先に用意。昼/夜の配色替えだけをB案としない。

**重要:** 「Mond」の画像を生成すること、公式写真を入力すること、実店を模した店内外観画像を生成すること、実店舗へURLやDMを送ることはここでは承認されていない。現行デザインの先行写真も「本物」と誤認させない。

**CPは構図候補を説明するための文書上の仮ID。** DR（参考研究）、DX（視覚調査）、T（技法適格性）、A（研究技法）と区別する。CP-001は他店への適用条件が揃っても**自動採用は不可**。個別のG1判断で選択・不採用を決める。

### ほかにも探索すべき構図ファミリー（未検証、固定テンプレ化禁止）

- **Typography-led**：大きな店名・短い言葉と余白を中心にする。写真不要な店にも適する可能性。
- **Single-object editorial**：実際の看板商品または道具を一点だけ主役にする。事実・写真権利が条件。
- **Spatial-story**：実際の建築・入口・工房の構造を画面の読み順に変換する。建築情報と画像権利が条件。
- **Catalog / index**：メニューや品目・器など、比較・収集が本質となる店舗の事実を編集する。
- **Sequential cinematic**：写真の大小とスクロールの緩急で体験を見せる。きれいなだけの汎用写真列に陥らないよう検証する。

これは強制的な5種類のメニューではない。**G0の店舗事実から新しい構図を発明してよいし、既存候補を全て却下してよい**。

**選定時に必須:** (1) 店舗固有の根拠、(2) 採用技法との具体的対応、(3) 他の候補を選ばなかった理由、(4) 2案の実質的な構図差、(5) 生成後に同じ骨格へ意図せず回帰していないか。合格基準・権利ゲートは既存どおり。

## 5. CODEXに渡す順序（次段階の要件）

1. 引用可能な事実とrights ledger
2. 参照IDとレビュー状態、採用理由
3. 非類似の2案と入替/構図検査の結果
4. 選定案の厳密な版付きアートディレクションと1440/390の仕様
5. 明示承認を受けた場合のみ、CODEXでの1回実行（prompt hash / quota / asset SHA /出力/reportを記録）
6. G2人間評価、別承認後のみG4実装

**自動化の位置づけ:** この文書は**人と将来の開発が守る方針**。コードでの自動化・品質再現性・データベース連携が完了したとは主張しない。
