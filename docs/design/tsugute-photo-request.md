## 1. オーナーが決めたこと (コードに入れた)

| 決めたこと | コード | 拒む符号 |
|---|---|---|
| 新しい写真は、表示の大きさの **2倍** を目標にする (どの幅で、は下の「倍率を確かめる幅」) | `scaledCrop` (`MIN_SCALE_DEFAULT = 2`) | — |
| **1.5倍** は例外としてだけ許す。誰が・なぜを記録する | `ScaleException` `{ scale, reason, decided_by: "owner" }` | 記録が無い: `SCALE_EXCEPTION_REQUIRED`。記録が壊れている: `SCALE_EXCEPTION_INVALID` |
| 1.5倍より下は、例外があっても拒む | `MIN_SCALE_FLOOR = 1.5` | `PHOTO_BELOW_MIN_SCALE` |
| 「写真｜…」の文を見た目から消し、画像の代わりの文 (alt) にする | `transformHtml` | 残れば `CAPTION_LEFT` |
| 出典と権利の記録は、別に非公開で持つ | `rights.private.json` (出力の中、ページの外) | — |
| 1枚を PC と SP で切って主役が残らなければ、SP 用の写真を求める | `planSlot` | `SP_PHOTO_REQUIRED` |

- 例外の記録 (`scale_exception`) は枠ごとに書く。
  - `scale` は 1.5 以上 2 未満。その枠は、その倍率までしか下げない。
  - `reason` は、実物の画質と切り抜きで足りると判断した理由。空は拒む。
  - `decided_by` は `"owner"` だけ。Claude は例外を決めない。
  - **`decided_by` は機械では確かめられない。** 道具は、誰がその記録を書いたかを知らない。`"owner"` と書いてあることを検めるだけである。オーナーが決めたことを守るのは手順 (§4 の3) であって、コードではない。
  - **1枠に記録は1つ。** その枠の PC の写真にも SP の写真にも、すべての幅にも同じ倍率が掛かる。PC だけ・SP だけ・ある幅だけ、という例外は書けない。
- 例外の記録が壊れていれば、2倍の写真でも拒む。

### 倍率を確かめる幅

- 板は、CSS の区切りの中で、窓の幅に合わせて大きくなる。測った4つの幅 (1440・1024・768・390) だけで確かめると、その間で2倍を割る。
  - 例 (つぐ手で測った): `ph-ware` は 390px で 350px 幅、600px で 560px 幅。1024px で 562px、1199px で 663px。1440px で 600px、1920px で 800px。`ph-hand` は 1199px で 719px、1920px で 828px。
- だから、区切りごとに **いちばん広い端** でも確かめる (`EDGE_VIEWPORTS`)。
  - mobile (600px 以下): 600px で。
  - tablet (601〜1199px): 1199px で。
  - desktop (1200px 以上): **1920px まで** (`DESKTOP_CAP_PX`)。**1920px より広い画面では、2倍 (例外なら1.5倍) を保証しない。** desktop の板は、その先も大きくなり続ける。
- 端の板の大きさは、枠の一覧と同じページで測り、`poc/tsugute/photo-slot-edges.json` に置いた (`scripts/design-artifact/photo-slots.ts --edges`)。`photo-slots.json` と同じ HTML・CSS・文の SHA を持つ。違えば道具は `EDGES_STALE` で拒む。
  - つぐ手の板は、どの区切りの中でも、窓が広いほど大きいか同じ (320〜2560px を測って確かめた)。だから端で足りれば、その区切りのどこでも足りる。
- 「2倍」は、測った4つの幅と3つの端で2倍、という意味である。

### 主役が残らない、の定義

- 写真ごとに **主役の箱** (`focal_box`) を書く。写真の幅と高さに対する割合 (0〜1) の `{ x, y, w, h }` である。
  - 切り抜きの中心は、この箱の中心にする。
- PC の写真を SP の形で切ったとき、次のどちらかなら「主役が残らない」とする。
  1. 主役の箱が、切り抜きの中に収まらない (0.5px の余裕だけ見る)。
  2. 切り抜きが、写真の面積の半分未満しか残さない (`kept_area < 0.5`)。
- その時は、その枠に SP 用の写真 (`sp`) が要る。無ければ `SP_PHOTO_REQUIRED` で拒む。
- つぐ手の CSS は、1199px 以下で、すべての板を SP の形にする (例: `ph-dry` は 1200px 以上で 340:500、以下で 4:3)。だから、つぐ手では SP 用の写真が 1199・1024・768・600・390 のすべてに使われる (`TSUGUTE_SP_VIEWPORTS`)。
- PC の側でも、主役の箱が切れれば `FOCAL_SUBJECT_CROPPED` で拒む。SP 用の写真も、同じ倍率と主役の規則で検める。

## 2. 差し替えの道具 `scripts/design-artifact/photo-swap.ts`

```
npx tsx scripts/design-artifact/photo-swap.ts \
  --page design-library/research/quality-pipeline/poc/tsugute/fidelity/d1-v3 \
  --manifest design-library/research/quality-pipeline/.intake/tsugute-swap.json \
  --out <リポジトリの外の、まだ無いディレクトリ>
```

**拒むもの (`--out` を作らない、終了 2):**

- ページが、枠の一覧を測ったページと違う (HTML・CSS・文の記録の SHA)。`PAGE_CHANGED`・`PAGE_NOT_INVENTORIED`。端の測り値が古い。`EDGES_STALE`
- `--out` がリポジトリの中 (`.intake/` も含む)、すでにある、親が無い。`OUT_INSIDE_REPO`・`OUT_EXISTS`・`OUT_PARENT_MISSING`
  - リンクを通ってリポジトリへ入る道も拒む。
- 手渡しの記録 (manifest) が、`.intake/` 以外のリポジトリの中にある。`MANIFEST_IN_REPO`。無い。`MANIFEST_NOT_FOUND`
- 6枠のどれかが欠けている。`SLOTS_INCOMPLETE`。重複・未知の枠も拒む。
- どれか1枚でも `resolvePrivatePhoto` か `checkPhotoRights` (品質検証の目的) を通らない。
- どれか1枠でも `planSlot` を通らない (倍率・主役・SP 用の写真)。
- 店は `tsugute` だけ (`SWAP_SHOPS`)。

**検めたあとで失敗しても、`--out` は作らない (全部か無しか):**

- 先に、すべての写真を読み、切り、書き出す形にし、HTML を書き換える。ここまでは記憶の中だけで、何も書かない。
  - 頭と権利は通るが途中で切れた写真 (例: 途中で終わる JPEG) は、ここで `PHOTO_DECODE_FAILED` になる。読み手の文は出さない。
  - 「写真｜」や板が、決まった所に無い。`CAPTION_NOT_FOUND`・`BOARD_NOT_FOUND`・`CAPTION_LEFT`
- 次に、`--out` と同じ親に、`mkdtemp` で一時の兄弟ディレクトリ (`.<名前>.partial-XXXXXX`、リポジトリの外) を作り、そこへ書く。
- 描いて確かめる (6枚が読み込まれた・各板に alt のある画像が1枚・「写真｜」が残らない)。通らなければ `RENDER_CHECK_FAILED`、描画が落ちれば `RENDER_FAILED`。この確かめは `swapPage` 自身が行い、通らなければ ok にしない。
- すべて通った時だけ、一時ディレクトリを `--out` へ名前を変える。どこかで失敗すれば、一時ディレクトリを消し、`--out` は無いままにする。
- 出来た `--out` は `mkdtemp` の権限 (0700) を持つ。

**手渡しの記録 `photo_swap_manifest_v0`:**

```json
{
  "schema": "photo_swap_manifest_v0",
  "shop": "tsugute",
  "slots": [
    {
      "slot_id": "ph-dry",
      "alt": "金の線が乾くのを待つ器",
      "pc": { "rights": { "schema": "photo_rights_v0", "...": "..." }, "focal_box": { "x": 0.35, "y": 0.2, "w": 0.3, "h": 0.6 } },
      "sp": { "rights": { "schema": "photo_rights_v0", "...": "..." }, "focal_box": { "x": 0.3, "y": 0.3, "w": 0.4, "h": 0.4 } },
      "scale_exception": { "scale": 1.5, "reason": "実物を見て、ぼやけないと判断", "decided_by": "owner" }
    }
  ]
}
```

- `alt` を省くと、枠の役割 (「写真｜」を除いた文) を使う。`alt` に「写真｜」は書けない。
- `sp` と `scale_exception` は、要る枠だけに書く。

**切り抜きの方法: 画素で切る (sharp)。**

- sharp は next の依存として `node_modules` に既にある。依存は足していない。
- 写真ごとに、EXIF の向きを当て、計算した矩形で切り、メタデータ (EXIF・GPS) を落として書く。
- CSS の区切りごとに1枚ずつ書く: desktop (1200px 以上)・tablet (601〜1199px)・mobile (600px 以下)。`<picture>` の `<source media>` が選ぶ。
- `<img>` には `object-fit: cover` を残す (同じ区切りの中の、小数の差のため)。
- object-position で元の写真をそのまま使う方法を選ばなかった理由:
  - オーナーが見るファイルが、そのまま表示されるものになる。
  - 元の写真のメタデータ (撮影場所など) が `.intake/` の外へ出ない。
  - PC と SP で、別の写真を使える。

**出力 (すべてリポジトリの外):**

| 道 | 中身 |
|---|---|
| `<out>/page/` | ページの写し。ブラウザが読めるのはここだけ |
| `<out>/page/photos/` | 切り抜いた写真 (6枠 × 3区切り) |
| `<out>/renders/` | `desktop_1440.png`・`mobile_390.png` (ページ全体) |
| `<out>/swap-summary.json` | 公開してよい形: SHA・大きさ・切り抜き・倍率の根拠。権利者・同意・置き場は無い |
| `<out>/rights.private.json` | 権利の記録・置き場・例外の理由。**非公開。commit しない。Issue・PR に貼らない** |

- 描画は fidelity-measure と同じ条件: JS 無効、写しの外への通信は拒否、deviceScaleFactor 1。
- 描いたあと、6枚の画像が読み込まれたか、各 `board_selector` の下に alt のある画像が1枚あるか、「写真｜」が残っていないかを確かめる。
- 写しの CSS の末尾にだけ、画像を板いっぱいに置く規則を足す。板の切り抜き (`clip-path`)・傾き・影・紙焼きの余白は、ページのものをそのまま使う。
- 「写真｜」の `figcaption` を消すので、割れ・欠け・ひびの板の下の余白が、名札の分だけ詰まる。板そのものの大きさは変わらない。
- リポジトリのページと、本番の実装レーンの許可一覧は、何も変えない。

## 4. 受け取ってから描くまで (承認が要る)

1. オーナーが依頼文を送る。
2. 写真と権利を受け取る (**承認が要る**)。
   - 写真は `design-library/research/quality-pipeline/.intake/photos/<名前>.<拡張子>` に置く。リンクは拒まれる。
   - 手渡しの記録は `design-library/research/quality-pipeline/.intake/tsugute-swap.json` に置く。
3. 枠ごとに `focal_box` と `alt` を書く。下限を使う枠は、オーナーが `scale_exception` を決める。
4. 本物の写真で道具を走らせる (**承認が要る**)。`--out` はリポジトリの外。
5. オーナーが `renders/` を見て決める。**Claude は成功例の水準とは言わない。**
6. 公開に使うこと (**別の承認が要る**)。本番の実装レーンは今も `url(` を拒む。

- 評価は、オーナーが描いた画像を見るまで `placeholder_limited` のままである。

## 5. 決まっていないこと

1. **非公開の渡し方** (`photo-intake.md` §10 の2)。依頼文の `<渡し方>` を埋める必要がある。
2. **sharp を直接の依存にするか。** 今は next を通して入っているだけである。next が sharp を外すと、道具は動かない。`package.json` に足すなら、レビュー記録に残す。今は足さない (オーナーの判断を待つ)。
3. **ph-dry を1枚にするか2枚にするか。** 2枚なら、SP 用の写真は 1199px 以下のすべてで使われる。
4. **1920px より広い画面。** 今は保証しない。保証するなら、上限の幅を決めて端を測り直し、依頼の大きさを上げる。

## 6. 分かっている弱いところ (Low)

- **確かめてから使うまでの隙間 (TOCTOU)。** 道具は、写真を `resolvePrivatePhoto` で開いて SHA を測ったあと、切り抜く時にもう一度読む。`--out` も、検めたあと、最後の名前の変更の直前にもう一度だけ「無いこと」を確かめる。その間に、同じ機械の誰かが `.intake/photos/` の写真や `--out` の場所を入れ替えれば、検めたものと違うものを使い得る。この道具はオーナーの手元で一人が走らせるもので、相手は同じ利用者である。だから Low として残す。
- **`decided_by: "owner"` は手順で守る。** 上の §1 のとおり。
