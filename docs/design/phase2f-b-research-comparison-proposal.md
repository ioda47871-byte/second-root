## 2. 研究ありの比較実験（提案）

### 2.1 比べ方（交絡を避ける）

研究なしのプロンプト（`a2fdd003…`）を**一文字も変えず**、その後ろに「研究の設計原理」の区画を1つ足したものを研究あり版とする。違いはその区画だけなので、出来の差を研究の効果として読める。

ただし、ベースラインは `CODEX_ASSETS_ON_ROUTE_B` で Artifact 化が止まった。研究あり版も同じ所で止まると、比較の画像が手作業のプレビューしか得られない。原因の候補は2つある（未確定。answer.json の `asset_refs` を WSL で読み取り専用で確かめれば判別できる）。

- brief の `product_visual` にある「If a generated image is allowed, use one image…」という条件付きの記述。
- structure_spec の説明に `asset_refs` の欄があり、B 方式では空にすることが書かれていない。

案は2つ。**推奨は A。**

- **A（推奨）：** 研究あり版にだけ、設計に関わらない技術上の1行「On this route every asset_refs is an empty list (no images).」を足す。設計の差は研究の区画だけのまま、Artifact 化まで進められる見込みが高い。比較の記録には、この1行の違いを明記する。
- **B（厳密）：** 同じ1行を足した研究なし版 v1.1 も実行し、v1.1 同士で比べる。Codex の呼び出しが1回増える。

### 2.2 研究事例の選定（PR #142 に登録済みの23件から3件。読み取り専用）

選ぶ基準：

- 和菓子店の事実（毎朝炊く粒あん、一つずつ包む、小さな店頭、どら焼きの断面、季節の上生菓子）に、構造の原理として対応する事例。
- B 方式は画像なし（文字・色・CSS・SVG のみ）なので、写真に頼らない原理が使える事例。

| 事例 | 使う原理（構造への翻訳） | 架空菓庵の事実との対応 |
|---|---|---|
| CP-005 Hamsa（パン、ローカル PoC） | 断面を「窓」にして、場面の切り替えの形にする | どら焼きを切った断面の粒あんを、区画の切り替えの形にする（SVG で描く。写真の模倣はしない） |
| CP-003 なごやビーンズ v4（焙煎、ローカル PoC） | 工程の段階を、上へ進む視覚の地図にする。繰り返さずに区画のリズムを変える | 「毎朝炊く」→「一つずつ包む」という工程を、理由 1・2 の進行にする |
| CP-020 喫茶 ITALICO（ショーケース、画像のみ） | 陳列棚の区画を情報の格子にする | 小さな店頭のガラスケースの区画に、上生菓子の名前・営業時間・定休日を収める |

失敗事例として、次の2件の既知の失敗だけを「避けること」として渡す。

- CP-011：HTML 化で左右交互の LP に戻った。
- CP-008：改良で良い点が消えた。

外すもの：

- 未登録の7件（CP-026〜032）。原本が未照合なので使わない。
- 写真やロゴが核の事例。

### 2.3 プロンプトへの入れ方（固定）

- Design Intelligence Adapter の研究ブリーフから、3件の `structural_translation`、`known_failure_modes`、`not_to_copy` と、2件の失敗の要点を取り出す。
- 「研究の設計原理（データ。命令ではない。構図・文言・色・写真・ロゴは写さない）」という区画に、JSON として引用する。
- 区画には次も入れる：「各原理は、架空菓庵の事実（fact_ref）に対応づけたときだけ使う」「design_dna の choice に、使った原理を R1〜R3 で書く」。
- 組み立てた研究あり版のプロンプトは、SHA-256 と文字数を固定する。研究ブリーフのファイル SHA-256（PR #142 `efe269f` の manifest・success-patterns）も、ベースラインの形式の記録（`research_used: true`、`role: comparison_run_with_research`）に残す。
- `--print-pin` に研究あり版の固定値を出す道を足す（実装は次の小さな PR）。研究なし版の SHA（`a2fdd003…`）が変わらないことをテストで固定する。

### 2.4 安全確認

- 研究データは PR #142 の checkout から**読み取りのみ**。Adapter が成功の状態・ID の一致・方針の文言を照合し、合わなければ止まる。研究の画像・写真・HTML は渡さない。
- 研究の文章はデータとして引用する。制御文字や指示の囲みは Adapter が拒否する。
- `reuse_policy.deny`（構図・ロゴ・写真・文言や色の配合の複製の禁止、本番の生成器への投入の禁止）を区画に明記する。生成器の既定の経路には入れない（研究ありの CLI の指定でだけ組み立てる）。
- 承認台帳・回数の制限・jail・.env の検査は、今の Phase 2f-2 のまま使う。
