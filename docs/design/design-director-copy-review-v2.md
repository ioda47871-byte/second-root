## 0. 何のための審査か

SR-001「輪」は画像と PC/SP のレイアウトで成功したが、ほぼ全区画に詩的な決め台詞を置いた
(「スポークの先に、修理がある。」「一本ずつ。」「空気を入れる日。」「一周して、店先へ。」)。
コピーが情報を伝える代わりにデザインの穴を埋めていた。今の SKILL.md §1 は決め台詞と事実の言い換えを禁じているが、
品質優先の研究の道 (comp-lane、`copy.json`) の `creative_expression` には、**数の上限も、区画の役割の点検も無い**。
1行ずつは事実の印 (`CREATIVE_LOOKS_LIKE_FACT`) に当たらないので、全部が通った。

この審査は、**語のブラックリストではない**。1行ずつではなく、ページ全体の文体・韻律・区画をまたぐ繰り返し・
情報の有無・店固有の事情を見る。店の一番強い表現が1つ残ってよい。全部を平板なラベルに変えるのも不合格である。

**審査の結果は、オーナーの承認の代わりにならない。**`approve_candidate` は「オーナーに見せてよい候補」であり、
送信・公開・実店舗向けの完成ではない。

## 1. 審査の入力

- 事実パック (`shop_facts_pack_v1`) と、その SHA-256
- 文の記録 (`comp_copy_v1`、`copy.json`) と、描いたページ (PC1440 / SP390 の全頁、HTML / CSS)
- 区画の一覧 (`data-section` / `data-comp-section` と見出し)
- 同じ業種の過去案 (あれば。入れ替えテストの比較に使う)

審査の機械的な部分は `copy_quality_review_v1` (DEV-199a、`lib/design-agent/quality-pipeline/copy-quality-review.ts`。別の PR で、この文書の時点では develop に未マージ) が持つ。
この文書は、Claude (ディレクター) がその結果を読み、**自分の目で**ページ全体を判断する手順である。
機械の結果を緩めることも、機械の `approve_candidate` だけで成功を宣言することもしない。

## 2. 区画ごとの役割を先に書く

コピーを読む前に、区画ごとに1行ずつ書く。

```
<section_id>  訪問者がここで知ること: <何を売るか / どんな店か / いつ開いているか / どう行くか ...>
              根拠の事実: F3, F7
```

- 「知ること」が書けない区画は、飾りの区画である。事実が無いなら区画ごと落とす案を出す。決め台詞で埋めない
- 根拠の事実が1つも無い区画に文があれば、それは創作である (研究の道の架空の店だけが `creative_expression` として持てる)
- 一般にサイトにあるはずの情報 (メニュー・価格・予約・在庫など) が事実パックに無いときは、
  **情報不足として報告し HOLD**。業種の一般論で埋めない (§5)

## 3. 五つの軸で読む

各軸 0〜5 の点は**補助**である。点だけで合否を決めない。軸ごとに、ページのどこを見てそう判断したかを書く。

1. **自然な日本語** — 言い切り・断片文・不自然な読点・体言止めの連続が無いか。その業種の接客で使わない借り物の口調 (広告・詩・ナレーション) が無いか。店の看板や品書きに書いてありそうな言い方か
2. **店舗固有性** — 店名を別の店に入れ替えても通用しないか。文が、その店の事実・商品・作業・客の疑問に根拠を持つか
3. **情報の有用性** — 各区画に目的があるか (§2)。商品・サービス・時間・来店方法へ素早くたどり着けるか。並び順が訪問者の必要に沿っているか、レイアウトの見栄えに沿っているか
4. **表現の抑制と一貫性** — 全区画がキャッチコピーになっていないか。同じ語調・比喩・構文 (「〜の先に、〜がある。」「〜する日。」「一〜ずつ。」) が区画をまたいで繰り返されていないか。象徴的な表現が店に結び付いているか
5. **事実・出典の正しさ** — 未確認の価格・予約・在庫・経験年数・店主の発言・お客様の声・商品の特徴を発明していないか。架空と実在の区別が保たれているか

**罰しないもの:**「メニュー」「アクセス」「営業時間」のような普通のラベル。出典つきの短く平易な文。
製法の事実として正しい「ひとつずつ」。「詩的でない」ことは不合格の理由にならない。「想い」「丁寧」「特別」の文字列だけで落とさない。
**AI が書いた文かどうかを断定しない。**判断するのは文の働きである。

## 4. 累積した決め台詞と、1つの強い Hero の行

いちばん大事な区別である。

- **1つの強い行は残してよい。**Hero に置いた、店の事実に結び付いた1行 (例: 輪の「まがった車輪も、まっすぐに。」は修理の事実と整合する) は、
  それだけで自動的に拒否しない。ページの声を担う行は**ページに1つ**まで
- **累積は直す。**Hero 以外の区画の3つ以上が、情報を持たない決め台詞から始まり、同じ型や比喩を繰り返すなら
  `COPY_RHETORICAL_OVERUSE` (REVISE)。複数の見出しが同じ型なら `COPY_REPETITIVE_CADENCE` (REVISE)
- 指摘は**ページ全体で1つ**にまとめ、該当する区画を並べる。1行ずつ別の指摘にしない (どの1行も単独なら許されうるため)
- 直し方は「全部をラベルにする」ではない。守る1行を先に名指しし、それ以外の区画の見出しを、その区画で知ることを言うラベルか事実の value に戻す

## 5. 判定

| 判定 | いつ | 次 |
|---|---|---|
| `fail` | 事実の創作・言い換え・出典の無い主張 (`COPY_FACT_UNSUPPORTED`)。既存の `copy-record` の失敗を優先する | 止める。改稿で救わない |
| `hold` | 事実が足りず、正しく書く材料が無い (`COPY_INFORMATION_MISSING` / `COPY_GENERIC_FOR_SHOP` の hold)。実店舗向けの提案はオーナーの確認待ち (`COPY_APPROVAL_MISSING`) | **再生成しない。創作で埋めない。**足りない事実を報告し、オーナーか事実の追加を待つ |
| `revise` | 文体の疑義 (`COPY_RHETORICAL_OVERUSE` / `COPY_REPETITIVE_CADENCE` / `COPY_GENERIC_FOR_SHOP` / `COPY_VOICE_UNNATURAL` / `COPY_INFORMATION_MISSING` の revise) | §7 の局所改稿 (最大2回) |
| `approve_candidate` | 上のどれにも当たらない | オーナーに PC/SP 全頁と審査を見せる。**オーナーの承認の前に、完成・営業候補として扱わない** |

**事実が足りないときは HOLD である。**「書けないから一般論で書く」「書けないから詩にする」はどちらも不合格。

## 6. 道ごとの規則 (lane)

| 道 | 書いてよい文 | 創作の文 |
|---|---|---|
| 実店舗の提案 (`real_shop_proposal`) | 事実の value そのまま (`fact`) と中立なラベル。文の提案は `proposal_pending_review` | **書かない。**審査は事実とラベルの選び方・並べ方だけを見る。常に `COPY_APPROVAL_MISSING` (HOLD) が付き、オーナーの確認まで店の言葉として出さない |
| 品質優先の研究・架空の店 (`quality_research_fictional`) | 上に加え、`creative_expression` (`owner_review_needed: true`) | 架空の店だけ (shop_id が `fictional-`、店名の事実が「架空」で始まる)。事実を作らない (`CREATIVE_LOOKS_LIKE_FACT`)。**ページの声を担う1行を原則とし、§4 の累積を作らない** |
| Phase 2f の B/C 経路 (Codex) | 事実の value そのまま (`fact_ref`) と 40字以内の中立な `ui_label` だけ | **無い。**回答の形 (`codex_design_v1`) に創作の欄が無い。v3 提案 (`COPY_V3_RULES`) も同じ |

どの道でも、研究の道の文を実店舗の言葉として見せない。過去の研究採用例 (SR-001「輪」を含む) を遡って取り消さない。

## 7. 改稿の規則

- 改稿の前に、**守る部分** (強い Hero の1行、よく働いている区画) を名指しする。良い箇所は変えない
- 改稿は指摘された箇所だけの局所修正。1巡に1つの原因、最大2巡 (`MAX_COPY_REVISION_ROUNDS = 2`)。2巡で通らなければ止めて報告する
- **改稿で `claim_type` を変えない。**`creative_expression` を `fact` に、`fact` を `creative_expression` に付け替えて通さない
- **事実は逐語のまま。**改稿で事実の value を言い換え・要約・つなぎ直さない。事実を言い換えた新しい創作行も作らない
  (`validateCopyRevision` が FAIL にする。DEV-199a)
- 改稿したら、事実パック・文の記録・HTML・CSS の SHA-256 が変わる。**古い審査を再利用しない。**改稿後のページで審査をやり直す

```
- 情報不足: <事実パックに無いもの>
```
