# Second Root｜店舗取り違え防止「Identity Lock」研究手順

**固定日:** 2026-10-28 JST
**適用:** CP-015以降のChatGPT内デザイン研究、後続の研究PoC
**状態:** 研究用手順と読み取り専用監査。**画像モデル自体の改修ではない**。既存ワーカー/生成器/本番DB/営業AIには未接続。

## なぜ導入するか

- CP-014「CAN BUY RECORDS」用の追加画像で、別店舗名「KOALA」や「cobaco」のパン屋が生成された。
- CP-015「imairo.」では初稿は正しい店名だが、別構図のはずの2枚目が「cobaco / BOOK・ZINE・LIFE」という別業種の画像に変わった。
- **店名だけでなく業種・扱う商品・画面コンセプトまで変わっており、前案と混ざる画像生成コンテキストの汚染が疑われる。** 原因の技術的確定はできていないため、「原因は100%コンテキスト」と断定しない。
- 架空の「cobaco」を実在確認済み店舗・制作成功例として扱ってはいけない。

## ゲート0：生成前の店舗固定（必須）

1. 研究ID、**対象の正式店名**、許容表記、業種コード、参照元URL、未確認事項、商用素材使用不可の範囲を1店舗ずつ固定する。
2. プロンプト内でも同じ正式名と業種コードを使用し、**前の店名・前回のプロンプト・別店舗の画像は入力例として混ぜない**。過去作品は抽象的な構図の知識のみ参照する。
3. 出力は「指定された1店舗のサイト案」であり、独自に架空名をつけてはいけないと明記する。看板・ナビゲーション・見出しのブランド同一性を最優先にする。
4. ブランド表記を画像モデルが安定再現できない場合、**背景写真/オブジェクトだけ画像で作り、店名・文字はHTML/CSS等の独立レイヤーで組む**。別の店名を補完させない。

## ゲート1：画像出力後の Identity Check（必須）

- 出力画像の実バイナリSHA-256を計算。**チェックした画像**と**採用候補画像**が同じハッシュであることを確認。
- 出力を実際に見て、サイトの屋号/看板/ロゴ/見出しに書かれた**サイト運営主体の名前**を列挙する（単なる商品パッケージのブランド名とは区別）。
- 店の業種（例：レコード店 vs パン屋／スパイスカフェ vs 本・ZINE）を目視で確認。
- 屋号に相違や別店舗名混入、業種違いがあれば**REJECT：不採用画像として別保管**。再生成が必要でも初稿の好評点を保護する。
- 店名が読めない・目視の記録がない・画像ハッシュ未確認は**HOLD：成功判定に進めない**。
- 正しい店名・業種なら**PASS_IDENTITY_ONLY**。これだけでは美的合格、オーナーの研究採用、店舗実像の真正性、商品・値段・日付の真偽、Web実装成功にはならない。

**監査は画像ピクセルを読まない。画像を目視した結果を構造化JSONに記載することが前提。自動でOCRして正しさを保証するシステムではない。**

## 使用例と回帰テスト

```bash
node --test design-library/intelligence/v02/identity-audit.test.mjs
node design-library/intelligence/v02/identity-audit.mjs design-library/intelligence/v02/experiments/CP015-imairo-v1-identity.json
node design-library/intelligence/v02/identity-audit.mjs design-library/intelligence/v02/experiments/CP015-cobaco-identity-rejected.json
# 最後は REJECT で exit 1 になるのが期待どおり
```

- **CP-015 imairo. 初稿:** 画像上のサイト名とスパイス料理／菓子／コーヒーという業種の一致を目視で確認。「Identity PASS」だが、デザインはまだ未承認。
- **CP-015 cobaco 書店:** 屋号と業種の両方が違うため REJECT。成功件数には加算しない。
- **CP-014 KOALA／cobaco:** 別店舗への逸脱を回帰テストに取り込み、類似事故を認識できるようにする。

## 再試行と制作フロー

1. 却下した出力は、修正ベースとして無意識に使わない。**プロンプトを対象店名・業種のロック情報から新規構築**して独立のコンセプトを試す。
2. 連続2回以上の店舗取り違えは新しい画像の連続生成を停止。文字入り1枚絵を避け、素材画像とタイポグラフィの分離方式へ切り替える。
3. 構図を直す際も店名同一性チェックを必ず再実行する。前の出力への評価が「良い」と言われていても、別店舗名や架空の事実があれば商用制作には流用しない。
4. CP番号を増やすのは店舗案を制作・研究する単位であり、**生成の失敗画像を別の店舗成功例として数えない**。採用は従来どおりオーナーの明示的選択が必要。
5. 実店舗の公認・写真使用権、所在地・商品・営業日、公開の判断は別ゲートで扱う。

## 安全な適用範囲

この研究用ルールは `docs/design/design-first-workflow-decision.md` のG0/G2に付加する**運用チェック**。モデルの画像生成成功率を保証せず、ランタイムCI・生成ワーカー・自動営業に結線していない。生成器への必須ゲート導入は独立のレビュー・承認・テストが必要。研究成功数13件/参考候補80件の内訳を変えない。
