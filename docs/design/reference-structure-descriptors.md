# 成功例と不採用例の構造記述子 (DEV-136、offline・助言)

- データ: `design-library/intelligence/v02/structure-descriptors-v0.json`
- 読み込みと比較: `lib/design-agent/structure/references.ts` (`ReferenceDescriptors`、`compareWithReferences`)

新しいデザインを、成功例の骨格 (写し) と、オーナーが却下した版の骨格に照らす。**オフラインの助言だけ**であり、
生成の入力にも、合否にも、停止にも使わない。生成器や Phase 2f の runner に組み込むのは別の承認が要る
(構造モジュールの隔離)。

## データ

- 成功例30件 (登録済みの全件)。証拠は manifest に合わせる: 画像 (CP-001〜003、プレビュー画像を見て宣言)・
  文章の記録 (CP-004〜024)・原本なし (CP-026〜032)
- 不採用の版8件: CP-016 の初稿、PT-02 の初稿、CP-011 v1、CP-015 の全頁1、CP-025 v1・v2、CP-023 v5、CP-027 v1。
  どれも記録の判定と出典を持つ (多くはオーナーの言葉や判定コード。CP-023 v5 は制作側の判断にオーナーが同意したもの)
- **すべて宣言** (`source: "declared"`)。測ったものは無い。記録が言わない観点は null
- 語彙と閾値は仮 (Issue #159)。宣言は研究記録を読んで書いたもので、オーナーの確認を受けていない

## 比較

`compareWithReferences(候補, データ)` は次を返す。

- `too_close_to_success`: 成功例との類似度が 0.75 以上 (写し)
- `close_to_rejected`: 不採用の版との類似度が 0.6 以上 (却下された骨格の繰り返し)
- `undecided`: 両方に分かっている観点の重みが 0.5 (MIN_COVERAGE) に満たず、決められない参照。
  「近くない」とは数えない

## 確かめたこと (2026-10-31)

- テスト: 登録済み30件と一致、証拠の種類が manifest と一致、出典のファイルが存在、宣言だけであること、
  汎用 LP の骨格は不採用の版 (CP-025 v1 など) に近いと出て成功例には近くないこと、
  成功例の骨格をそのまま持つページは写しと出ること、**どの成功例も不採用の骨格に近くない** (データが自分と矛盾しない)
- DEV-133 の評価の試作12枚に掛けた:
  - 描画から測った記述子だけでは、どの試作でも、参照38件すべてが `undecided` だった。Hero と流れは描画から測れず、参照は Hero と流れで
    書かれているものが多いため
  - スキルありの6枚に、試作が宣言した Hero と流れを足すと、どの試作でも参照38件のうち12件が判定でき、写しも
    却下骨格の繰り返しも無かった。26件はなお `undecided` (参照の記述が薄い)

## 限界

- 参照の多くは Hero と流れしか書かれておらず、判定できる組が少ない。記録の薄い CP-026・031・032 はすべての観点が null
- 宣言の判断 (例: CP-001 の流れ、CP-002 の Hero、CP-010 の流れ: 「本棚が地図になる」は `map_of_stations` とも読める)
  は研究記録の読みであり、オーナーの確認が要る
- 閾値を下げて判定を増やすことはしていない
